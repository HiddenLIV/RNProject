# 로드맵 (초안)

`docs/specs/`에는 지금까지 만든 16개 기능의 스펙이 쌓여 있지만, 그건 전부 "과거에 무엇을 만들었는가"의 기록이지 "다음에 뭘 만들지"에 대한 답은 아니다. 이 문서는 그 공백을 메우기 위한 초안이다.

**이 문서의 성격**: 우선순위는 전부 제안이며, 실제 결정권은 사용자에게 있다. 새 기능 요청이 들어오면 여기 순서와 무관하게 먼저 처리해도 된다. 이 문서는 "다음에 뭘 할지 매번 새로 고민하지 않기 위한 시작점"이지, 반드시 지켜야 할 계획이 아니다.

## 완료된 것 (참고용 — 상세는 `docs/specs/` 각 파일)

매달리기 타이머, 다국어 지원(4개 언어), 라이트 모드, 테마 컬러 커스터마이징, 운동 커스터마이징, 자세 촬영 영상, 자세 안내 영상(YouTube 링크 + 검색), 온보딩/도움말, 기록 시간 보정, 타이머 알림 무음(음성 안내 토글), 홈 메뉴, **데이터 백업 및 내보내기**(최신).

## 다음 우선순위 제안

### P0 — 출시 전/직후 안정성

1. **크래시 리포팅 도입 검토** — 현재 크래시 발생 시 개발자가 알 방법이 전혀 없다. 스토어 배포가 임박한 상태에서 가장 위험한 공백. Sentry 등 서드파티 SDK는 `docs/guides/play-store-listing-copy.md`의 "No data collected" 답변과 상충할 수 있어(참고: 기획자 관점 2번 "분석 도구"와 같은 이유로 이번엔 보류됨), 도입한다면 그 문서도 함께 갱신해야 한다. 최소한 "크래시가 나면 사용자가 직접 신고할 방법"(예: 도움말 화면에 문의 이메일)이라도 먼저 마련하는 절충안도 고려할 만하다.
2. **테스트 코드 도입** — 전무한 상태. UI 테스트보다 `src/lib/`의 순수 로직(특히 `storage.ts`의 `restoreFromBackup`, `backup.ts`의 검증 로직처럼 실수하면 데이터가 통째로 날아가는 부분)부터 유닛 테스트를 붙이는 게 비용 대비 효과가 크다.

### P1 — 유지보수성

3. **남은 대형 파일 분리** — `TimerScreen.tsx`는 이번에 분리했지만, `AddExerciseScreen.tsx`(524줄)·`EditExerciseModal.tsx`(410줄)·`HomeScreen.tsx`(410줄)가 다음 후보다. 두 화면은 폼 검증·아이콘 선택·측정방식 선택 로직이 뒤섞여 있어 TimerScreen과 같은 패턴(관심사별 훅 분리)을 적용할 수 있다.
4. **디자인 토큰 문서화** — `primarySoft`/`accentSoft`가 "항상 어두운 칩" 전용이라는 규칙이 `ThemeContext.tsx` 주석에만 있다. 이 세션에서만 같은 대비 버그가 3곳(아이콘 선택, 스테퍼, 타이머 조정 버튼)에서 반복됐다. 짧은 규칙 문서 하나(`docs/design-tokens.md` 같은)로 정리해두면 재발을 줄일 수 있다.
5. **접근성 라벨 계속 확대** — 이번에 아이콘 전용 버튼 4곳(뒤로가기 2곳, 스테퍼 증감)을 채웠다. 새 화면/컴포넌트를 만들 때마다 아이콘 전용 버튼에 라벨을 넣는 걸 체크리스트화할 만하다.

### P2 — 인프라

6. **CI 파이프라인** — 지금은 로컬 빌드 + adb install에 전부 의존한다(이번 세션에도 Gradle JS 번들 캐시 문제, 에뮬레이터 크래시를 두 번 더 겪었다). 최소한 PR마다 `tsc --noEmit`이라도 자동 실행되면 이런 종류의 회귀를 조기에 잡을 수 있다.

## 보류 (이번엔 다루지 않기로 결정)

- **사용성 분석 도구(Firebase Analytics 등)** — 스토어 등록 카피의 "No data collected" 주장과 정면 충돌해 보류. 나중에 필요해지면 로컬 로그 방식(기기 밖 전송 없음)부터 재검토.
- **클라우드 자동 백업(Google Drive/iCloud 연동)** — `데이터 백업 및 내보내기` 스펙에서 이미 로컬 파일 방식으로 범위를 좁혔다. 자동 백업이 필요해지면 별도 스펙으로 다시 논의.
