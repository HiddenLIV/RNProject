# HiddenReps 로드맵

기획자·개발자·디자이너 3인 관점으로 2026-08-22에 진행한 앱 진단을 바탕으로 정리한 순차 실행 로드맵. 아티팩트(claude.ai)로도 한 번 보여줬지만, 그건 열람용 산출물일 뿐이고 이 파일이 원본/추적 대상이다.

## 현재 상태 한 줄 요약

측정 도구로는 탄탄하다(운동 커스터마이징, 4개 언어, 다크/라이트 테마, 온보딩, 백업 export/import 등은 이미 견고). 하지만 **다시 켜고 싶게 만드는 장치**(알림·스트릭·목표·통계 그래프)가 전무하고, 개발 쪽엔 자동 테스트·에러 리포팅이 없어 데이터 유실 리스크에 안전망이 없다.

## 관점 1 — 기획 (PM)

**부족한 점**
1. 리텐션 장치 전무 — 알림·스트릭·"오늘 아직 안 했어요" 넛지 없음
2. 진척이 눈에 안 보임 — 캘린더/히트맵, 이번 주 요약 없음
3. 목표 설정 불가
4. 공유·바이럴 장치 없음 (기록 카드 공유, 마일스톤 배지)
5. 수익모델이 배너광고 하나뿐
6. 기기 이전 문턱 — 수동 파일 export/import뿐, 자동 클라우드 백업 없음

**추가해야 할 것 (우선순위 순)**
1. [Phase 1] 세트 간 휴식 타이머 (횟수형 운동에도)
2. [Phase 2] 로컬 알림·리마인더
3. [Phase 2] 홈 화면 "이번 주 요약" + 캘린더 히트맵 + 스트릭
4. [Phase 2] 목표 설정·달성률
5. [Phase 3] 기록 카드 이미지 공유
6. [Phase 3] 프리미엄 구독(광고 제거 + 고급 통계 + 자동 백업)
7. [Phase 4] Apple Health / Google Fit 연동

## 관점 2 — 개발 (Dev)

**부족한 점**
1. 자동 테스트 0건 — 타이머·저장 큐·백업 복원처럼 데이터 유실 직결 코드에 회귀 방지 장치 없음
2. `storage.ts`의 `readJson`이 파싱 실패 시 조용히 fallback — 손상된 데이터를 사용자에게 알리지 않음
3. 에러 리포팅 도구 없음 — 프로덕션 크래시를 알 방법이 없음
4. 기록이 하나의 JSON 배열로 저장돼 누적될수록 느려질 구조
5. 백업 스키마 버전은 있지만 마이그레이션 함수 부재
6. CI 파이프라인 없음 — 타입체크·린트가 로컬 실행 의존

**추가해야 할 것 (우선순위 순)**
1. [Phase 1] `storage.ts` 핵심 함수 스모크 테스트
2. [Phase 1] 에러 리포팅 도입(Sentry 등)
3. [Phase 1] GitHub Actions CI(타입체크·린트)
4. [Phase 2] `readJson` 파싱 실패 시 사용자 알림 경로 추가
5. [Phase 3] 백업 스키마 마이그레이션 전략 문서화·구현
6. [Phase 4] AsyncStorage → expo-sqlite 전환 검토

## 관점 3 — 디자인 (Design)

**부족한 점**
1. 기록 화면이 텍스트뿐 — 그래프·스파크라인 없음
2. 세트 간 휴식 타이머 없음 (횟수형 운동)
3. PR 갱신 순간이 밋밋함 — 토스트 하나뿐
4. 홈 화면 정렬·재배열 불가
5. 로딩 상태가 빈 화면(스켈레톤 없음)
6. 태블릿·가로모드 레이아웃 미고려

**추가해야 할 것 (우선순위 순)**
1. [Phase 1] 횟수형 운동에도 세트 간 휴식 타이머
2. [Phase 1] 로딩 스켈레톤 UI
3. [Phase 2] 기록 화면 추이 스파크라인
4. [Phase 2] PR 갱신 축하 마이크로 인터랙션
5. [Phase 2] 홈 화면 "이번 주 요약" 카드 + 드래그 정렬
6. [Phase 4] 홈스크린 위젯(오늘 상태·스트릭)
7. [Phase 4] 태블릿 레이아웃 최적화
