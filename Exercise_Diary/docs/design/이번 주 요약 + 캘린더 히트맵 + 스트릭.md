# 이번 주 요약 + 캘린더 히트맵 + 스트릭 — 설계

## 화면 구조

> **사용자 요청에 따른 변경(구현 완료 후, 실기기 확인 단계에서):** 원래 설계는 히트맵을 홈 화면의
> "이번 주 요약" 카드 안에 그대로 넣는 것이었다. 그런데 사용자가 "홈에는 이번 주 며칠 운동했는지·
> PR 몇 번인지 숫자 두 개만 보이고, 히트맵처럼 들여다보는 성격의 화면은 따로 구성하는 게 낫겠다"는
> 의견을 줬고(홈 화면의 역할은 "빠르게 운동 골라 시작하기"인데 56칸 그리드가 그 공간을 크게
> 차지한다는 점에 서로 동의함), 진입 경로는 "요약 카드를 탭하면 이동"으로, 스트릭 배지는 기존대로
> 홈에 남기는 것으로 확정했다. 그래서 새 화면 `src/screens/ActivityScreen.tsx`가 추가된다.

> **재변경(실기기 확인 단계, 두 번째 피드백):** `ActivityHeatmap`(8주 히트맵 그리드)을 실제로 써보니
> 범례·요일 라벨을 붙여도 "무슨 의미인지 모르겠다", "정확히 며칠인지 안 보인다"는 피드백을 받았다.
> 히트맵류 표현은 압축된 패턴 파악엔 좋지만 날짜 하나하나를 정확히 짚기엔 약하다는 점에 서로
> 동의해, 누구나 바로 읽을 수 있는 **월 단위 일반 캘린더**(이전/다음 달 이동, 기록 있는 날짜에
> 점 표시, 오늘 날짜 테두리 강조)로 교체했다. `ActivityHeatmap.tsx`는 삭제하고
> `src/components/MonthCalendar.tsx`로 대체한다. 아래 문서에서 "히트맵"을 언급하는 부분은 이
> 교체 이전의 기록이며, 최종 구현은 캘린더 기준이다.

- **`src/lib/stats.ts`** (신규) — 순수 계산 로직. AsyncStorage를 직접 읽어(기존 `storage.ts`의 `getRecords`/`getRepsRecords` 재사용) 이번 주 요약·캘린더 점 표시·스트릭에 필요한 값을 한 번에 계산해 반환한다. UI를 모른다.
- **`src/components/WeeklySummaryCard.tsx`** (신규) — "이번 주 요약" 카드. 활동일수·PR 갱신 횟수 두 지표 텍스트만 담는다. `onPress` prop을 받는 `Pressable`로, 눌리면 활동 기록 화면으로 이동한다. 기록이 전혀 없으면 빈 상태 문구만 보여준다.
- **`src/components/MonthCalendar.tsx`** (신규, `ActivityHeatmap.tsx` 대체) — 월 단위 캘린더. `Set<string>`(기록 있었던 로컬 날짜 키 전체, 기간 제한 없음)을 props로 받고, 컴포넌트 내부 상태로 현재 보고 있는 연/월을 들고 이전/다음 달 이동을 직접 처리한다. 요일 헤더 + 날짜 그리드, 기록 있는 날짜엔 점, 오늘 날짜엔 테두리. `HomeScreen`이 아니라 `ActivityScreen`이 사용한다.
- **`src/components/StreakBadge.tsx`** (신규) — "🔥 N일" 배지 하나짜리 작은 컴포넌트. `HomeScreen`의 운동 목록 카드 안에서 조건부(스트릭 ≥ 2)로 렌더링.
- **`src/screens/HomeScreen.tsx`** (수정) — `getHomeStats(exercises)` 호출 결과를 상태로 들고 `WeeklySummaryCard`를 렌더링하고(탭하면 `onOpenActivity` 콜백 호출), 목록 카드 렌더링부에 `StreakBadge`를 끼워 넣는다.
- **`src/screens/ActivityScreen.tsx`** (신규) — 활동 기록 화면. `AddExerciseScreen`과 같은 헤더 패턴(뒤로가기 chevron + 중앙 타이틀)을 쓴다. 마운트 시 자체적으로 `getExercises()` → `getHomeStats()`를 호출해 통계를 로드하고, 같은 두 지표 텍스트와 `MonthCalendar`를 보여준다.
- **`App.tsx`** (수정) — `Screen` 유니언 타입에 `{ name: 'activity' }` 추가, `HomeScreen`에 `onOpenActivity={() => setScreen({ name: 'activity' })}` 전달, `screen.name === 'activity'`일 때 `ActivityScreen` 렌더링(뒤로가기는 기존 하드웨어 back 처리 로직이 이미 "홈이 아니면 홈으로"를 처리하므로 별도 분기 불필요).

```
App
├─ HomeScreen
│   ├─ header (기존)
│   ├─ WeeklySummaryCard          ← 신규, 헤더와 검색창 사이, 탭하면 ActivityScreen으로 이동
│   ├─ searchBox (기존)
│   └─ FlatList (기존, 각 카드에 StreakBadge 추가)
└─ ActivityScreen                 ← 신규, WeeklySummaryCard를 탭했을 때만 마운트
    └─ MonthCalendar              ← 신규, 컴포넌트 내부에서 월 이동 상태 + 연도·월 선택 시트를 관리
```

> **추가 변경(같은 실기기 확인 단계, 세 번째·네 번째 피드백):** 사용자가 "날짜를 눌렀을 때 그날
> 무슨 운동을 했는지 보여주고 그 운동을 누르면 기록 화면까지 보여주면 기록 화면을 더 많이 쓸 것
> 같다"는 의견과, "연도·월도 직접 골라서 이동할 수 있으면 좋겠다(연도는 최근 2년 전까지, 달은
> 12달 다)"는 의견을 추가로 줬다. 스펙의 제외 범위에 있던 "날짜 탭 인터랙션 없음" 항목이 이번에
> 뒤집힌 것 — 스펙 문서도 이 대화 시점에 맞춰 갱신했다. 다음이 추가된다:
> - **`src/lib/stats.ts`** — `getExerciseDatedValues`를 export하고, 새 함수
>   `getExercisesRecordedOn(dateKey, exercises)`를 추가한다: 운동별로 그 날짜에 기록이 있는지
>   확인해, 있는 운동만 원래 순서대로 반환한다.
> - **`src/components/MonthCalendar.tsx`** — `onSelectDate: (dateKey: string) => void` prop 추가.
>   기록 있는 날짜 셀만 `Pressable`로 감싸 누르면 호출한다(기록 없는 날짜는 탭 반응 자체가 없다).
>   또한 월 제목을 누르면 여는 연도·월 선택 시트(기존 `BottomSheet` 재사용)를 컴포넌트 내부에
>   추가한다 — 연도 칩(올해 포함 최근 3년) + 12개월 그리드, 선택 연도가 올해면 미래 달 비활성화.
> - **`src/screens/ActivityScreen.tsx`** — `exercises` 목록을 상태로 들고(기존엔 통계 계산에만
>   씀), `onSelectDate`에서 `getExercisesRecordedOn`을 호출해 그 결과를 보여준다. 목록의 운동을
>   누르면 새 prop `onOpenExerciseRecords(exercise)`를 호출한다.
> - **`App.tsx`** — `Screen` 유니언의 `exercise` variant에 `initialTab?: 'records'`를 추가하고,
>   `ActivityScreen`에 `onOpenExerciseRecords={(exercise) => setScreen({ name: 'exercise', exercise, initialTab: 'records' })}`를
>   전달한다.
>
> **추가 변경(다섯 번째 피드백):** "바텀시트보다 캘린더 화면 아래에 리스트로 나오는 게 나을 것
> 같다"는 의견으로, 위에서 말한 `BottomSheet` 재사용 방식을 걷어내고 캘린더 바로 아래 인라인
> 섹션(날짜 제목 + 닫기 ✕ 버튼 + 운동 목록)으로 바꿨다 — `ActivityScreen`의 `ScrollView` 안에서
> `selectedDateKey`가 있을 때만 조건부 렌더링된다. `MonthCalendar`에 `selectedDateKey?: string | null`
> prop을 추가해, 선택된 날짜 셀을 채워진 원(`backgroundColor: accent.primary`, 텍스트는
> `accent.onPrimary`)으로 표시한다 — "오늘"의 테두리 링과는 다른 시각 신호라 두 상태가 겹쳐도
> (오늘이면서 선택됨) 헷갈리지 않는다.
>
> **여섯 번째 피드백(요일 색상):** "토요일은 파란색, 일요일은 빨간색으로 표시하면 보기 편할 것
> 같다"는 의견으로, 요일 헤더와 날짜 숫자 색을 요일 인덱스 기준으로 분기했다(`weekdayTextColor`
> 헬퍼, `MonthCalendar.tsx`). 일요일은 `accent.danger`(이미 두 모드·모든 강조색 프리셋에서 고정된
> 빨강)를 재사용하고, 토요일은 이 목적 전용의 새 고정값 `SATURDAY_COLOR = '#2F80ED'`를 둔다 —
> 강조색 프리셋이 파랑(MyFitnessPal Blue)이어도 항상 같은 톤을 유지해야 하므로 `accent.primary`를
> 쓰지 않는다(danger 토큰과 같은 이유로 프리셋과 무관하게 고정).
> - **`src/screens/ExerciseScreen.tsx`** — `initialTab?: Tab` prop을 추가해 `useState<Tab>(initialTab ?? 'measure')`로
>   초기 탭을 결정한다(기존엔 항상 `'measure'`로 시작).
>
> **일곱 번째 피드백(활동 기록 화면에서 두 지표 제거):** "며칠 운동했고 PR 몇 회 경신했는지는
> 홈 화면에만 나오면 된다"는 요청으로, `ActivityScreen`에서 `weeklyActiveDays`/`weeklyPrCount`를
> 렌더링하던 부분을 통째로 뺐다(관련 스타일 `statsRow`/`statText`/`emptyText`도 삭제). `getHomeStats`
> 호출 자체는 그대로 둔다 — 캘린더의 `recordedDates`와 날짜 탭 조회용 `dateKeysByExerciseId`가
> 여전히 필요하기 때문이다. 부수 효과로, 코드 리뷰에서 지적됐던 "홈 카드와 활동 기록 화면의
> 통계 텍스트 블록 중복" 문제도 자연히 해소됐다.
>
> **여덟 번째 피드백(뒤로가기 복귀 위치):** "활동 기록 화면에서 운동 기록 화면으로 넘어갔다가
> 뒤로가기 하면 활동 기록 화면으로 못 돌아간다"는 지적으로, `App.tsx`의 화면 전환에 아주 얕은
> "돌아갈 곳" 정보를 추가했다. 전체 내비게이션 히스토리 스택을 두는 대신, `exercise` 화면 자신의
> 상태에 `returnTo?: 'home' | 'activity'` 필드 하나만 둬서 필요한 한 단계만 기억한다:
> - `ActivityScreen`의 `onOpenExerciseRecords`가 화면을 열 때 `returnTo: 'activity'`를 함께 넘긴다
>   (`HomeScreen`에서 여는 기존 경로는 `returnTo` 없이 그대로 — 기본값 `'home'`).
> - `App.tsx`에 `goBack()` 헬퍼(`useCallback`, 함수형 `setScreen` 사용)를 두고, 화면 버튼의 `onBack`과
>   하드웨어 뒤로가기 핸들러 양쪽 모두 이 함수 하나로 통일한다 — `screen.name === 'exercise' &&
>   screen.returnTo === 'activity'`면 활동 기록 화면으로, 아니면 홈으로.
> - `ActivityScreen`/`AddExerciseScreen` 자신의 뒤로가기는 항상 홈으로 가는 기존 동작 그대로다
>   (이 두 화면은 지금 홈에서만 열리므로 더 깊은 복귀 경로가 필요 없다).

> **아홉 번째 피드백(바텀시트 끝까지 끌어올리는 제스처):** "bottom modal 위로 올리면 화면 끝까지
> 올라가는 제스처도 추가하고 싶다"는 요청으로, 도움말·설정·(이 기능에서 새로 쓰는) 캘린더
> 연도·월 선택 시트가 모두 공유하는 `src/components/BottomSheet.tsx`에 드래그 확장을 추가했다.
> - 기본 높이는 기존과 동일하게 "내용 실측 높이, 단 화면의 85% 상한"이다(`onLayout`/
>   `onContentSizeChange`로 헤더·콘텐츠 높이를 재고, `insets.bottom`까지 더한 값을 자연 높이로
>   쓴다 — `SafeAreaView(edges=['bottom'])`가 그만큼 padding을 먹으므로 빠뜨리면 인셋이 있는
>   기기에서 내용이 살짝 잘려 불필요한 스크롤이 생긴다).
> - 핸들바(헤더 영역)를 위로 끌면 `Animated.Value`로 애니메이션되는 높이가 `windowHeight -
>   insets.top`까지 확장되고, 아래로 끌거나(또는 빠르게 아래로 튕기면) 다시 기본 높이로
>   스냅한다. 드래그 속도는 move 이벤트 사이 `pageY`/`Date.now()` 델타로 직접 계산하고,
>   마지막 move로부터 80ms 넘게 지난 뒤 뗀 경우는 속도를 0으로 취급한다(손가락을 멈춘 채
>   들고 있다 떼도 튕긴 것으로 오판하지 않도록).
> - `PanResponder.create()` 대신 `View`의 네이티브 responder prop(`onStartShouldSetResponder`
>   등)을 JSX에 직접 건다 — 이 프로젝트의 React Compiler 대비 ESLint 규칙(`react-hooks/refs`)이
>   `PanResponder.create()` 호출 자체를(그 콜백이 ref를 참조한다는 이유만으로, 실제로는 나중에
>   제스처가 발생할 때만 실행되는데도) "렌더 중 ref 접근"으로 오탐해서, 렌더 중 별도 "생성 호출"을
>   거치지 않는 이 방식으로 피했다.
> - `insets`는 반드시 이 Modal 자신의 `SafeAreaProvider`(컴포넌트를 `BottomSheet`(Modal+Provider
>   래퍼)와 `BottomSheetContent`(실제 로직, Provider 안쪽)로 나눠 안쪽에서 읽는다) 안에서 읽어야
>   한다 — 바깥(App 루트) Provider에서 읽으면 이 Modal이 실제로 물려받지 못하는 값을 쓰게 된다.
> - 도움말/설정처럼 시트 하나를 여러 종류의 내용으로 돌려쓰는 화면(`HomeScreen`)에서는 내용이
>   바뀔 때마다 컴포넌트가 새로 마운트되도록 `key={sheetKind}`를 준다 — 그렇지 않으면 이전
>   내용의 측정값(높이)이 한 프레임 남아있다가 새 내용 측정 후 스냅되는 게 보인다. 같은 시트를
>   확장한 채로 닫았다 다시 여는 경우를 위해, 다시 열릴 때 확장 상태를 기본값으로 되돌리는
>   이펙트는 `useLayoutEffect`로 커밋 전에 반영한다.

> **열 번째 피드백(그 외 자잘한 다듬기):**
> - 캘린더에서 날짜를 선택한 채로 화살표나 연·월 선택으로 다른 달을 보면, 선택 표시는 그 달에
>   없는데 아래 날짜 섹션만 남는 문제가 있었다 — `MonthCalendar`에 `onMonthChange` 콜백을 추가해
>   달이 바뀔 때마다 새 연/월을 알리고, `ActivityScreen`은 선택된 날짜가 그 달에 없으면 선택을
>   해제한다.
> - 다크 모드에서 요일 헤더(월~금)와 "운동한 날" 범례 글자가 `accent.textFaint`(플레이스홀더용,
>   대비가 낮음)를 쓰고 있어 잘 안 보였다 — `accent.textMuted`로 교체했다.
> - 도움말 아이콘(`help-circle-outline`)과 설정 아이콘(`settings-outline`)이 같은 `size` 값인데도
>   실제 렌더링 크기가 달라 보였다 — Ionicons 글리프 자체의 내부 여백이 아이콘마다 달라서다.
>   도움말 아이콘 크기를 26→30으로 올려 시각적으로 맞췄다.
> - 도움말 시트에 "이번 주 활동 확인"(홈 카드·캘린더·스트릭 배지 안내) 섹션을 새로 추가했다(4개
>   언어 모두, `HELP_SECTION_ICONS`에 `calendar-outline` 추가).
> - 토요일·일요일 색은 원래 `MonthCalendar.tsx` 안에 하드코딩(토)하거나 `accent.danger`를

## 상태 설계

`HomeScreen`은 이미 `loadExercises()`를 `useEffect(..., [])`에서 마운트 시 1회 호출해 운동 목록을 불러온다. `App.tsx`가 화면 전환을 `{screen.name === 'home' && <HomeScreen />}` 형태의 조건부 렌더링으로 처리하기 때문에(라우팅 라이브러리 없이 언마운트/리마운트 방식), 측정 화면에 갔다가 홈으로 돌아오면 `HomeScreen`이 새로 마운트되며 `loadExercises()`가 다시 실행된다 — 별도 focus 이벤트 없이도 이 패턴 하나로 통계가 자동 갱신된다(로컬 알림 리마인더 이전 기능들과 동일한 전제).

- `HomeScreen`에 상태 추가: `const [homeStats, setHomeStats] = useState<HomeStats | null>(null);`
- `loadExercises()` 안에서 `getExercises()`로 받은 목록으로 `getHomeStats(next)`를 이어서 호출해 `homeStats`를 채운다(운동 목록과 통계는 같은 생명주기).
- `homeStats === null`인 동안(최초 로드 전)은 `WeeklySummaryCard` 자리에 기존 `Skeleton` 패턴으로 자리표시자를 보여준다(운동 목록 스켈레톤과 같은 원칙).
- 전역 context나 새로운 provider는 필요 없다 — 이 통계는 홈 화면 진입 시점의 스냅샷이면 충분하고, 다른 화면과 실시간으로 공유될 필요가 없다(요구사항 7의 "재계산"은 홈 화면에 다시 들어올 때 다시 계산하는 것으로 충족된다).

## 데이터 모델

새로운 영속 데이터는 없다 — 기존 `TimeRecord`/`RepsRecord`(둘 다 `measuredAt: string` ISO 8601 보유)만 읽어 매번 다시 계산한다. `src/lib/types.ts`에 타입을 추가하지 않고, 계산 결과 타입은 `src/lib/stats.ts`에 로컬로 정의한다:

```ts
// src/lib/stats.ts
export type HomeStats = {
  hasAnyRecordEver: boolean;       // 요구사항 9: 전체 빈 상태 판정용 (이번 주 활동 0일과는 다른 개념)
  weeklyActiveDays: number;        // 0~7, 최근 7일(오늘 포함) 중 운동 종류 무관 기록이 있던 날의 수
  weeklyPrCount: number;           // 최근 7일 동안 발생한 PR 갱신 이벤트 수(전 운동 합산)
  recordedDates: Set<string>;      // 기간 제한 없이, 기록이 있던 모든 로컬 날짜 키(YYYY-MM-DD) 집합 — 캘린더가 어느 달로 이동해도 정확히 표시하려면 8주로 잘라둘 수 없다(요구사항 11)
```

## 핵심 로직

### 1. 로컬 날짜 키 계산 (타임존 안전)

`measuredAt`(ISO 문자열)을 기기 로컬 달력 날짜로 변환한다. `new Date(iso)`는 로컬 타임존으로 파싱되므로 `getFullYear/getMonth/getDate`를 쓰면 별도 변환 없이 로컬 날짜가 나온다(요구사항 8).

```ts
function localDateKey(iso: string): string {
  const d = new Date(iso);
  const y = d.getFullYear();
  const m = `${d.getMonth() + 1}`.padStart(2, '0');
  const day = `${d.getDate()}`.padStart(2, '0');
  return `${y}-${m}-${day}`;
}
```

날짜 키끼리의 "며칠 차이"는 `Date.UTC(y, m-1, d)`로 만든 자정 타임스탬프의 차를 86400000으로 나눠 계산한다(로컬 자정을 UTC로 재해석해 두 값 모두 같은 기준점에서 비교하므로 서머타임 등 지역 규칙과 무관하게 정확한 정수 일수 차가 나온다). 이 함수(`daysBetweenKeys`, `addDaysToKey`)는 히트맵 그리드 계산과 스트릭 계산이 공유한다.

### 2. 운동별 기록 → `{ measuredAt, value }[]` 정규화

시간형은 `durationMs`, 횟수·세트형은 `RepsRecordItem.tsx`가 이미 export하는 `totalReps(record)`를 값으로 쓴다 — `RecordsScreen`이 "최고 기록"을 판정하는 것과 완전히 같은 기준이라 두 화면의 PR 개념이 어긋나지 않는다.

```ts
async function getExerciseDatedValues(exercise: Exercise): Promise<{ measuredAt: string; value: number }[]> {
  if (exercise.measureType === 'time') {
    const records = await getRecords(exercise.id);
    return records.map((r) => ({ measuredAt: r.measuredAt, value: r.durationMs }));
  }
  const records = await getRepsRecords(exercise.id);
  return records.map((r) => ({ measuredAt: r.measuredAt, value: totalReps(r) }));
}
```

### 3. PR 갱신 이벤트 판정

기록을 `measuredAt` 오름차순으로 정렬한 뒤, 이전까지의 최댓값보다 큰 값이 나올 때마다 "그 시점에 PR을 갱신했다"고 표시한다. 맨 첫 기록도 PR 이벤트로 센다(그 시점 기준 유일한 최고 기록이므로 `RecordsScreen`의 "최고 기록 = 전체 reduce" 표시와 일관됨).

```ts
function findPrEventDateKeys(datedValues: { measuredAt: string; value: number }[]): string[] {
  const sorted = [...datedValues].sort((a, b) => (a.measuredAt < b.measuredAt ? -1 : 1));
  let best = -Infinity;
  const events: string[] = [];
  for (const { measuredAt, value } of sorted) {
    if (value > best) {
      best = value;
      events.push(localDateKey(measuredAt));
    }
  }
  return events;
}
```

### 4. 스트릭 계산 (운동별)

그 운동의 날짜 키 집합(중복 제거)에서, 가장 최근 기록일부터 거꾸로 하루도 안 빠지고 이어진 날 수를 센다. 가장 최근 기록일이 오늘도 어제도 아니면(이틀 이상 공백) 0으로 취급한다.

```ts
function computeStreak(dateKeys: Set<string>, today: string): number {
  if (dateKeys.size === 0) return 0;
  const lastKey = [...dateKeys].sort().at(-1)!; // 문자열 정렬 = 날짜순 정렬(YYYY-MM-DD)
  if (daysBetweenKeys(lastKey, today) >= 2) return 0;
  let streak = 0;
  let cursor = lastKey;
  while (dateKeys.has(cursor)) {
    streak += 1;
    cursor = addDaysToKey(cursor, -1);
  }
  return streak;
}
```

### 5. `getHomeStats(exercises)` — 한 번에 조립

```ts
export async function getHomeStats(exercises: Exercise[]): Promise<HomeStats> {
  const today = localDateKey(new Date().toISOString());
  const perExercise = await Promise.all(
    exercises.map(async (exercise) => ({
      exercise,
      datedValues: await getExerciseDatedValues(exercise),
    })),
  );

  const recordedDates = new Set<string>();
  const activeDaysThisWeek = new Set<string>();
  const streaksByExerciseId: Record<string, number> = {};
  let weeklyPrCount = 0;
  let hasAnyRecordEver = false;

  for (const { exercise, datedValues } of perExercise) {
    if (datedValues.length > 0) hasAnyRecordEver = true;
    const dateKeys = new Set(datedValues.map((v) => localDateKey(v.measuredAt)));
    for (const key of dateKeys) {
      recordedDates.add(key); // 기간 제한 없음 — 캘린더가 어느 달을 보든 정확해야 하므로
      if (daysBetweenKeys(key, today) < 7) activeDaysThisWeek.add(key);
    }
    streaksByExerciseId[exercise.id] = computeStreak(dateKeys, today);
    weeklyPrCount += findPrEventDateKeys(datedValues).filter((key) => daysBetweenKeys(key, today) < 7).length;
  }

  return {
    hasAnyRecordEver,
    weeklyActiveDays: activeDaysThisWeek.size,
    weeklyPrCount,
    recordedDates,
    streaksByExerciseId,
  };
}
```

`daysBetweenKeys(key, today) < 7`은 "오늘부터 과거 6일 전까지, 오늘 포함 7일"을 뜻한다(요구사항 1의 최근 7일 롤링).

### 6. 월 캘린더 구성 (`MonthCalendar.tsx` 내부)

> 이 절은 삭제된 `ActivityHeatmap`(8주 히트맵 그리드) 설계를 대체한다. 히트맵 버전에서 겪었던
> "flex+aspectRatio로 정사각형 셀을 만들면 부모 높이가 콘텐츠로부터 거꾸로 결정돼야 하는
> 컨테이너에서 0으로 접힌다"는 레이아웃 함정은 그대로 유효한 교훈이라, 캘린더의 날짜 셀도 같은
> 이유로 `onLayout` 측정 + 픽셀 단위 `width`/`height` 지정 방식을 그대로 재사용한다.

`MonthCalendar`는 자체 상태(`viewedYear`, `viewedMonth`, 0-indexed)로 현재 보고 있는 달을 들고, 이전/다음 달 버튼이 그 상태를 바꾼다. 다음 달 버튼은 `viewedYear/viewedMonth`가 오늘이 속한 달과 같으면 비활성화된다(요구사항 6, 미래로 이동 불가).

```ts
type DayCell = { key: string; day: number } | null;

function buildMonthWeeks(year: number, month: number): DayCell[][] {
  const firstOfMonth = new Date(year, month, 1);
  const startDow = firstOfMonth.getDay(); // 0=일 ... 6=토, 그 달 1일 앞을 이만큼 비운다
  const daysInMonth = new Date(year, month + 1, 0).getDate();

  const cells: DayCell[] = [];
  for (let i = 0; i < startDow; i++) cells.push(null);
  for (let day = 1; day <= daysInMonth; day++) {
    cells.push({ key: `${year}-${pad(month + 1)}-${pad(day)}`, day });
  }
  while (cells.length % 7 !== 0) cells.push(null); // 마지막 주도 7칸으로 채움

  const weeks: DayCell[][] = [];
  for (let i = 0; i < cells.length; i += 7) weeks.push(cells.slice(i, i + 7));
  return weeks;
}
```

월 제목(예: "2026년 8월", "August 2026")은 4개 언어 각각에 문자열을 새로 추가하는 대신 `Intl.DateTimeFormat(SPEECH_LOCALE[language], { year: 'numeric', month: 'long' })`로 만든다 — 이미 `speechLocale.ts`에 있는 언어→로케일 태그 매핑(`ko-KR`/`en-US`/`ja-JP`/`zh-CN`)을 재사용하면 각 언어의 표준 표기를 별도 번역 문자열 없이 정확히 얻을 수 있다.

날짜 셀: 기록이 있는 날짜(`recordedDates.has(cell.key)`)엔 숫자 아래 작은 점을 그린다(요구사항 4). 오늘 날짜(`cell.key === todayKey`)엔 숫자를 감싸는 원형 테두리를 그린다(요구사항 5) — 점과 테두리는 서로 다른 시각 신호라 동시에 있어도 겹쳐 보이지 않는다. (다섯 번째 피드백 이후) 기록이 있는 날짜만 `Pressable`로 감싸 탭하면 `onSelectDate`가 호출된다 — 기록 없는 날은 보여줄 게 없어 탭 반응을 주지 않는다. 각 셀은 `accessibilityLabel`로 날짜·기록 여부·오늘 여부를 함께 노출한다.

> **구현 중 발견한 버그(선택된 날짜가 사각형으로 보임):** 선택된 날짜(사용자가 캘린더에서 누른
> 날짜, `isSelected`)의 채움 원을 처음 구현했을 때 안드로이드에서 완전히 각진 사각형으로
> 렌더링됐다. 원인은 두 가지가 겹쳐 있었다: (1) `width:'78%'` + `aspectRatio:1` 조합 대신
> `cellSize` 기준 픽셀 값(`dayCircleSize = cellSize * 0.78`)으로 바꿔도 여전히 사각형이었는데,
> (2) 진짜 원인은 **안드로이드에서 `backgroundColor`만 있고 테두리(`borderWidth`)가 없는 View는
> `borderRadius`를 무시하고 각진 사각형으로 그려지는 알려진 문제**였다(오늘 표시처럼 테두리만
> 있는 경우엔 문제없이 둥글게 나온다 — 실제로 재현해 확인함). `dayCircle` 스타일에
> `overflow: 'hidden'`을 추가해 배경도 강제로 `borderRadius`에 맞춰 잘리게 하는 것으로 해결했다.
> 배경색이 있는 원형/pill 뷰를 새로 만들 때는 테두리가 없다면 `overflow: 'hidden'`을 같이
> 챙길 것.

캘린더 아래에 점 하나 + `t.activity.recordedDayLegend`("운동한 날") 한 줄만 붙인다 — 일반 달력은 그 자체로 이미 익숙한 형태라 히트맵처럼 별도의 "빈칸/채운칸" 범례 두 줄이 필요 없고, 점의 의미만 확인시켜주면 충분하다.

뒤로가기 버튼 접근성 라벨은 기존 화면들과 동일하게 `t.common.back`을 재사용한다. 월/연도 제목과 연도·월 선택 시트의 월 이름(1월~12월 등)은 `Intl.DateTimeFormat`으로 만들어 별도 번역 문자열이 필요 없다(핵심 로직 6번 참고). 날짜별 운동 목록 시트의 제목은 새 문자열이 아니라 `ActivityScreen`이 직접 `YYYY.MM.DD (요일)` 형식으로 조립한다(`RecordsScreen`의 날짜 표기와 동일한 관행).

## 요구사항 대응

| 스펙 요구사항 | 설계 대응 |
|---|---|
| 1. 이번 주 요약 카드(활동일수, PR 갱신 횟수만) | `getHomeStats().weeklyActiveDays`/`weeklyPrCount`, `WeeklySummaryCard` |
| 2. 요약 카드는 탭 가능, 탭하면 활동 기록 화면 이동 | `WeeklySummaryCard`의 `onPress` → `HomeScreen`의 `onOpenActivity` → `App.tsx`가 `screen: {name:'activity'}`로 전환 |
| 3. 활동 기록 화면에 두 지표 + 월 캘린더 | `ActivityScreen`이 자체적으로 `getHomeStats()` 호출, 텍스트 + `MonthCalendar` 렌더링 |
| 4. 기록 있는 날짜에 점 표시 | `MonthCalendar`가 `recordedDates.has(cell.key)`일 때 날짜 아래 점(`recordDot`) 렌더링 |
| 5. 오늘 날짜 시각적 구분 | `cell.key === todayKey`일 때 원형 테두리(`dayCircle` + `borderWidth`) |
| 6. 월 이동, 미래 달 불가 | `MonthCalendar`의 `viewedYear`/`viewedMonth` 상태 + `goPrevMonth`/`goNextMonth`, `isCurrentMonth`일 때 다음 달 버튼 비활성화 |
| 7. 연도·월 직접 선택(최근 3년, 올해는 미래 달 비활성화) | 월 제목 `Pressable` → `pickerOpen` 상태로 `BottomSheet` 표시, 연도 칩 3개 + 12개월 그리드, `pickerYear === now.getFullYear() && month > now.getMonth()`일 때 `disabled` |
| 8. 기록 있는 날짜 탭 → 그날 운동 목록 | `MonthCalendar`가 `recorded`인 셀만 `Pressable`로 감싸 `onSelectDate(cell.key)` 호출 → `ActivityScreen`이 `getExercisesRecordedOn`으로 동기 필터링해 캘린더 바로 아래 인라인 섹션에 나열(다섯 번째 피드백 이후 `BottomSheet`에서 인라인으로 변경). 달이 바뀌면(`onMonthChange`) 선택한 날짜가 그 달에 없을 때 선택을 해제한다(열 번째 피드백) |
| 9. 목록에서 운동 선택 → 그 운동 기록 탭으로 이동 | 인라인 섹션의 운동 행 `onPress` → `onOpenExerciseRecords(exercise)` → `App.tsx`가 `screen:{name:'exercise', exercise, initialTab:'records', returnTo:'activity'}`로 전환 → `ExerciseScreen`이 `initialTab`으로 `useState<Tab>` 초기화, 뒤로가기는 `returnTo`를 보고 활동 기록 화면으로 복귀(여덟 번째 피드백) |
| 10. 활동 기록 화면 뒤로가기 | `AddExerciseScreen`과 동일한 헤더 패턴(`chevron-back` + `onBack`), 하드웨어 back은 `App.tsx`의 `goBack()`(여덟 번째 피드백에서 통일)이 처리 — 활동 기록 화면 자신은 항상 홈으로 복귀 |
| 11. 운동별 개별 스트릭 | `streaksByExerciseId`(운동 id 키), `getExerciseDatedValues`가 해당 운동 기록만 사용 |
| 12. 스트릭 유효 판정(오늘/어제까지, 그저께 이전은 0) | `computeStreak`의 `daysBetweenKeys(lastKey, today) >= 2` 분기 |
| 13. 스트릭 2일 미만은 배지 숨김 | `StreakBadge`를 `HomeScreen`에서 `streak >= 2`일 때만 렌더링 |
| 14. 기록 시간 보정/삭제 반영, 월 이동 범위 무제한 | `recordedDates`가 기간 제한 없이 전체를 담아 매번 새로 계산(캐시 없음), 홈/활동 기록 화면 재진입 시 다시 호출됨 |
| 15. 로컬 시간대 기준 날짜 판정 | `localDateKey`가 로컬 `Date` getter만 사용 |
| 16. 기록 전무 시 빈 상태 | `hasAnyRecordEver === false`일 때 `WeeklySummaryCard`는 빈 상태 문구, `MonthCalendar`는 점 없이 정상 렌더링 |
| 17. 4개 언어 번역 | i18n 신규 키 섹션 참고 |
| 18. 로컬 전용, 서버 통신 없음 | `stats.ts`는 기존 `storage.ts`(AsyncStorage) 함수만 호출, 네트워크 요청 없음 |
