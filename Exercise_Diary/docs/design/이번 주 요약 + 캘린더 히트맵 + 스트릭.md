## 상태 설계

`HomeScreen`은 이미 `loadExercises()`를 `useEffect(..., [])`에서 마운트 시 1회 호출해 운동 목록을 불러온다. `App.tsx`가 화면 전환을 `{screen.name === 'home' && <HomeScreen />}` 형태의 조건부 렌더링으로 처리하기 때문에(라우팅 라이브러리 없이 언마운트/리마운트 방식), 측정 화면에 갔다가 홈으로 돌아오면 `HomeScreen`이 새로 마운트되며 `loadExercises()`가 다시 실행된다 — 별도 focus 이벤트 없이도 이 패턴 하나로 통계가 자동 갱신된다(로컬 알림 리마인더 이전 기능들과 동일한 전제).

- `HomeScreen`에 상태 추가: `const [homeStats, setHomeStats] = useState<HomeStats | null>(null);`
- `loadExercises()` 안에서 `getExercises()`로 받은 목록으로 `getHomeStats(next)`를 이어서 호출해 `homeStats`를 채운다(운동 목록과 통계는 같은 생명주기).
- `homeStats === null`인 동안(최초 로드 전)은 `WeeklySummaryCard` 자리에 기존 `Skeleton` 패턴으로 자리표시자를 보여준다(운동 목록 스켈레톤과 같은 원칙).
- 전역 context나 새로운 provider는 필요 없다 — 이 통계는 홈 화면 진입 시점의 스냅샷이면 충분하고, 다른 화면과 실시간으로 공유될 필요가 없다(요구사항 7의 "재계산"은 홈 화면에 다시 들어올 때 다시 계산하는 것으로 충족된다).

## 데이터 모델

새로운 영속 데이터는 없다 — 기존 `TimeRecord`/`RepsRecord`(둘 다 `measuredAt: string` ISO 8601 보유)만 읽어 매번 다시 계산한다. `src/lib/types.ts`에 타입을 추가하지 않고, 계산 결과 타입은 `src/lib/stats.ts`에 로컬로 정의한다:

```ts
// src/lib/stats.ts
export type HomeStats = {
  hasAnyRecordEver: boolean;       // 요구사항 9: 전체 빈 상태 판정용 (이번 주 활동 0일과는 다른 개념)
  weeklyActiveDays: number;        // 0~7, 최근 7일(오늘 포함) 중 운동 종류 무관 기록이 있던 날의 수
  weeklyPrCount: number;           // 최근 7일 동안 발생한 PR 갱신 이벤트 수(전 운동 합산)
  recordedDates: Set<string>;      // 기간 제한 없이, 기록이 있던 모든 로컬 날짜 키(YYYY-MM-DD) 집합 — 캘린더가 어느 달로 이동해도 정확히 표시하려면 8주로 잘라둘 수 없다(요구사항 11)
  streaksByExerciseId: Record<string, number>; // 운동 id -> 그 운동만의 연속 기록일수
};
```

## 핵심 로직

### 1. 로컬 날짜 키 계산 (타임존 안전)

`measuredAt`(ISO 문자열)을 기기 로컬 달력 날짜로 변환한다. `new Date(iso)`는 로컬 타임존으로 파싱되므로 `getFullYear/getMonth/getDate`를 쓰면 별도 변환 없이 로컬 날짜가 나온다(요구사항 8).

```ts
function localDateKey(iso: string): string {
  const d = new Date(iso);
  const y = d.getFullYear();
  const m = `${d.getMonth() + 1}`.padStart(2, '0');
  const day = `${d.getDate()}`.padStart(2, '0');
  return `${y}-${m}-${day}`;
}
```

날짜 키끼리의 "며칠 차이"는 `Date.UTC(y, m-1, d)`로 만든 자정 타임스탬프의 차를 86400000으로 나눠 계산한다(로컬 자정을 UTC로 재해석해 두 값 모두 같은 기준점에서 비교하므로 서머타임 등 지역 규칙과 무관하게 정확한 정수 일수 차가 나온다). 이 함수(`daysBetweenKeys`, `addDaysToKey`)는 히트맵 그리드 계산과 스트릭 계산이 공유한다.

### 2. 운동별 기록 → `{ measuredAt, value }[]` 정규화

시간형은 `durationMs`, 횟수·세트형은 `RepsRecordItem.tsx`가 이미 export하는 `totalReps(record)`를 값으로 쓴다 — `RecordsScreen`이 "최고 기록"을 판정하는 것과 완전히 같은 기준이라 두 화면의 PR 개념이 어긋나지 않는다.

```ts
async function getExerciseDatedValues(exercise: Exercise): Promise<{ measuredAt: string; value: number }[]> {
  if (exercise.measureType === 'time') {
    const records = await getRecords(exercise.id);
    return records.map((r) => ({ measuredAt: r.measuredAt, value: r.durationMs }));
  }
  const records = await getRepsRecords(exercise.id);
  return records.map((r) => ({ measuredAt: r.measuredAt, value: totalReps(r) }));
}
```

### 3. PR 갱신 이벤트 판정

기록을 `measuredAt` 오름차순으로 정렬한 뒤, 이전까지의 최댓값보다 큰 값이 나올 때마다 "그 시점에 PR을 갱신했다"고 표시한다. 맨 첫 기록도 PR 이벤트로 센다(그 시점 기준 유일한 최고 기록이므로 `RecordsScreen`의 "최고 기록 = 전체 reduce" 표시와 일관됨).

```ts
function findPrEventDateKeys(datedValues: { measuredAt: string; value: number }[]): string[] {
  const sorted = [...datedValues].sort((a, b) => (a.measuredAt < b.measuredAt ? -1 : 1));
  let best = -Infinity;
  const events: string[] = [];
  for (const { measuredAt, value } of sorted) {
    if (value > best) {
      best = value;
      events.push(localDateKey(measuredAt));
    }
  }
  return events;
}
```

### 4. 스트릭 계산 (운동별)

그 운동의 날짜 키 집합(중복 제거)에서, 가장 최근 기록일부터 거꾸로 하루도 안 빠지고 이어진 날 수를 센다. 가장 최근 기록일이 오늘도 어제도 아니면(이틀 이상 공백) 0으로 취급한다.

```ts
function computeStreak(dateKeys: Set<string>, today: string): number {
  if (dateKeys.size === 0) return 0;
  const lastKey = [...dateKeys].sort().at(-1)!; // 문자열 정렬 = 날짜순 정렬(YYYY-MM-DD)
  if (daysBetweenKeys(lastKey, today) >= 2) return 0;
  let streak = 0;
  let cursor = lastKey;
  while (dateKeys.has(cursor)) {
    streak += 1;
    cursor = addDaysToKey(cursor, -1);
  }
  return streak;
}
```

### 5. `getHomeStats(exercises)` — 한 번에 조립

```ts
export async function getHomeStats(exercises: Exercise[]): Promise<HomeStats> {
  const today = localDateKey(new Date().toISOString());
  const perExercise = await Promise.all(
    exercises.map(async (exercise) => ({
      exercise,
      datedValues: await getExerciseDatedValues(exercise),
    })),
  );

  const recordedDates = new Set<string>();
  const activeDaysThisWeek = new Set<string>();
  const streaksByExerciseId: Record<string, number> = {};
  let weeklyPrCount = 0;
  let hasAnyRecordEver = false;

  for (const { exercise, datedValues } of perExercise) {
    if (datedValues.length > 0) hasAnyRecordEver = true;
    const dateKeys = new Set(datedValues.map((v) => localDateKey(v.measuredAt)));
    for (const key of dateKeys) {
      recordedDates.add(key); // 기간 제한 없음 — 캘린더가 어느 달을 보든 정확해야 하므로
      if (daysBetweenKeys(key, today) < 7) activeDaysThisWeek.add(key);
    }
    streaksByExerciseId[exercise.id] = computeStreak(dateKeys, today);
    weeklyPrCount += findPrEventDateKeys(datedValues).filter((key) => daysBetweenKeys(key, today) < 7).length;
  }

  return {
    hasAnyRecordEver,
    weeklyActiveDays: activeDaysThisWeek.size,
    weeklyPrCount,
    recordedDates,
    streaksByExerciseId,
  };
}
```

`daysBetweenKeys(key, today) < 7`은 "오늘부터 과거 6일 전까지, 오늘 포함 7일"을 뜻한다(요구사항 1의 최근 7일 롤링).

### 6. 월 캘린더 구성 (`MonthCalendar.tsx` 내부)

> 이 절은 삭제된 `ActivityHeatmap`(8주 히트맵 그리드) 설계를 대체한다. 히트맵 버전에서 겪었던
> "flex+aspectRatio로 정사각형 셀을 만들면 부모 높이가 콘텐츠로부터 거꾸로 결정돼야 하는
> 컨테이너에서 0으로 접힌다"는 레이아웃 함정은 그대로 유효한 교훈이라, 캘린더의 날짜 셀도 같은
> 이유로 `onLayout` 측정 + 픽셀 단위 `width`/`height` 지정 방식을 그대로 재사용한다.

`MonthCalendar`는 자체 상태(`viewedYear`, `viewedMonth`, 0-indexed)로 현재 보고 있는 달을 들고, 이전/다음 달 버튼이 그 상태를 바꾼다. 다음 달 버튼은 `viewedYear/viewedMonth`가 오늘이 속한 달과 같으면 비활성화된다(요구사항 6, 미래로 이동 불가).

```ts
type DayCell = { key: string; day: number } | null;

function buildMonthWeeks(year: number, month: number): DayCell[][] {
  const firstOfMonth = new Date(year, month, 1);
  const startDow = firstOfMonth.getDay(); // 0=일 ... 6=토, 그 달 1일 앞을 이만큼 비운다
  const daysInMonth = new Date(year, month + 1, 0).getDate();

  const cells: DayCell[] = [];
  for (let i = 0; i < startDow; i++) cells.push(null);
  for (let day = 1; day <= daysInMonth; day++) {
    cells.push({ key: `${year}-${pad(month + 1)}-${pad(day)}`, day });
  }
  while (cells.length % 7 !== 0) cells.push(null); // 마지막 주도 7칸으로 채움

  const weeks: DayCell[][] = [];
  for (let i = 0; i < cells.length; i += 7) weeks.push(cells.slice(i, i + 7));
  return weeks;
}
```

월 제목(예: "2026년 8월", "August 2026")은 4개 언어 각각에 문자열을 새로 추가하는 대신 `Intl.DateTimeFormat(SPEECH_LOCALE[language], { year: 'numeric', month: 'long' })`로 만든다 — 이미 `speechLocale.ts`에 있는 언어→로케일 태그 매핑(`ko-KR`/`en-US`/`ja-JP`/`zh-CN`)을 재사용하면 각 언어의 표준 표기를 별도 번역 문자열 없이 정확히 얻을 수 있다.

날짜 셀: 기록이 있는 날짜(`recordedDates.has(cell.key)`)엔 숫자 아래 작은 점을 그린다(요구사항 4). 오늘 날짜(`cell.key === todayKey`)엔 숫자를 감싸는 원형 테두리를 그린다(요구사항 5) — 점과 테두리는 서로 다른 시각 신호라 동시에 있어도 겹쳐 보이지 않는다. 날짜 셀에 탭 인터랙션은 없다(제외 범위와 일치). 각 셀은 `accessibilityLabel`로 날짜·기록 여부·오늘 여부를 함께 노출한다.

캘린더 아래에 점 하나 + `t.activity.recordedDayLegend`("운동한 날") 한 줄만 붙인다 — 일반 달력은 그 자체로 이미 익숙한 형태라 히트맵처럼 별도의 "빈칸/채운칸" 범례 두 줄이 필요 없고, 점의 의미만 확인시켜주면 충분하다.

## 의존성

새로 추가하는 패키지는 없다. 날짜 계산은 순수 JS `Date`만 쓰고, 월 이름·연도 표기는 JS 내장 `Intl.DateTimeFormat`으로 해결한다(새 번역 문자열 불필요). 그리드는 기존 `View`/`StyleSheet` + `onLayout` 측정으로 충분하다.

## 구현 순서

1. `src/lib/stats.ts`의 순수 함수(`localDateKey`, `daysBetweenKeys`, `addDaysToKey`, `computeStreak`, `findPrEventDateKeys`)부터 작성하고 `stats.test.ts`로 단위 테스트를 붙인다 — AsyncStorage 없이 날짜 산술만 검증할 수 있어 가장 빠르게 정확성을 확인할 수 있는 단계다. (스트릭 리셋 경계, 8주 그리드 시작점, PR 이벤트 판정 등)
2. `getHomeStats()`를 완성해 `getRecords`/`getRepsRecords`/`getExercises`와 연결하고, 임시로 콘솔 로그나 QA용 화면에서 실제 저장된 기록으로 값을 확인한다.
3. `MonthCalendar.tsx`를 독립 컴포넌트로 만들어 임의의 `Set<string>`을 넘겨 그리드가 올바른 요일에 정렬되는지, 이전/다음 달 이동이 되는지 확인한다.
4. `StreakBadge.tsx`를 만들고, `WeeklySummaryCard.tsx`에서 두 지표 텍스트만 조립한다(빈 상태 분기 포함).
5. `HomeScreen.tsx`에 `homeStats` 상태와 `WeeklySummaryCard` 렌더링, 운동 카드별 `StreakBadge`를 배선한다.
6. `ActivityScreen.tsx`를 만들어 같은 두 지표 + `MonthCalendar`를 보여주고, `App.tsx`의 `Screen` 유니언·렌더링·`HomeScreen`으로의 `onOpenActivity` 콜백을 배선한다.
7. i18n 4개 언어 파일에 새 문구 키를 추가한다.
8. 실기기/에뮬레이터에서 실제 기록을 쌓아가며(어제 기록 남기기 → 오늘 확인 등) 스트릭·캘린더 점 표시·요약 수치와 홈↔활동 기록 화면 전환, 월 이동을 눈으로 검증한다.

| 스펙 요구사항 | 설계 대응 |
|---|---|
