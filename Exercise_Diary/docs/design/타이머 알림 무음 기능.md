# 타이머 알림 무음 기능 — 설계

## 화면 구조

새 화면·새 컴포넌트는 만들지 않는다. 기존 `src/screens/TimerScreen.tsx`의 idle phase 설정 카드(`styles.settings` — 지금 "준비 카운트다운"·"벨 간격" `NumberStepper` 두 개가 들어있는 카드)에 토글 행을 하나 추가한다.

```
설정 카드
├─ NumberStepper (준비 카운트다운)
├─ NumberStepper (벨 간격)
└─ (신규) 음성 안내 토글 행 ← 추가 위치
```

- 토글은 React Native 기본 `Switch`를 그대로 쓴다. `AddExerciseScreen.tsx`의 "무게 기록 사용" 행(라벨 `Text` + `Switch`, `trackColor={{ true: accent.primary, false: accent.border }}`)과 완전히 같은 패턴이라 그대로 복사해 쓴다 — 새 컴포넌트로 추출하지 않는다(쓰이는 곳이 한 곳뿐이라 추상화가 과함).
- 새 스타일 `voiceGuideRow`는 `AddExerciseScreen.tsx`의 `weightRow`(`flexDirection: 'row', alignItems: 'center', justifyContent: 'space-between'`)를 그대로 `TimerScreen.tsx`의 `StyleSheet.create` 블록에 추가한다.

## 상태 설계

- `TimerScreen` 로컬 state에 `voiceGuideEnabled: boolean`을 추가한다. 초깃값은 `true`(저장값을 불러오기 전에도 기존 동작과 동일하게 보이도록).
- 컴포넌트 마운트 시 1회, `exercise.id`와 무관한 `useEffect(() => { getVoiceGuideEnabled().then(setVoiceGuideEnabledState); }, [])`로 저장된 값을 불러온다. 기존 `settings`(카운트다운·벨 간격)를 불러오는 `useEffect`는 `[exercise.id]`에 의존하지만, 이 값은 운동과 무관한 전역 값이므로 의존성 배열을 비워 마운트 시 한 번만 읽는다.
- **전역 Context를 새로 만들지 않는다.** 이 값을 읽는 곳은 `TimerScreen` 한 곳뿐이고(스펙 제외 범위: 다른 화면에서 참조하거나 측정 중 실시간 전환하는 기능 없음), `ExerciseScreen.tsx`의 기존 주석에 명시된 대로 `TimerScreen`은 탭 전환(측정↔기록)이나 phase 전환마다 마운트가 풀렸다 다시 붙는다. 즉 다른 운동을 열거나 화면을 재진입할 때마다 자연히 storage에서 새로 읽으므로, `ThemeContext`처럼 여러 화면이 동시에 구독해야 하는 상황이 아니다. Context를 추가하면 이번 범위엔 과설계다.
- 토글 변경 핸들러는 `ThemeContext.setPresetId`와 같은 낙관적 업데이트 패턴을 쓴다: state를 즉시 바꿔 화면에 반영하고, 저장은 백그라운드로 실행하며 실패해도 사용자에게 별도로 알리지 않는다(기존 코드에 없는 에러 처리를 새로 만들지 않는다).

```ts
const [voiceGuideEnabled, setVoiceGuideEnabledState] = useState(true);

useEffect(() => {
  getVoiceGuideEnabled().then(setVoiceGuideEnabledState);
}, []);

const handleVoiceGuideToggle = (value: boolean) => {
  setVoiceGuideEnabledState(value); // 화면엔 즉시 반영
  setVoiceGuideEnabled(value); // 저장은 백그라운드
};
```

## 데이터 모델

`src/lib/storage.ts`에 테마 프리셋과 동일한 패턴(단순 덮어쓰기, `enqueueWrite` 불필요)으로 전역 키를 추가한다.

```ts
const VOICE_GUIDE_KEY = 'timecheck:voiceGuide:v1';

export async function getVoiceGuideEnabled(): Promise<boolean> {
  return readJson<boolean>(VOICE_GUIDE_KEY, true); // 기본값 true → 최초 설치 시 켜짐(요구사항 6)
}

export function setVoiceGuideEnabled(enabled: boolean): Promise<void> {
  return AsyncStorage.setItem(VOICE_GUIDE_KEY, JSON.stringify(enabled));
}
```

- `types.ts`의 `Settings` 타입에는 넣지 않는다. `Settings`는 운동별(`settingsKey(exerciseId)`)로 저장되는 값이고, 이 토글은 운동과 무관한 앱 전체 공통 값이라 저장 범위 자체가 다르다(요구사항 4) — 같은 타입에 섞으면 "운동별 설정처럼 보이는" 착오를 유발한다.
- 번역 키: `src/lib/i18n/locales/en.ts`의 `timer` 섹션에 `voiceGuideLabel: string`을 추가한다. `Translations` 타입이 `typeof en`으로 파생되고 `ko.ts`/`ja.ts`/`zh.ts`는 각각 `: Translations`로 선언돼 있으므로, 세 파일에 값을 채우지 않으면 `npx tsc --noEmit`이 즉시 실패한다 — 컴파일러가 "4개 언어 모두 번역"(요구사항 8)을 강제한다.

## 핵심 로직

`TimerScreen`이 `useHangTimer`에 넘기는 콜백 3곳에서만 분기하고, `useHangTimer.ts`·`feedback.ts`는 손대지 않는다 — 타이머 훅은 "몇 초째인지"만 알려주고, 그 초에 실제로 말할지는 화면(TimerScreen)이 결정하는 기존 관심사 분리를 그대로 따른다.

```ts
const timer = useHangTimer({
  onCountdownSecond: (remainingSec) => {
    if (voiceGuideEnabled) speakCountdown(remainingSec, language);
  },
  onMeasureStart: () => {
    if (voiceGuideEnabled) speakStart(language, t.timer.speechStart);
  },
  onMeasureSecond: (second) => {
    if (second % settings.bellIntervalSeconds === 0) {
      playBellSound(); // 토글과 무관하게 항상 울림 (요구사항 3)
    } else if (voiceGuideEnabled) {
      speakSecond(second, language); // 꺼져 있으면 아무 것도 하지 않음 — 무음
    }
  },
});
```

- 벨 간격에 해당하는 초는 토글 상태와 상관없이 `playBellSound()`가 항상 실행되도록 `if/else` 순서를 유지한다(벨 우선, 그 다음에만 음성 여부 판단).
- 화면 렌더링 쪽(경과 시간, 동기부여 문구, 정지 버튼 등)은 이 로직과 완전히 분리되어 있어 건드릴 필요가 없다(요구사항 7).
- 측정이 시작되면 idle phase(설정 카드)가 언마운트되므로, 자연히 측정 도중에는 토글을 조작할 UI 자체가 없다(요구사항: 측정 전 설정 카드에서만 변경 가능 — 별도 가드 코드 불필요, 기존 phase 분기 구조가 이미 보장).

## 의존성

새로 추가하는 패키지는 없다. `AsyncStorage`(이미 사용 중), `react-native`의 `Switch`(이미 `AddExerciseScreen.tsx`에서 사용 중), `expo-speech` 기반 `feedback.ts`(기존 함수 그대로 재사용)만으로 구현된다.

## 구현 순서

1. `src/lib/storage.ts`에 `getVoiceGuideEnabled`/`setVoiceGuideEnabled` 추가.
2. `en.ts`의 `timer`에 `voiceGuideLabel` 키를 추가하고 `npx tsc --noEmit`을 돌려 `ko.ts`/`ja.ts`/`zh.ts`에서 타입 에러가 나는지 확인 → 세 파일에 번역 값을 채워 에러를 없앤다.
3. `TimerScreen.tsx`에 `voiceGuideEnabled` state와 마운트 시 로딩 `useEffect`를 추가하고, 설정 카드에 `Switch` 행(라벨 + 토글)을 추가한다. 이 시점엔 아직 값 저장·TTS 연동 없이 화면에 토글이 보이고 눌리는지만 확인한다.
4. 토글 `onValueChange`에 `handleVoiceGuideToggle`(state 갱신 + `setVoiceGuideEnabled` 저장)을 연결하고, 앱을 재시작해 마지막 상태가 유지되는지 확인한다.
5. `useHangTimer` 콜백 3곳(`onCountdownSecond`, `onMeasureStart`, `onMeasureSecond`)에 `voiceGuideEnabled` 분기를 추가한다. 토글을 켠 채 측정해 기존과 동일하게 들리는지, 끈 채 측정해 카운트다운·"시작"·매초 숫자 읽기는 안 들리고 벨소리만 들리는지 확인한다.
6. 다른 운동의 측정 화면을 열어도 같은 토글 상태가 보이는지, 측정↔기록 탭을 오간 뒤에도 유지되는지 확인한다.
7. `npx tsc --noEmit` 최종 통과 확인.

## 스펙 요구사항 대응

| 스펙 요구사항 | 설계 대응 |
|---|---|
| 1. 설정 카드에 음성 안내 토글 추가 | 화면 구조 — `styles.settings` 카드에 `Switch` 행 추가 |
| 2. 토글 끄면 3가지 TTS 억제 | 핵심 로직 — 콜백 3곳에 `if (voiceGuideEnabled)` 분기 |
| 3. 벨소리는 토글과 무관하게 유지 | 핵심 로직 — `onMeasureSecond`에서 `playBellSound()`는 조건 밖 |
| 4. 앱 전체 공통 설정 | 데이터 모델 — 운동 ID 없는 전역 키 `timecheck:voiceGuide:v1`; 상태 설계 — Context 없이도 마운트마다 재로딩으로 전역처럼 동작 |
| 5. 재시작해도 유지 | 데이터 모델 — `AsyncStorage`에 저장 |
| 6. 최초 설치 시 기본값 켜짐 | 데이터 모델 — `getVoiceGuideEnabled` 기본값 `true` |
| 7. 무음 시에도 시각 요소 불변 | 핵심 로직 — 변경 범위가 TTS 호출부와 토글 행 하나로 한정, 기존 렌더링 트리 불변 |
| 8. 4개 언어 번역 | 데이터 모델 — `Translations` 타입이 `en.ts` 기준으로 파생되어 누락 시 타입 에러 |
