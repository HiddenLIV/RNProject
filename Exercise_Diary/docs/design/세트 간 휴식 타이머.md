# 세트 간 휴식 타이머 — 설계

## 화면 구조

새 화면은 없다. 기존 `RepsScreen`(횟수·세트형 운동 측정 화면) 하나에 통합한다.

| 위치 | 역할 |
|---|---|
| `src/screens/RepsScreen.tsx` (수정) | 휴식 설정(스테퍼+토글) ↔ 휴식 진행 배너를 같은 자리에서 상태에 따라 교체 렌더링. 세트 추가 시 휴식 시작, 저장/입력/촬영은 항상 그대로 조작 가능하도록 배치를 건드리지 않는다. |
| `src/components/RestTimerBanner.tsx` (신규) | 휴식 중에만 보이는 카드: 남은 초 표시 + "건너뛰기" 버튼. `TimeDisplay`처럼 숫자만 보여주는 표시 전용 컴포넌트가 아니라 액션(건너뛰기)이 있어 별도 컴포넌트로 분리한다. |
| `src/lib/useRestTimer.ts` (신규) | 휴식 카운트다운의 순수 타이밍 로직(런타임 상태) — `useHangTimer`와 같은 패턴(Date.now() 기준, ref로 종료 시각 보관)이지만 phase가 idle/resting 둘뿐이라 훨씬 단순하다. |

휴식 설정(스테퍼+토글)은 새 컴포넌트를 만들지 않는다. `TimerScreen`이 이미 `NumberStepper` + `Switch`로 카운트다운·벨 간격·음성 안내를 나란히 배치한 것과 동일한 방식으로 `RepsScreen`에 인라인으로 둔다 — 재사용 가능한 두 프리미티브(NumberStepper, Switch)를 그대로 쓰면 되므로 래퍼 컴포넌트가 필요 없다.

## 상태 설계

| 상태 | 위치 | 수명 |
|---|---|---|
| `settings.restSeconds`, `settings.restEnabled` | `useTimerSettings(exercise.id)` (기존 훅 재사용, 반환 필드가 새로 늘어남) → AsyncStorage(`timecheck:settings:${exerciseId}:v1`) | 영구 저장, 운동별 |
| `rest.phase` (`'idle' \| 'resting'`), `rest.remainingSec` | `useRestTimer()` — RepsScreen 로컬 | 화면에 머무는 동안만(런타임), 저장 안 함 |

`RepsScreen`은 이미 `useState`로 화면 로컬 상태(`currentReps`, `loggedSets` 등)를 직접 관리하는 화면이라, 이번에도 Context를 새로 만들지 않고 같은 방식(로컬 훅 조합)을 따른다.

`settings`는 `TimerScreen`이 시간형 운동에 쓰는 것과 완전히 같은 저장소(`Settings` 타입, `getSettings`/`saveSettings`)를 그대로 쓴다. `useTimerSettings`가 이미 "운동별로 불러오고, 바뀌면 즉시 저장"하는 로직을 갖고 있으므로 `RepsScreen`에서도 그대로 호출해 `settings`/`updateSettings`만 꺼내 쓴다 (그 훅이 함께 반환하는 `voiceGuideEnabled`/`onVoiceGuideToggle`은 reps 화면에서 쓰지 않으므로 구조 분해 시 생략한다).

## 데이터 모델

`src/lib/types.ts`의 `Settings`를 확장한다 (기존 필드는 시간형 운동 전용이었지만, 운동별로 저장되는 범용 설정 저장소이므로 횟수형 운동의 휴식 설정도 같은 타입에 얹는다):

```ts
export type Settings = {
  countdownSeconds: number;
  bellIntervalSeconds: number;
  restSeconds: number;    // 신규 — 세트 간 휴식 시간(초)
  restEnabled: boolean;   // 신규 — 휴식 타이머 켜기/끄기
};

export const DEFAULT_SETTINGS: Settings = {
  countdownSeconds: 5,
  bellIntervalSeconds: 10,
  restSeconds: 60,
  restEnabled: true,
};

export const REST_SECONDS_MIN = 10;
export const REST_SECONDS_MAX = 300;
export const REST_SECONDS_STEP = 10;
```

`RepsRecord`는 건드리지 않는다 (스펙 제외 범위 — 실제 휴식 시간은 기록에 남기지 않는다).

**마이그레이션 불필요**: `storage.ts`의 `getSettings()`는 이미 `{ ...DEFAULT_SETTINGS, ...raw }`로 병합해 반환하므로, 새 필드가 없는 기존 저장값(시간형 운동에 저장된 옛 설정)도 자동으로 `restSeconds: 60, restEnabled: true`를 채워 받는다. `backup.ts`의 `isBackupExerciseDataShape`도 `countdownSeconds`/`bellIntervalSeconds` 두 필드만 검증하고 나머지는 그대로 통과시키므로, 옛 백업 파일 복원도 새 백업 내보내기도 별도 처리 없이 그대로 동작한다. `BACKUP_SCHEMA_VERSION`을 올릴 필요가 없다 (기존 `colorSchemeOverride` 추가 때와 같은 패턴).

## 핵심 로직

### `useRestTimer` — 카운트다운 + "뒤늦은 알림 금지"

```ts
export type RestPhase = 'idle' | 'resting';

export function useRestTimer(onFinish: () => void) {
  const [phase, setPhase] = useState<RestPhase>('idle');
  const [remainingSec, setRemainingSec] = useState(0);
  const endsAtRef = useRef(0);
  const intervalRef = useRef<ReturnType<typeof setInterval> | null>(null);
  const onFinishRef = useRef(onFinish);
  onFinishRef.current = onFinish;

  const clearTick = () => {
    if (intervalRef.current != null) {
      clearInterval(intervalRef.current);
      intervalRef.current = null;
    }
  };

  // silent=true: 이미 지난 뒤에야 발견된 종료(백그라운드 복귀) — 소리/진동 없이 조용히 idle로.
  const finish = (silent: boolean) => {
    clearTick();
    setPhase('idle');
    setRemainingSec(0);
    if (!silent) onFinishRef.current();
  };

  const tick = () => {
    const remainMs = endsAtRef.current - Date.now();
    if (remainMs <= 0) {
      finish(false); // 화면을 보고 있는 동안 정상적으로 0에 도달 → 벨+진동 울림
      return;
    }
    setRemainingSec(Math.ceil(remainMs / 1000));
  };

  const start = (durationSec: number) => {
    endsAtRef.current = Date.now() + durationSec * 1000;
    setRemainingSec(durationSec);
    setPhase('resting');
    clearTick();
    intervalRef.current = setInterval(tick, 250); // 초 단위 표시라 useHangTimer(33ms)보다 성기게
  };

  const skip = () => finish(true); // 사용자가 직접 끝냄 — 벨/진동 불필요

  // 백그라운드에서 돌아왔을 때 이미 끝나 있었는지 즉시 확인 — setInterval은 백그라운드 중
  // 사실상 멈춰 있다가 포그라운드 복귀 시 몰아서 한 번 발생하므로, 그 첫 tick이 아니라
  // AppState 전환 시점에 직접 검사해 finish(false)가 뒤늦게 벨을 울리는 경우를 막는다.
  useEffect(() => {
    const sub = AppState.addEventListener('change', (state) => {
      if (state === 'active' && phaseRefIsResting() && endsAtRef.current <= Date.now()) {
        finish(true);
      }
    });
    return () => sub.remove();
  }, []);

  useEffect(() => clearTick, []);

  return { phase, remainingSec, start, skip };
}
```

(`phaseRefIsResting()`은 stale closure를 피하려고 `phase`를 ref로도 미러링해 검사하는 자리표시자 — 실제 구현 시 `useHangTimer`가 이미 쓰는 "state + ref 동시 보관" 패턴을 그대로 따른다.)

- **요구사항 6 (Date.now() 기준)** — `endsAtRef`는 시작 시각이 아니라 "종료 시각"을 저장하고 매 tick마다 `endsAtRef - Date.now()`로 남은 시간을 계산한다. `useHangTimer`의 카운트다운 phase와 동일한 방식.
- **요구사항 13 (뒤늦은 알림 금지)** — 위 AppState 리스너가 핵심. 일반 tick 종료(`finish(false)`)와 백그라운드 복귀 후 발견된 종료(`finish(true)`)를 구분해, 후자만 소리 콜백을 억제한다.

### RepsScreen에서의 연결

```ts
const { settings, updateSettings } = useTimerSettings(exercise.id);
const timerAudio = useTimerAudio();
const rest = useRestTimer(() => {
  timerAudio.playBellSound();
  notifySuccess();
});
useKeepAwakeWhileActive(rest.phase === 'resting');

const addSet = () => {
  // ...기존 유효성 검사·tapMedium()·setLoggedSets 그대로...
  if (settings.restEnabled) rest.start(settings.restSeconds);
};

const handleSkipRest = () => {
  tapLight();
  rest.skip();
};
```

- **요구사항 3·4 (켜짐/꺼짐에 따라 자동 시작 여부)** — `addSet()` 맨 끝에 `if (settings.restEnabled)` 한 줄로 분기.
- **요구사항 8 (벨+진동)** — `useRestTimer`에 넘기는 `onFinish` 콜백에서 기존 `useTimerAudio().playBellSound()`(벨 사운드 재사용)와 `notifySuccess()`(저장 완료 때와 같은 진동 패턴, `haptics.ts`에 이미 있음)를 그대로 호출. 새 사운드 에셋이나 새 haptic 함수가 필요 없다.
- **요구사항 9 (자동으로 다음 세트 입력 상태 복귀)** — 별도 로직이 필요 없다. `RestTimerBanner`는 `rest.phase === 'resting'`일 때만 렌더링되므로, `finish()`가 `phase`를 `'idle'`로 바꾸는 순간 UI가 자동으로 원래의 무게·횟수 입력 뷰로 돌아간다.
- **요구사항 10 (휴식 중에도 저장/입력/촬영 가능)** — `RestTimerBanner`는 "이번 세트" 입력 영역 위에 별도 카드로만 추가되고, 기존 입력·저장·촬영 버튼의 `disabled`/렌더 조건은 전혀 건드리지 않는다.
- **요구사항 11 (세트 삭제가 휴식에 영향 없음)** — `removeLoggedSet()`은 `rest`를 참조하지 않으므로 자연히 만족.
- **요구사항 14 (자동 잠금 방지)** — `useKeepAwakeWhileActive(rest.phase === 'resting')` 한 줄로 기존 훅 재사용.

## 의존성

새 패키지는 추가하지 않는다.

- `AppState` — `react-native` 기본 제공 (이미 프로젝트 의존성에 포함된 `react-native` 패키지의 일부, 새 설치 불필요).
- 벨 사운드 — 기존 `assets/sounds/bell.wav` 재사용 (`useTimerAudio`가 이미 로드).
- 진동 — 기존 `expo-haptics` 래퍼(`src/lib/haptics.ts`) 재사용.
- 화면 잠금 방지 — 기존 `expo-keep-awake` 래퍼(`useKeepAwakeWhileActive`) 재사용.

## 구현 순서

각 단계가 끝날 때마다 실제 기기/시뮬레이터에서 눈으로 확인 가능하도록 나눈다.

1. **데이터 모델**: `types.ts`에 `restSeconds`/`restEnabled`/`REST_SECONDS_*` 추가. `npx tsc --noEmit`으로 기존 코드(TimerScreen 등)가 깨지지 않는지 확인.
2. **설정 UI만 우선 연결**: `RepsScreen`에 `useTimerSettings` 연결 + 스테퍼(10~300초, 10단위)·토글을 인라인으로 배치. 이 시점에는 아직 타이머가 안 뜨므로, "값을 바꾸고 화면을 나갔다 들어와도 유지되는지"만 눈으로 확인.
3. **`useRestTimer` 훅 작성** (AppState 처리 전, 기본 카운트다운만): idle→resting→idle 전환과 초 감소가 콘솔 로그나 임시 텍스트로 잘 도는지 단독 확인.
4. **`RestTimerBanner` 컴포넌트 + `addSet()` 연결**: 세트를 추가하면 배너가 뜨고 초가 줄어들다가 0에서 사라지는지, 건너뛰기 버튼이 즉시 종료시키는지 확인.
5. **벨+진동 연결**: `onFinish` 콜백에 `playBellSound`/`notifySuccess` 연결, 건너뛰기 시에는 소리가 안 나는지 확인.
6. **keep-awake 연결**: 휴식 중 화면 자동 잠금이 안 되는지 확인 (설정 앱의 화면 자동 잠금 시간을 짧게 해두고 테스트).
7. **AppState 백그라운드 처리**: 휴식을 시작한 뒤 앱을 백그라운드로 보냈다가 휴식 시간이 다 지난 후 복귀 — 벨 없이 조용히 idle로 돌아오는지 확인. 휴식 시간이 남은 채로 복귀하는 경우도 함께 확인(정상적으로 이어서 카운트).
8. **i18n**: `en.ts` → `ko/ja/zh.ts` 순으로 `reps.rest*` 키 추가.
9. **최종 점검**: `npx tsc --noEmit`, `npm run lint` (변경 파일만).

## 스펙 요구사항 ↔ 설계 대응표

| 스펙 요구사항 | 설계에서 충족되는 위치 |
|---|---|
| 1. 휴식 시간 스테퍼(10~300초, 10단위, 기본 60초) | `REST_SECONDS_MIN/MAX/STEP` + `NumberStepper` (RepsScreen 인라인) |
| 2. 켜기/끄기 토글(기본 켜짐) | `settings.restEnabled` + `Switch` (RepsScreen 인라인) |
| 3. 켜짐 상태에서 세트 추가 시 자동 시작 | `addSet()` 끝의 `if (settings.restEnabled) rest.start(...)` |
| 4. 꺼짐 상태에서는 시작 안 함 | 위와 동일 분기의 else 경로(아무 것도 안 함) |
| 5. 남은 시간 초 단위 표시 | `RestTimerBanner`가 `rest.remainingSec` 렌더링 |
| 6. Date.now() 기준 경과 계산 | `useRestTimer`의 `endsAtRef` 방식 |
| 7. 건너뛰기 버튼 | `RestTimerBanner`의 skip 버튼 → `rest.skip()` |
| 8. 벨+진동 알림 | `onFinish` 콜백의 `playBellSound()` + `notifySuccess()` |
| 9. 종료 후 자동으로 다음 세트 입력 상태 | `rest.phase`가 `'idle'`로 바뀌면 배너가 자동으로 사라짐 |
| 10. 휴식 중에도 저장/입력/촬영 가능 | 기존 UI 요소의 조건부 렌더/disabled를 변경하지 않음 |
| 11. 세트 삭제가 휴식에 영향 없음 | `removeLoggedSet()`이 `rest` 상태를 참조하지 않음 |
| 12. 운동별 설정 저장·유지 | `useTimerSettings(exercise.id)` → 기존 `settingsKey(exerciseId)` 저장소 |
| 13. 백그라운드 복귀 시 뒤늦은 알림 없음 | `useRestTimer`의 `AppState` 리스너 + `finish(silent)` 구분 |
| 14. 휴식 중 화면 자동 잠금 방지 | `useKeepAwakeWhileActive(rest.phase === 'resting')` |
| 15. 4개 언어 번역 | `en/ko/ja/zh.ts`에 `reps.rest*` 키 추가 |
