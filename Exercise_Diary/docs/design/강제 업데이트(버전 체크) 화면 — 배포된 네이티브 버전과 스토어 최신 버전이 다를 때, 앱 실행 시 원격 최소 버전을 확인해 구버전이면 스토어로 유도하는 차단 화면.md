# 업데이트 안내 바텀시트(버전 체크) — 설계

> 2026-08-14 갱신: 전체 화면 차단(닫기 불가) → 스킵 가능한 바텀시트로 UI·상호작용을 변경. 아래 내용은 갱신된 스펙에 맞춰 다시 작성됨.

## 알려진 제약(의도적으로 보류)

`checkForceUpdate()`의 네트워크 응답을 기다리는 동안(최대 4초) 사용자가 `HomeScreen`의 도움말·백업·운동 수정·카메라 권한 모달을 먼저 열면, iOS에서는 이미 present된 Modal 위에 `ForceUpdateModal`을 또 present하는 것이 조용히 실패한다(RN Modal의 알려진 제약 — `AlertHost`의 `embedded` 패턴이 같은 문제를 우회하기 위해 존재). 이 경우 그 세션에서는 안내가 보이지 않고 다음 콜드 스타트에 다시 시도된다. 발생 확률이 낮고(콜드 스타트 직후 몇 초 안에 다른 모달을 먼저 열어야 함) 결과도 "이번엔 못 봄" 수준이라, 전역 모달 조율 장치를 새로 만드는 더 큰 리팩터는 지금은 보류한다.

## 화면 구조

새 화면(전체 네비게이션 스크린)은 만들지 않는다. 기존 `AlertHost`/`CameraPermissionModal`처럼 **App 최상단에 항상 마운트되어 있다가 조건이 맞을 때만 내용을 보여주는 오버레이 모달** 방식을 그대로 따르되, 화면 형태는 `HelpModal.tsx`류의 풀스크린이 아니라 **하단에서 올라오는 바텀시트**다.

- `src/lib/forceUpdate.ts` — 원격 버전 조회, 버전 비교, 표시 여부 판단(순수 로직, UI 없음)
- `src/components/ForceUpdateModal.tsx` — 바텀시트 UI. `Modal transparent` + 반투명 백드롭(뒷화면이 어둡게 비침) + 화면 하단에 붙는 카드. 아이콘 배지는 우측 상단, 제목·본문은 좌측 정렬, 하단에 "나중에"/"업데이트하기" 버튼이 나란히 있다.
- `App.tsx` — 콜드 스타트 시 `checkForceUpdate()`를 1회 호출해 결과를 상태로 들고, `ForceUpdateModal`을 최상단에 렌더링한다. "나중에"·뒤로가기 모두 같은 닫기 핸들러로 연결한다.

```
App.tsx
├─ useEffect(() => { checkForceUpdate() ... }, [])   // 콜드 스타트 1회
├─ BackHandler: 바텀시트 떠 있으면 닫기(= "나중에"와 동일 동작)
├─ (기존 화면 트리: HomeScreen / ExerciseScreen / AddExerciseScreen)
├─ <AlertHost />
└─ <ForceUpdateModal visible={visible} storeUrl={storeUrl} onDismiss={...} />   // 항상 마지막에 두어 다른 모달보다 위에 뜨게 함
```

### 레이아웃 (참고 이미지 반영)

```
┌──────────────────────────────┐
│  (반투명 백드롭 — 기존 화면 비침)   │
│                                │
╭──────────────────────────────╮ ← 상단만 둥근 모서리
│  업데이트가 필요해요      (아이콘) │
│  더 안정적인 사용을 위해           │
│  최신 버전으로 업데이트해야 해요    │
│                                │
│ ┌───────────┐ ┌──────────────┐ │
│ │   나중에   │ │   업데이트하기  │ │
│ └───────────┘ └──────────────┘ │
╰──────────────────────────────╯
```

## 상태 설계

- `App.tsx`(`AppContent`)에 로컬 state 하나만 추가한다: `const [forceUpdateStoreUrl, setForceUpdateStoreUrl] = useState<string | null>(null);`
  - `null` = 아직 체크 전이거나 표시 불필요, 또는 사용자가 "나중에"로 닫음 → 평소대로 진행
  - 문자열(스토어 URL) = 표시 필요 → `ForceUpdateModal`이 뜨고 "업데이트하기"가 그 URL로 연결됨
- "나중에" 선택 이력은 어디에도 저장하지 않는다(AsyncStorage 없음) — 스펙 제외 범위대로 매 콜드 스타트마다 새로 체크한다.
- `forceUpdate.ts`는 상태를 갖지 않는 순수 함수 모음이다(테스트·재사용이 쉽도록).

## 데이터 모델

`src/lib/forceUpdate.ts`에 정의(기존과 동일, 변경 없음):

```ts
type PlatformVersionInfo = {
  minVersion: string; // "1.2.3" 형식
  storeUrl: string;
};

type RemoteVersionConfig = {
  ios: PlatformVersionInfo;
  android: PlatformVersionInfo;
};

export type ForceUpdateResult =
  | { blocked: false }
  | { blocked: true; storeUrl: string };
```

원격 `version.json`(gh-pages 루트, `https://hiddenliv.github.io/RNProject/version.json`)도 동일한 형태이며 이미 배포되어 있다:

```json
{
  "ios": { "minVersion": "1.0.0", "storeUrl": "https://apps.apple.com/app/id0000000000" },
  "android": { "minVersion": "1.0.0", "storeUrl": "https://play.google.com/store/apps/details?id=com.hiddenlab.hiddenreps" }
}
```

이 JSON은 `docs/privacy-policy.html`과 같은 방식으로 관리한다 — 저장소에는 `docs/version.json`을 원본으로 두고, 배포 시(수동으로) `gh-pages` 브랜치의 루트에 `version.json`으로 복사해 커밋·푸시한다.

## 핵심 로직

`src/lib/forceUpdate.ts` — 판단 로직 자체는 이전과 동일하되, QA에서 발견된 검증 허점을 하나 막는다.

1. **버전 비교** — 문자열 사전순 비교는 `"1.9.0" > "1.10.0"`으로 잘못 판단하므로, 점(.)으로 분리해 세그먼트를 숫자로 비교한다(기존과 동일, 변경 없음).

2. **현재 앱 버전** — `Constants.expoConfig?.version`. 값이 없으면 비교 없이 통과.

3. **원격 설정 조회** — `fetch`에 4초 타임아웃(`AbortController`)을 걸고, 실패·타임아웃·JSON 파싱 실패·필수 필드 누락 중 하나라도 해당하면 `null`을 반환한다. **QA 지적 반영**: `storeUrl`이 빈 문자열이면 검증을 통과시키되 이후 `App.tsx`의 `!!storeUrl`이 `false`가 되어 표시가 조용히 무력화되는 문제가 있었다 — `isValidPlatformInfo`에서 `storeUrl.trim().length > 0`까지 확인하도록 강화한다.

   ```ts
   function isValidPlatformInfo(value: unknown): value is PlatformVersionInfo {
     if (!value || typeof value !== 'object') return false;
     const info = value as Record<string, unknown>;
     return (
       typeof info.minVersion === 'string' &&
       typeof info.storeUrl === 'string' &&
       info.storeUrl.trim().length > 0
     );
   }
   ```

4. **판단 진입점** — 기존과 동일한 `checkForceUpdate()`.

5. **App.tsx 연동**

   ```ts
   useEffect(() => {
     setAudioModeAsync({ playsInSilentMode: true, interruptionMode: 'doNotMix' });
     initializeAds();
     checkForceUpdate()
       .then((result) => {
         if (result.blocked) setForceUpdateStoreUrl(result.storeUrl);
       })
       .catch(() => {});
   }, []);

   const dismissForceUpdate = () => setForceUpdateStoreUrl(null);
   ```

   하드웨어 뒤로가기 핸들러는 바텀시트가 떠 있으면 "나중에"와 동일하게 닫기만 하고, 화면 전환 로직은 실행하지 않는다:

   ```ts
   useEffect(() => {
     const sub = BackHandler.addEventListener('hardwareBackPress', () => {
       if (forceUpdateStoreUrl) {
         dismissForceUpdate();
         return true;
       }
       if (screen.name !== 'home') {
         setScreen({ name: 'home' });
         return true;
       }
       return false;
     });
     return () => sub.remove();
   }, [screen, forceUpdateStoreUrl]);
   ```

`ForceUpdateModal.tsx`:
- `visible`이 `true`일 때만 `Modal`을 그린다(`transparent`, `animationType="slide"`, `onRequestClose={onDismiss}`).
- 백드롭은 `rgba(0,0,0,0.4)` 반투명이라 뒤 화면이 비쳐 보인다. 바텀시트 카드는 화면 하단에 붙고 상단 모서리만 둥글다.
- 백드롭을 탭해도 "나중에"와 동일하게 닫힌다(바텀시트의 일반적인 관례).
- 우측 상단에 실제 앱 런처 아이콘(`assets/icon.png`)을 둥근 정사각형으로 표시한다(generic 아이콘 대신 브랜드 인지도를 살림). 제목·본문(좌측 정렬), "나중에"(보조 버튼, `onDismiss`) / "업데이트하기"(주 버튼, `Linking.openURL(storeUrl)`) 두 버튼을 가로로 배치한다.
- **QA 지적 반영**: `Linking.openURL(storeUrl)` 실패(unhandled rejection) 방지를 위해 `.catch(() => {})`를 붙인다 — 실패해도 사용자는 여전히 "나중에"로 빠져나갈 수 있으므로 별도 에러 UI는 필요 없다.

## 의존성

새로 추가하는 패키지는 없다(이전과 동일).

- `expo-constants` — 현재 앱 버전 읽기용
- `react-native`의 `Linking`, `Platform` — 기존 패턴 재사용
- `fetch`/`AbortController` — RN 런타임 내장

## 구현 순서

1. `src/lib/forceUpdate.ts`의 `isValidPlatformInfo`에 빈 문자열 방지 검증 추가
2. `src/components/ForceUpdateModal.tsx`를 풀스크린 차단 카드 → 하단 바텀시트(아이콘 우측 상단, 좌측 정렬 텍스트, "나중에"/"업데이트하기" 2버튼)로 재작성, `Linking.openURL`에 `.catch` 추가
3. `App.tsx`에 `dismissForceUpdate` 추가, `BackHandler` 조건을 "무조건 소비"에서 "닫기 실행 후 소비"로 변경, `ForceUpdateModal`에 `onDismiss` 전달
4. 로컬에서 `minVersion`을 임시로 올려 바텀시트가 뜨는지, "나중에"·뒤로가기로 닫히는지, "업데이트하기"가 스토어로 이동하는지 눈으로 확인 후 원상 복구
5. `npx tsc --noEmit` 재확인

| 2. iOS/Android 최소 버전 독립 | `RemoteVersionConfig.ios` / `.android` 분리 필드 |
| 3. 플랫폼별 스토어 URL 포함 | `PlatformVersionInfo.storeUrl` |
| 4. 콜드 스타트 1회 체크 | `App.tsx` 마운트 전용 `useEffect(..., [])`에서만 호출 |

| 7. 낮을 때만 표시 | `compareVersions(current, minVersion) < 0`일 때만 `blocked: true` |
| 8. 하단 바텀시트 + 백드롭 비침 + 우측 상단 아이콘 + 좌측 정렬 텍스트 + 하단 2버튼 | `ForceUpdateModal`의 `transparent` `Modal` + 백드롭 + 카드 레이아웃 |
