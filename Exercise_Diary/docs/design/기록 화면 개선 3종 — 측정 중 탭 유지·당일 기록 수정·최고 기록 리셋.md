# 기록 화면 개선 3종 — 측정 중 탭 유지·당일 기록 수정·최고 기록 리셋 (설계)

> 스펙: `docs/specs/기록 화면 개선 3종 — 측정 중 탭 유지·당일 기록 수정·최고 기록 리셋.md`

## 화면 구조

- **`src/screens/ExerciseScreen.tsx`** (수정) — 측정 탭 콘텐츠를 렌더링하는 조건을 바꾼다. 지금은 `tab === 'measure'`일 때만 `RepsScreen`을 마운트하지만, 앞으로는 **운동이 횟수·세트형이면 탭과 무관하게 `RepsScreen`을 항상 마운트**해 두고 `visible` prop으로 화면 표시 여부만 넘긴다. `RecordsScreen`은 기존과 동일하게 `tab === 'records'`일 때만 마운트한다.
- **`src/screens/RepsScreen.tsx`** (수정) — `visible: boolean` prop 추가. 기존 상태·로직·JSX는 그대로 두고, 모든 훅을 호출한 뒤 `if (!visible) return null;` 한 줄만 추가한다. 컴포넌트가 탭 전환에 언마운트되지 않으므로 세트 목록·입력값·수정 인덱스(`useState`), 촬영 영상(`useVideoCapture`), 휴식 타이머(`useRestTimer`의 `setInterval`)가 전부 인스턴스째 유지된다.
- **`src/components/SetListEditor.tsx`** (신규) — `RepsScreen`의 "이번 세트 입력 + 등록된 세트 목록" UI(현재 `RepsScreen.tsx:318~433`)를 순수 프레젠테이션 컴포넌트로 추출한다. `exercise`, `sets`, `currentReps`, `currentWeightText`, `editingIndex`, `error`를 props로 받고 `onRepsChange`/`onWeightTextChange`/`onConfirm`(추가 또는 수정 확정)/`onStartEdit`/`onRemove` 콜백만 부른다. `RepsScreen`(측정 중 라이브 편집)과 아래 `EditRepsRecordSheetContent`(저장된 기록 사후 편집) 양쪽이 이 컴포넌트를 재사용한다 — 세트 추가/수정/삭제 UI와 로직을 두 곳에 따로 만들지 않기 위해서다.
- **`src/components/RecordItem.tsx`** (수정) — `onEdit?: (record: TimeRecord) => void` prop 추가. `isToday(record.measuredAt)`일 때만 삭제 버튼 왼쪽에 연필 아이콘(`create-outline`) 버튼을 노출한다.
- **`src/components/RepsRecordItem.tsx`** (수정) — 동일하게 `onEdit?: (record: RepsRecord) => void`와 오늘 기록에 한정된 연필 아이콘.
- **`src/components/EditTimeRecordSheetContent.tsx`** (신규) — `BottomSheet` 안에 들어가는 콘텐츠. `record: TimeRecord`, `onChanged: (next: TimeRecord | null) => void`(수정되면 갱신된 값, 1초 미만으로 내려가 삭제되면 `null`)를 props로 받는다. `TimerScreen`의 결과 화면과 같은 `TimeDisplay` + `−1초`/`+1초` pill 버튼 레이아웃을 그대로 재사용해, 누를 때마다 즉시 반영한다.
- **`src/components/EditRepsRecordSheetContent.tsx`** (신규) — `BottomSheet` 콘텐츠. `exercise: Exercise`, `record: RepsRecord`, `onSaved: (next: RepsRecord) => void`를 props로 받는다. `record.sets`의 로컬 사본을 `SetListEditor`로 편집하다가 명시적 "저장" 버튼을 눌러야 한 번에 반영한다(측정 화면과 동일하게 "여러 세트를 편집하다 한 번에 저장"하는 기존 패턴을 재사용 — 시간형의 "즉시 반영"과는 편집 단위가 달라 의도적으로 다르게 간다).
- **`src/screens/RecordsScreen.tsx`** (수정) — `TimeRecordsScreen`/`RepsRecordsScreen` 각각에:
  - 편집 대상 상태(`editingRecord`)와 `BottomSheet` 인스턴스를 추가해 위 두 신규 콘텐츠를 띄운다.
  - 최고 기록 계산을 신규 헬퍼 `bestTimeRecord`/`bestRepsRecord`(리셋 기준 시각 반영)로 교체한다.
  - `BestCard`에 "최고 기록 리셋" 아이콘 버튼을 추가한다. `showAlert` 확인 후 `updateSettings({ bestRecordResetAt: new Date().toISOString() })`를 호출한다(기존 `confirmDelete`와 같은 확인 패턴).
  - `BestCard`가 `{ kind: 'value'; date; value }` 상태 외에 `{ kind: 'emptySinceReset' }` 상태도 렌더링할 수 있도록 props를 바꾼다.

## 상태 설계

| 상태 | 위치 | 저장소 | 비고 |
|---|---|---|---|
| 측정 중 세트 목록·입력값·수정 인덱스·촬영 영상·휴식 타이머 | `RepsScreen` 로컬 `useState`(변경 없음) | 없음(메모리만) | `RepsScreen`이 탭 전환에도 계속 마운트돼 있어 그대로 유지됨(요구사항 1). `ExerciseScreen` 자체를 벗어나면 정말 언마운트되어 사라짐(요구사항 2, 의도된 경계) |
| 오늘 기록 편집 버퍼 | `Edit*SheetContent` 로컬 `useState`(신규) | 없음 | 시트를 닫으면 버려도 됨 — 스펙에 복구 요구 없음 |
| 최고 기록 리셋 기준 시각(`bestRecordResetAt`) | `useTimerSettings(exercise.id)`(기존 훅 재사용) | `Settings` (`settingsKey(exerciseId)`, AsyncStorage) | 앱 재시작에도 유지돼야 하므로 반드시 영속 저장 |

## 데이터 모델

```ts
// src/lib/types.ts — Settings에 필드 추가
export type Settings = {
  countdownSeconds: number;
  bellIntervalSeconds: number;
  restSeconds: number;
  restEnabled: boolean;
  /** 이 시각(ISO 8601) 이후에 측정된 기록만 "최고 기록" 후보로 삼는다. 없으면(undefined) 전체 기간 대상. */
  bestRecordResetAt?: string;
};
```

`TimeRecord`/`RepsRecord`/`RepsSet`은 스키마 변경 없음 — 필드 일부만 patch하는 기존 `updateRecord`(TimeRecord)와, 아래에서 신설하는 `updateRepsRecord`(RepsRecord)로 충분하다.

```ts
// src/lib/storage.ts — 추가 (updateRecord와 완전히 동일한 패턴)
export function updateRepsRecord(
  exerciseId: string,
  id: string,
  patch: Partial<RepsRecord>,
): Promise<RepsRecord[]> {
  return enqueueWrite(async () => {
    const records = await getRepsRecords(exerciseId);
    const next = records.map((r) => (r.id === id ? { ...r, ...patch } : r));
    await AsyncStorage.setItem(repsKey(exerciseId), JSON.stringify(next));
    return next;
  });
}
```

```ts
// src/lib/records.ts — 추가
export function isToday(iso: string): boolean {
  const d = new Date(iso);
  const now = new Date();
  return (
    d.getFullYear() === now.getFullYear() &&
    d.getMonth() === now.getMonth() &&
    d.getDate() === now.getDate()
  );
}

export function bestTimeRecord(records: TimeRecord[], resetAt?: string): TimeRecord | null {
  const pool = resetAt ? records.filter((r) => r.measuredAt >= resetAt) : records;
  return pool.length > 0 ? pool.reduce((best, r) => (r.durationMs > best.durationMs ? r : best)) : null;
}

export function bestRepsRecord(records: RepsRecord[], resetAt?: string): RepsRecord | null {
  const pool = resetAt ? records.filter((r) => r.measuredAt >= resetAt) : records;
  return pool.length > 0
    ? pool.reduce((best, r) => (totalReps(r) > totalReps(best) ? r : best))
    : null;
}
```

`measuredAt`은 ISO 8601 문자열이라 `storage.ts`의 `getMostRecentRecordAt`과 같은 이유로 `Date` 파싱 없이 사전순 비교(`>=`)로 시간순 비교를 대신할 수 있다.

## 핵심 로직

### 1. 측정 중 탭 유지 (요구사항 1~2)

마운트를 지속시키는 방식으로 푼다 — 새 상태 저장소를 만들지 않는다.

```tsx
// ExerciseScreen.tsx 발췌
<View style={styles.content}>
  {exerciseState.measureType === 'reps' && (
    <RepsScreen
      ref={repsScreenRef}
      exercise={exerciseState}
      onGuideVideoChange={handleGuideVideoChange}
      onUnsavedCountChange={setUnsavedRepsCount}
      visible={tab === 'measure'}
    />
  )}
  {tab === 'measure' && exerciseState.measureType === 'time' && (
    <TimerScreen exercise={exerciseState} onGuideVideoChange={handleGuideVideoChange} />
  )}
  {tab === 'records' && <RecordsScreen exercise={exerciseState} />}
</View>
```

`RepsScreen`은 `exercise.measureType === 'reps'`인 동안 `ExerciseScreen`과 생명주기를 같이한다 — 탭을 오가도 언마운트되지 않고, `visible=false`일 때는 훅을 전부 실행한 뒤 `null`만 반환한다. 그 결과:
- 세트 목록·입력값·수정 인덱스가 `useState`째 보존된다(요구사항 1).
- `useRestTimer`의 `setInterval`이 계속 돌아 기록 탭을 보고 있는 동안에도 휴식 종료 벨이 정상적으로 울린다(부수 효과로 자연 해결).
- `useVideoCapture`의 `capturedVideo`도 그대로 남는다.
- `ExerciseScreen` 자체를 벗어나면(뒤로가기 → 홈) `RepsScreen`이 정말로 언마운트되어 초안이 사라진다 — 요구사항 2가 요구하는 경계와 정확히 일치한다.

`repsScreenRef`/`requestBack`/`unsavedRepsCount` 로직(뒤로가기 시 저장 확인)은 변경할 필요가 없다 — `RepsScreen`이 노출하는 `save()` ref 인터페이스는 그대로이고, 이제는 더 오래 마운트돼 있을 뿐이다.

### 2. 당일 기록 수정 (요구사항 3~6)

목록 아이템의 연필 아이콘은 `isToday(record.measuredAt)`일 때만 렌더링한다 — 활성/비활성 플래그가 아니라 조건부 렌더링이므로, 자정이 지난 뒤 화면을 다시 열면(리스트가 다시 그려지는 시점 기준) 자연히 사라진다(요구사항 5).

- **시간형**: `EditTimeRecordSheetContent`가 `−1초`/`+1초`를 누를 때마다 `Math.max(0, durationMs + delta)`를 계산해, `MIN_RECORD_MS`(`src/lib/useTimerResult.ts`에서 가져와 재사용) 이상이면 `updateRecord`, 미만이면 `removeRecord` 후 시트를 닫는다 — "기록 시간 보정" 스펙(`docs/specs/기록 시간 보정.md`)의 즉시 반영 규칙을 그대로 재사용한다.
- **횟수·세트형**: `EditRepsRecordSheetContent`가 `record.sets`의 로컬 사본을 `SetListEditor`로 편집하다가, "저장"에서 세트가 1개 이상이면 `updateRepsRecord(exercise.id, record.id, { sets })`를 호출하고 시트를 닫는다. 0개면 `RepsScreen`과 같은 `t.reps.errorNoSets` 메시지로 저장을 막는다(전체 삭제는 기존 목록의 휴지통 버튼 몫으로 남겨둔다).
- 두 경우 모두 콜백으로 `RecordsScreen`의 `records` state를 갱신하면, 다음 렌더에서 `bestTimeRecord`/`bestRepsRecord`가 자동으로 재계산된다(요구사항 6).

### 3. 최고 기록 리셋 (요구사항 7~12)

실제 기록은 건드리지 않고 `Settings.bestRecordResetAt`만 갱신하는 방식이라 목록·개수는 절대 변하지 않는다(요구사항 7). `bestTimeRecord`/`bestRepsRecord`가 `resetAt` 이상인 기록만 후보로 삼으므로:
- 리셋 직후 후보가 없으면 `null`이 반환돼 `BestCard`가 `emptySinceReset` 상태로 표시된다(요구사항 9).
- 이후 새로 저장되는 기록의 `measuredAt`은 항상 리셋 시각보다 뒤이므로 자동으로 후보에 포함된다(요구사항 10).
- 리셋 이전의 더 높은 기록은 `resetAt` 필터에 걸려 다시는 최고 기록으로 뽑히지 않는다.

`bestRecordResetAt`은 `settingsKey(exerciseId)`(운동별 키)에 저장되므로 운동 간 완전히 독립적이다(요구사항 12). 리셋 버튼은 `showAlert`로 확인을 받은 뒤에만 `updateSettings({ bestRecordResetAt: new Date().toISOString() })`를 호출한다(요구사항 11) — `RecordsScreen`의 기존 `confirmDelete`와 같은 확인 패턴을 그대로 쓴다.

## 의존성

새 패키지 없음. 기존 컴포넌트(`BottomSheet`, `NumberStepper`, `TimeDisplay`, `AppText`, `Ionicons`)와 기존 훅(`useTimerSettings`, `useVideoCapture`, `useRestTimer`), 기존 유틸(`showAlert`, `MIN_RECORD_MS`)만 재사용한다.
