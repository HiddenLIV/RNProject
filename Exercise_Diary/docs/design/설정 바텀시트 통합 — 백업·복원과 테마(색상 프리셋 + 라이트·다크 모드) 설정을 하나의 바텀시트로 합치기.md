# 설정 바텀시트 통합 — 백업·복원과 테마(색상 프리셋 + 라이트·다크 모드) 설정을 하나의 바텀시트로 합치기

설계 기준 스펙: [설정 바텀시트 통합](../specs/설정%20바텀시트%20통합%20—%20백업·복원과%20테마(색상%20프리셋%20+%20라이트·다크%20모드)%20설정을%20하나의%20바텀시트로%20합치기.md)

## 화면 구조

기존에 이미 있는 조각(`BottomSheet`, `ThemeSwatchRow`, `BackupSheetContent`)을 그대로 재사용하고, 그걸 한 화면으로 묶는 조합 컴포넌트와 라이트/다크 선택 UI만 새로 만든다.

| 파일 | 상태 | 역할 |
|---|---|---|
| `src/components/BottomSheet.tsx` | 기존, 무변경 | 백드롭+슬라이드 시트 셸. `HomeScreen`이 도움말/설정 두 내용을 이 안에 갈아 끼운다(기존과 동일 구조). |
| `src/components/HelpSheetContent.tsx` | 기존, 무변경 | 도움말 내용 — 이번 기능과 무관하게 그대로 유지(스펙 요구사항 14). |
| `src/components/ColorSchemeSelector.tsx` | **신규** | "시스템 설정 따름 / 라이트 / 다크" 3단 세그먼트. `AddExerciseScreen`의 측정방식 세그먼트(`segment`/`segmentSelectedStyle`)와 동일한 시각 언어를 따른다. props 없이 `useAccentColors()`로 직접 읽고 쓴다(`ThemeSwatchRow`와 같은 패턴). |
| `src/components/SettingsSheetContent.tsx` | **신규** | 설정 시트의 실제 내용. "포인트 컬러" 섹션(`ThemeSwatchRow` 재사용) → "화면 모드" 섹션(`ColorSchemeSelector`) → "백업/복원" 섹션(`BackupSheetContent` 재사용) 순서로 세로 배치. `onRestored`/`onRestoreFailed`를 그대로 받아 `BackupSheetContent`에 전달한다(props 시그니처 동일하게 유지). |
| `src/components/ThemeSwatchRow.tsx` | 기존, 무변경 | 로직 변경 없음. 배치 위치만 헤더→시트 안으로 이동(사용하는 쪽 변경일 뿐 컴포넌트 자체는 그대로). |
| `src/components/BackupSheetContent.tsx` | 기존, 무변경 | 로직 변경 없음. `SettingsSheetContent`가 대신 마운트한다는 점만 달라진다. |
| `src/screens/HomeScreen.tsx` | 변경 | 헤더에서 `<ThemeSwatchRow />` 제거, 백업(구름) 아이콘을 설정(톱니바퀴) 아이콘으로 교체, `sheetKind` 값을 `'help' \| 'backup'` → `'help' \| 'settings'`로 변경. |
| `src/lib/ThemeContext.tsx` | 변경 | 라이트/다크 수동 오버라이드 상태 추가(아래 상태 설계 참고). |
| `src/lib/storage.ts` | 변경 | 오버라이드 값 저장/조회 함수, 백업 복원 로직에 반영. |
| `src/lib/backup.ts` | 변경 | 백업 파일에 오버라이드 값 포함/검증. |
| `src/lib/types.ts` | 변경 | `ColorSchemeOverride` 타입, `BackupPayload`에 선택 필드 추가. |
| `src/lib/i18n/locales/*.ts` (4개) | 변경 | `settings.*` 신규 키. |

`SettingsSheetContent`는 `HelpSheetContent`와 대칭 구조(둘 다 `BottomSheet`의 children으로 들어가는 순수 조합 컴포넌트, 자체 `Modal`이나 상태를 안 가짐)라 `HomeScreen`의 기존 바텀시트 배선(스펙 요구사항 3, 13)을 그대로 재사용할 수 있다.

## 상태 설계

**`ThemeContext` (전역, Provider가 앱 최상단에서 관리)** — 기존 `presetId` 상태와 완전히 같은 패턴을 하나 더 둔다:

- `colorSchemeOverride: ColorSchemeOverride` (`'system' | 'light' | 'dark'`) — 마운트 시 `storage.getColorSchemeOverride()`로 불러오고, 로딩 중 사용자가 먼저 바꾸면 그 값을 덮어쓰지 않도록 `presetId`와 동일한 `userChangedRef` 가드를 별도로 하나 더 둔다(두 값은 독립적으로 로드되므로 가드도 독립).
- `setColorSchemeOverride(value)` — 화면엔 즉시 반영(`setState`), 저장은 `storage.setColorSchemeOverride`로 백그라운드 처리(실패해도 사용자에게 노출 안 함) — `setPresetId`와 동일한 책임 분리.
- 실제로 화면에 적용되는 `colorScheme: ColorScheme`(`'light' | 'dark'`)은 파생값: `colorSchemeOverride === 'system'`이면 기존처럼 `useColorScheme()`(시스템 실시간 구독)을 쓰고, `'light'`/`'dark'`면 그 값을 그대로 쓴다. 이 한 줄 분기가 스펙 요구사항 6·7을 모두 만족한다 — system 분기는 지금까지의 동작(라이트 모드 지원 스펙)을 한 글자도 안 바꾼다.
- `colorSchemeOverride`·`setColorSchemeOverride`를 컨텍스트 값에 추가 노출한다(`presetId`/`setPresetId`처럼).

**`HomeScreen` (로컬 state, 기존 그대로 재사용)**

- `sheetKind: 'help' | 'settings'` (기존 `'help' | 'backup'`에서 값만 바뀜, 구조는 동일)
- `sheetOpen: boolean` — 변경 없음
- `openHelp`/`openSettings`(기존 `openBackup`을 이름만 변경)/`closeSheet` — 구조 변경 없음, `sheetOpen`이 여전히 애니메이션 담당, `sheetKind`는 닫을 때도 유지(기존 설계 그대로) — 이 덕분에 이번에도 시트가 닫히는 동안 내용이 비어 보이는 문제가 재발하지 않는다.

**`SettingsSheetContent`/`ColorSchemeSelector`** — 자체 로컬 state 없음. 둘 다 `useAccentColors()`로 컨텍스트를 직접 읽고 쓴다(`ThemeSwatchRow`가 이미 쓰는 패턴과 동일 — prop drilling 없음).

**`BackupSheetContent`** — 기존 `busy`/`exportToastVisible` 로컬 state 그대로, 변경 없음.

## 데이터 모델

`src/lib/types.ts`에 추가:

```ts
// 화면 모드 수동 선택 — 'system'이면 ColorScheme은 useColorScheme()을 따라간다
export type ColorSchemeOverride = 'system' | 'light' | 'dark';
export const COLOR_SCHEME_OVERRIDE_VALUES: ColorSchemeOverride[] = ['system', 'light', 'dark'];
```

`BackupPayload`에 선택 필드 추가(기존 필드는 무변경):

```ts
export type BackupPayload = {
  schemaVersion: typeof BACKUP_SCHEMA_VERSION;
  exportedAt: string;
  appVersion: string;
  exercises: Exercise[];
  theme: ThemePresetId;
  colorSchemeOverride?: ColorSchemeOverride; // 신규, optional — 이전 백업 파일엔 없음
  exerciseData: Record<string, BackupExerciseData>;
};
```

`BACKUP_SCHEMA_VERSION`은 **올리지 않는다**(그대로 `1`). 필드를 선택(optional)으로 추가하는 것만으로 이전 버전 백업 파일(필드 없음)도 그대로 유효한 형태가 되어, 스펙 요구사항 12("이전 형식 백업을 가져와도 실패하지 않는다")를 버전 분기 없이 만족한다. 검증(`isBackupPayloadShape`)에서는 "필드가 있다면 3개 값 중 하나여야 하고, 없으면 통과"로 처리한다.

## 핵심 로직

**라이트/다크 결정 (`ThemeContext.tsx`)**

```ts
const systemScheme = useColorScheme();
const resolvedSystemScheme: ColorScheme = systemScheme === 'light' ? 'light' : 'dark';
const colorScheme: ColorScheme =
  colorSchemeOverride === 'system' ? resolvedSystemScheme : colorSchemeOverride;
```

기존 코드는 `const colorScheme = systemScheme === 'light' ? 'light' : 'dark'` 한 줄이었다. 이번엔 그 결과를 `resolvedSystemScheme`으로 이름만 바꾸고, 오버라이드가 `'system'`이 아닐 때만 그 값으로 대체하는 한 단계를 앞에 끼워 넣는 방식이라 diff가 최소화된다.

파일명 충돌 주의: `storage.ts`가 이미 `setThemePreset`을 export하고 컨텍스트는 `setPresetId`라는 다른 이름으로 감싸는 기존 관례가 있다(그래야 같은 파일 안에서 두 함수명이 안 겹친다). `setColorSchemeOverride`도 storage 함수명과 컨텍스트가 밖으로 노출하는 이름이 같아지므로, `ThemeContext.tsx`에서 storage의 함수를 `import { setColorSchemeOverride as persistColorSchemeOverride } from './storage'`처럼 별칭으로 들여와 내부 구현과 외부 API 이름 충돌을 피한다.

**로드 시점 레이스 가드** — 기존 `presetId`용 `userChangedRef`와 완전히 같은 목적의 별도 ref(`colorSchemeUserChangedRef`)를 하나 더 둔다. 두 값이 각각 다른 AsyncStorage 키에서 독립적으로 로드되므로 가드도 독립적이어야 한다(하나로 합치면 프리셋만 바꿨는데 화면 모드 로딩 결과가 씹히거나 그 반대의 오탐이 생길 수 있음).

**백업 저장/복원 (`backup.ts`/`storage.ts`)**

- `collectBackupPayload`: `getColorSchemeOverride()`를 함께 호출해 `colorSchemeOverride` 필드로 포함(기존 `theme` 수집과 나란히).
- `isBackupPayloadShape`: `v.colorSchemeOverride === undefined || COLOR_SCHEME_OVERRIDE_VALUES.includes(v.colorSchemeOverride)` 조건 추가 — 없으면 통과, 있으면 유효값이어야 함.
- `restoreFromBackup`: `theme`을 검증하던 것과 같은 방식으로 `const colorSchemeOverride = payload.colorSchemeOverride && COLOR_SCHEME_OVERRIDE_VALUES.includes(payload.colorSchemeOverride) ? payload.colorSchemeOverride : 'system'`을 구해 `entries`(multiSet 배열)에 `[COLOR_SCHEME_OVERRIDE_KEY, JSON.stringify(colorSchemeOverride)]`로 추가. 값이 없는 이전 백업은 자동으로 `'system'`이 되어 스펙 요구사항 12를 만족.

새 AsyncStorage 키: `const COLOR_SCHEME_OVERRIDE_KEY = 'timecheck:colorSchemeOverride:v1';` (기존 `THEME_KEY`/`VOICE_GUIDE_KEY`와 같은 네이밍 규칙).

```ts
export async function getColorSchemeOverride(): Promise<ColorSchemeOverride> {
  const raw = await readJson<ColorSchemeOverride | null>(COLOR_SCHEME_OVERRIDE_KEY, null);
  return raw && COLOR_SCHEME_OVERRIDE_VALUES.includes(raw) ? raw : 'system';
}
export function setColorSchemeOverride(value: ColorSchemeOverride): Promise<void> {
  return AsyncStorage.setItem(COLOR_SCHEME_OVERRIDE_KEY, JSON.stringify(value));
}
```
(`getThemePreset`/`setThemePreset`과 동일 형태 — 단순 덮어쓰기라 `enqueueWrite` 불필요.)

**타이머 관련**: 이번 기능은 타이머 로직을 전혀 건드리지 않는다(`Date.now()` 기반 경과시간 계산 규칙과 무관).

## 의존성

새로 추가하는 패키지 없음. 전부 이미 설치된 것(`@react-native-async-storage/async-storage`, RN `useColorScheme`)과 기존 컴포넌트 재사용으로 구현된다.

## 구현 순서

각 단계 끝에 `npx tsc --noEmit`로 확인 가능한 지점을 둔다.

1. **데이터 타입** — `types.ts`에 `ColorSchemeOverride`/`COLOR_SCHEME_OVERRIDE_VALUES` 추가, `BackupPayload`에 선택 필드 추가.
2. **저장소** — `storage.ts`에 `COLOR_SCHEME_OVERRIDE_KEY`·`getColorSchemeOverride`·`setColorSchemeOverride` 추가, `restoreFromBackup`에 반영.
3. **백업 파일 포맷** — `backup.ts`의 `collectBackupPayload`/`isBackupPayloadShape`에 반영. 여기까지는 UI 변경이 없으니 기존 백업 내보내기/가져오기가 여전히 정상 동작하는지로 회귀 확인.
4. **테마 엔진** — `ThemeContext.tsx`에 오버라이드 상태·파생 로직 추가. 이 시점엔 아직 UI가 없으니, 임시로 개발자 도구에서 `setColorSchemeOverride('dark')`를 호출해보거나 다음 단계(5)와 묶어서 확인해도 된다.
5. **`ColorSchemeSelector` 컴포넌트** — 새로 만들어 아무 화면에나 임시로 붙여 탭하면 즉시 화면이 전환되는지, 앱을 재시작해도 유지되는지 확인(이 단계에서 3번 항목 로직이 실제로 맞물려 동작하는 걸 처음 눈으로 확인하게 된다).
6. **i18n** — `settings.*` 키를 4개 언어 파일에 추가.
7. **`SettingsSheetContent` 컴포넌트** — `ThemeSwatchRow` + `ColorSchemeSelector` + `BackupSheetContent`를 섹션 라벨과 함께 조합.
8. **`HomeScreen` 배선** — 헤더에서 `ThemeSwatchRow` 제거, 아이콘 교체, `sheetKind`를 `'settings'`로 바꿔 `SettingsSheetContent` 연결. 여기서 처음으로 전체 흐름이 눈으로 확인 가능(설정 시트 열기 → 3개 섹션 → 백업까지 이어서 조작).
9. **회귀 테스트** — 백업 내보내기(오버라이드 값 포함 확인) → 가져오기(복원 확인) → 화면 모드/포인트 컬러가 함께 복원되는지. 이전 형식(오버라이드 필드 없는) 백업 파일도 하나 만들어 가져오기 시도 → 오류 없이 시스템 따름으로 처리되는지 확인.
10. 전체 `npx tsc --noEmit` + 변경 파일 `npm run lint` 마무리.

## 스펙 요구사항 대응표

| 스펙 요구사항 | 설계 대응 |
|---|---|
| 1. 백업 아이콘→설정 아이콘 교체, 도움말 유지 | HomeScreen 헤더 변경 |
| 2. 헤더의 테마 스와치 제거, 시트로 이동 | HomeScreen에서 `<ThemeSwatchRow/>` 제거 → `SettingsSheetContent` 안으로 |
| 3. 한 시트 안에 3섹션, 탭 전환 없음 | `SettingsSheetContent`가 세로로 모두 배치, `BottomSheet`의 `ScrollView`로 스크롤만으로 접근 |
| 4. 포인트 컬러 기존 동작 유지 | `ThemeSwatchRow` 컴포넌트 자체는 무변경 |
| 5. 화면 모드 3단 선택 UI | `ColorSchemeSelector` |
| 6. 라이트/다크 고르면 기기 설정 무관하게 즉시 전체 전환 | `ThemeContext`의 `colorScheme` 파생 로직 |
| 7. 시스템 따름 선택 시 기존 동작 | 파생 로직의 `'system'` 분기 = 기존 코드 그대로 |
| 8. 재시작해도 유지, 기본값 시스템 따름 | `storage.getColorSchemeOverride` 기본값 `'system'` |
| 9. 백업/복원 섹션 기존 동작 유지 | `BackupSheetContent` 무변경 재사용 |
| 10. 백업 파일에 화면 모드 포함 | `collectBackupPayload`에 필드 추가 |
| 11. 가져오기 시 화면 모드도 함께 교체 | `restoreFromBackup`에 반영 |
| 12. 이전 형식 백업도 실패 없이 가져오기 | 필드를 optional로 설계, 없으면 `'system'` 폴백 |
| 13. 시트 안에서 설정 바꿔도 안 닫힘 | `sheetOpen`은 닫기 버튼/백드롭에서만 바뀜 — 스와치·세그먼트 탭은 `sheetOpen`을 건드리지 않음 |
| 14. 도움말 시트 별도 유지 | `HelpSheetContent` 무변경, `sheetKind === 'help'` 분기 그대로 |
