# 앱 사용법 안내 — 설계

스펙: `docs/specs/앱 사용법 안내.md` (요구사항 1~7)

## 화면 구조

| 파일 | 역할 |
|---|---|
| `src/lib/helpContent.ts` | **(신규)** `HelpSection` 타입과 6개 섹션(운동 추가·측정 시작·기록 확인·운동 촬영·자세 안내 영상·운동 커스터마이징)의 아이콘·제목·설명 정적 데이터 |
| `src/components/HelpModal.tsx` | **(신규)** 전체 화면 모달. 상단에 "도움말" 타이틀 + 닫기 버튼, 아래로 `HELP_SECTIONS`를 스크롤 리스트로 렌더링 |
| `src/screens/HomeScreen.tsx` | (수정) 상단을 `title`/`subtitle` 세로 배치에서 좌우 헤더 행(제목 영역 + 도움말 버튼)으로 재구성, `helpVisible` 상태와 `HelpModal` 인스턴스 소유 |

기존 `EditExerciseModal`/`CameraPermissionModal`/`VideoPlayerModal`과 같은 "부모 화면이 boolean/식별자 상태를 들고, 그 값을 모달 컴포넌트에 prop으로 내려준다" 패턴을 그대로 따른다 — 이 프로젝트에서 이미 세 번 검증된 구조라 새로 고민할 게 없다. 다만 이번 모달은 내용이 길어 스크롤이 필요하므로, 작은 카드형 모달(`transparent + backdrop + card`)이 아니라 `EditExerciseModal` 계열과 달리 **배경을 화면 전체로 채우는 슬라이드형 모달**로 만든다.

> **설계 변경 (실기기 테스트 중 발견)**: RN의 `Modal`은 `App.tsx` 최상위 `SafeAreaProvider`/`SafeAreaView` 바깥의 별도 네이티브 레이어에 뜨기 때문에, 그 안전영역을 물려받지 못한다. 처음 구현에서 헤더를 일반 `View`로만 감쌌더니 실기기(안드로이드, 상태표시줄이 화면을 침범하는 기종)에서 헤더가 상태표시줄과 겹쳐 닫기 버튼이 눌리지 않는 문제가 났다. `HelpModal` 최상위를 `View` 대신 `react-native-safe-area-context`의 `SafeAreaView`(`edges={['top', 'bottom']}`)로 감싸 해결했다 — 이 프로젝트에 이미 있는 의존성이라 새로 추가한 패키지는 없다.

## 상태 설계

- **`HomeScreen`**: `helpVisible: boolean`(초기 `false`) 하나만 추가한다. 도움말 버튼 `onPress`로 `true`, `HelpModal`의 `onClose`로 `false`. 초기값이 `false`라는 사실 자체가 요구사항 7("최초 실행 시 자동으로 안 뜸")을 그대로 충족한다 — 별도의 "처음 실행 여부" 플래그나 AsyncStorage 저장이 전혀 필요 없다.
- **`HelpModal`**: 상태 없음(순수 프레젠테이션) — `visible: boolean`, `onClose: () => void`만 받는다. 섹션 데이터는 `helpContent.ts`에서 직접 import해서 쓴다(부모로부터 내려받을 이유가 없는 정적 데이터).

## 데이터 모델

```ts
// src/lib/helpContent.ts
import { Ionicons } from '@expo/vector-icons';

export type HelpSection = {
  icon: keyof typeof Ionicons.glyphMap;
  title: string;
  description: string;
};

export const HELP_SECTIONS: HelpSection[] = [
  { icon: 'add-circle-outline', title: '운동 추가', description: '...' },
  { icon: 'timer-outline', title: '측정 시작', description: '...' },
  { icon: 'list-outline', title: '기록 확인', description: '...' },
  { icon: 'videocam-outline', title: '운동 촬영', description: '...' },
  { icon: 'play-circle-outline', title: '자세 안내 영상', description: '...' },
  { icon: 'create-outline', title: '운동 커스터마이징', description: '...' },
];
```

이 6개는 AsyncStorage에 저장하는 사용자 데이터가 아니라 앱에 고정으로 박혀 있는 참고 콘텐츠라 `storage.ts`는 전혀 건드리지 않는다. 각 섹션의 `icon`은 이미 앱 곳곳에서 그 기능을 나타내는 데 쓰인 아이콘과 통일해서 사용자가 "어디서 본 아이콘"이라고 바로 연결 지을 수 있게 한다:
- 운동 추가 → `add-circle-outline` (홈 화면의 "운동 추가" 카드가 `add` 아이콘을 씀)
- 측정 시작 → `timer-outline` (`ExerciseScreen`의 "측정" 탭 아이콘)
- 기록 확인 → `list-outline` (`ExerciseScreen`의 "기록" 탭 아이콘)
- 운동 촬영 → `videocam-outline` (`CaptureVideoRow`의 촬영 버튼 아이콘)
- 자세 안내 영상 → `play-circle-outline` (`GuideVideoPanel`의 토글 버튼 아이콘)
- 운동 커스터마이징 → `create-outline` (`HomeScreen`의 운동 카드 수정 연필 아이콘과는 다르지만 "수정"을 뜻하는 표준 아이콘)

## 핵심 로직

1. **섹션 렌더링** (요구사항 3~5) — `HelpModal`은 로직이랄 게 거의 없다. `HELP_SECTIONS.map()`으로 아이콘 배지 + 제목 + 설명을 세로로 나열하고 전체를 `ScrollView`로 감싼다:
   ```tsx
   <ScrollView contentContainerStyle={styles.content}>
     {HELP_SECTIONS.map((section) => (
       <View key={section.title} style={styles.section}>
         <View style={styles.iconBadge}>
           <Ionicons name={section.icon} size={26} color={colors.primary} />
         </View>
         <View style={styles.sectionText}>
           <Text style={styles.sectionTitle}>{section.title}</Text>
           <Text style={styles.sectionDescription}>{section.description}</Text>
         </View>
       </View>
     ))}
   </ScrollView>
   ```
   `HomeScreen`의 운동 카드(`iconBadge` + 텍스트를 가로로 배치하는 `card` 스타일)와 같은 레이아웃 감각을 재사용해 앱 안에서 낯설지 않게 한다.

2. **열기/닫기** (요구사항 2, 6) — `HomeScreen`에서:
   ```tsx
   const [helpVisible, setHelpVisible] = useState(false);
   // ...
   <Pressable onPress={() => setHelpVisible(true)} accessibilityLabel="도움말">
     <Ionicons name="help-circle-outline" size={26} color={colors.primary} />
   </Pressable>
   <HelpModal visible={helpVisible} onClose={() => setHelpVisible(false)} />
   ```
   `HelpModal` 내부는 `Modal`의 `onRequestClose`에 같은 `onClose`를 연결해서, 우측 상단 닫기 버튼과 안드로이드 하드웨어/제스처 뒤로가기가 동일하게 동작하게 한다(요구사항 6) — `EditExerciseModal` 등 기존 모달들과 동일한 처리 방식이라 추가로 고민할 부분이 없다.

3. **홈 화면 헤더 레이아웃 조정** — 지금은 `title`(대제목)과 `subtitle`이 세로로 쌓여 있고 화면 폭을 꽉 채운다. 도움말 버튼이 우측 상단에 오려면, `title`+`subtitle`을 하나의 세로 `View`로 묶고, 그 옆에 도움말 버튼을 두는 가로 `View`(`flexDirection:'row', justifyContent:'space-between', alignItems:'flex-start'`)로 감싼다. 제목 영역엔 `flexShrink:1`을 줘서 긴 제목이 버튼 자리를 침범하지 않게 한다.

## 의존성

새 패키지 없음 — `Modal`, `ScrollView`, `Pressable`은 React Native 내장, 아이콘은 이미 쓰고 있는 `@expo/vector-icons`(Ionicons)만 사용한다.

## 구현 순서

각 단계 끝에서 기존 홈 화면 기능(운동 목록·운동 추가·운동 수정)이 깨지지 않았는지 확인한다.

1. **콘텐츠 데이터 작성** — `src/lib/helpContent.ts`에 `HelpSection` 타입과 6개 섹션 문구를 작성한다. 문구부터 확정하면 이후 UI 작업이 내용에 안 흔들린다.
2. **`HelpModal` 컴포넌트** — 헤더(타이틀+닫기 버튼) + 스크롤 섹션 리스트를 만들고, `HomeScreen`과 무관하게 임시로 `visible` 하드코딩해 시뮬레이터에서 레이아웃·스크롤을 먼저 확인한다.
3. **`HomeScreen` 헤더 재구성 + 연동** — 헤더를 가로 배치로 바꾸고 도움말 버튼 추가, `helpVisible` 상태로 `HelpModal` 연결. 버튼 노출, 열기, 스크롤, 닫기 버튼, 안드로이드 뒤로가기까지 확인.
4. `npx tsc --noEmit` + 실기기 확인 → `/qa`.

| 요구사항 | 설계 반영 위치 |
|---|---|

| 2. 버튼 누르면 도움말 화면 열림 | `helpVisible` state + `HelpModal`(핵심 로직 2) |

| 4. 아이콘·일러스트 + 설명 텍스트, 스크린샷 아님 | `HelpSection` 타입에 이미지 URI 없이 `icon`만 존재 |

| 7. 최초 실행 시 자동으로 안 뜸 | `helpVisible` 초기값 `false`(상태 설계) — 별도 저장 로직 없음 |
