# 측정 화면에서 자세 안내 영상 링크 추가 — 설계

> **개정**: 최초 설계는 저장된 링크를 `GuideVideoPanel` 내부 로컬 state(`savedVideoId`)로만 들고 있었다. `/qa`에서 이 방식이 타이머 단계 전환(측정→"메인으로"→idle 복귀)이나 탭 전환(측정↔기록) 때 `GuideVideoPanel`이 마운트 해제·재마운트되며 방금 저장한 링크가 다시 "추가" 버튼으로 되돌아가는 문제를 발견해, 상태를 `ExerciseScreen`으로 올리는 방식으로 바꿨다. 아래 내용은 개정된 설계다.

## 화면 구조

새 화면 파일은 만들지 않는다. 기존 컴포넌트 4개를 수정한다.

- `src/components/GuideVideoPanel.tsx` — 수정. `videoId`가 없을 때 지금처럼 `return null`이 아니라 "자세 영상 링크 추가" 버튼을 그린다. 탭하면 유튜브 링크 입력란 + 저장/취소 버튼이 그 자리에 펼쳐진다(기존 "펼침" 인터랙션 패턴과 동일한 결의 UI). **저장된 값을 자체적으로 들고 있지 않는 완전한 controlled 컴포넌트**로 만든다 — `videoId` prop을 그대로 읽어 렌더링하고, 저장에 성공하면 `onSaved(videoId)` 콜백으로 부모에 알리기만 한다.
- `src/screens/ExerciseScreen.tsx` — 수정. 이 화면은 타이머 단계 전환이나 측정↔기록 탭 전환 중에도 계속 마운트된 상태로 남아 있는 유일한 지점이라, 여기서 `exerciseState`를 들고 있다가 `onGuideVideoSaved` 콜백으로 갱신한다.
- `src/screens/TimerScreen.tsx`, `src/screens/RepsScreen.tsx` — 수정. `onGuideVideoSaved` prop을 받아 그대로 `<GuideVideoPanel onSaved={onGuideVideoSaved} />`에 전달하는 통로 역할만 한다.
- `src/lib/i18n/locales/*.ts` — `guideVideoPanel` 네임스페이스에 버튼 라벨 키 1개만 신규 추가. 입력란 placeholder·에러 메시지·저장/취소 버튼 문구는 `editExercise` 네임스페이스에 이미 있는 걸 그대로 재사용한다(아래 데이터 모델 참고) — 문구가 완전히 같으므로 중복 키를 만들지 않는다.

## 상태 설계

- `ExerciseScreen`의 `exerciseState: Exercise` (신규) — 홈에서 넘어온 `exercise` prop을 초기값으로 하는 로컬 state. 이 화면이 떠 있는 동안의 "현재 진실"이다. `handleGuideVideoSaved(guideVideoId)`가 `setExerciseState((prev) => ({ ...prev, guideVideoId }))`로 갱신하고, `TimerScreen`/`RepsScreen`/`RecordsScreen`에는 원래 `exercise` prop 대신 이 `exerciseState`를 내려준다.
- `GuideVideoPanel` 내부 로컬 state는 UI 상호작용에만 쓴다 (저장된 값 자체는 들고 있지 않음):
  - `expanded` (기존) — 영상이 있을 때 플레이어를 펼쳤는지.
  - `addingLink: boolean` — 링크가 없을 때, 입력 폼을 펼쳤는지.
  - `linkText: string` — 입력 중인 링크 텍스트.
  - `linkError: string` — 검증 실패 메시지.

**왜 `ExerciseScreen`까지 올리는가 (그 아래로는 안 올리는가)**: `App.tsx`의 `screen.exercise`(홈에서 선택한 시점의 스냅샷)까지 올릴 필요는 없다 — 어차피 홈으로 나갔다 재선택하면 `HomeScreen`이 `getExercises()`로 새로 읽어온 최신값이 내려온다. 반면 `ExerciseScreen`보다 아래(`TimerScreen`/`RepsScreen`/`GuideVideoPanel`)에 두면, 그 컴포넌트들이 타이머 단계·탭 전환 때마다 마운트 해제되므로 방금 저장한 값이 사라진다. `ExerciseScreen`은 이 두 unmount 경로 모두에서 유일하게 계속 떠 있는 지점이라 정확히 여기가 "화면을 나가기 전까지는 유지돼야 하는 값"의 저장 위치다.

렌더링은 단순해진다 — `GuideVideoPanel`은 `videoId` prop이 있으면 기존 토글+플레이어 UI, 없으면 추가 버튼/입력 폼 UI를 그릴 뿐이고, 그 판단 기준(`videoId`)은 이제 항상 `ExerciseScreen`의 `exerciseState.guideVideoId`에서 내려온 최신값이다.

## 데이터 모델

새 타입은 필요 없다. 기존 `Exercise.guideVideoId?: string`(`src/lib/types.ts`)를 그대로 쓴다. 저장은 기존 `updateExercise(id, patch)`(`src/lib/storage.ts`)를 그대로 호출한다 — `EditExerciseModal`이 쓰는 것과 동일한 함수, 동일한 저장소 키라 "홈 화면 수정 모달에도 동일하게 반영"(요구사항 7)이 별도 동기화 로직 없이 자동으로 성립한다.

```ts
// GuideVideoPanel.tsx
type Props = {
  exerciseId: string; // 신규 — 저장 시 updateExercise에 필요
  videoId?: string;   // 기존
};
```

번역 스키마(`Translations`, `src/lib/i18n/locales/en.ts`)에 추가되는 키는 하나뿐이다:
```ts
guideVideoPanel: {
  toggleLabel: string;       // 기존
  addLinkLabel: string;      // 신규 — "자세 영상 링크 추가" / "Add Guide Video Link" 등
}
```
재사용하는 기존 키: `t.editExercise.videoLinkPlaceholder`(입력란 placeholder), `t.editExercise.errorInvalidVideoLink`(검증 실패 메시지), `t.editExercise.save`/`t.editExercise.cancel`(버튼 라벨).

## 핵심 로직

`extractYoutubeVideoId`(`src/lib/youtube.ts`, 기존 함수, 수정 없음)를 그대로 재사용해 watch/youtu.be/shorts 형식만 허용한다.

```ts
// GuideVideoPanel.tsx 내부 — 저장된 값은 들고 있지 않고 부모에 알리기만 한다
const handleSaveLink = async () => {
  const id = extractYoutubeVideoId(linkText);
  if (!id) {
    setLinkError(t.editExercise.errorInvalidVideoLink);
    return;
  }
  await updateExercise(exerciseId, { guideVideoId: id });
  onSaved(id); // ExerciseScreen.exerciseState 갱신 → videoId prop이 갱신돼 토글 버튼으로 전환
  setAddingLink(false);
  setLinkText('');
  setLinkError('');
};

const handleCancelAdd = () => {
  setAddingLink(false);
  setLinkText('');
  setLinkError('');
};
```

```ts
// ExerciseScreen.tsx 내부
const [exerciseState, setExerciseState] = useState(exercise);
const handleGuideVideoSaved = (guideVideoId: string) => {
  setExerciseState((prev) => ({ ...prev, guideVideoId }));
};
// TimerScreen/RepsScreen에 exercise={exerciseState} onGuideVideoSaved={handleGuideVideoSaved}로 전달
```

빈 문자열 저장은 애초에 이 흐름에서 의미가 없다 — "자세 영상 링크 추가" 버튼 자체가 "링크를 채워 넣겠다"는 의도로 진입하는 것이므로, `EditExerciseModal`과 달리 빈 입력에 대해 "링크 없음 허용"을 별도로 처리하지 않고 `extractYoutubeVideoId('')`가 `null`을 반환하는 기존 동작 그대로 "형식 아님" 에러로 통일한다(빈 채로 저장하려는 걸 취소 버튼으로 유도).

렌더 분기(`GuideVideoPanel`):
```tsx
if (!videoId) {
  return addingLink ? <AddLinkForm .../> : <AddLinkButton .../>;
}
return <ExistingToggleAndPlayer .../>; // 기존 코드 그대로
```

## 의존성

없음. `extractYoutubeVideoId`, `updateExercise`, 기존 `useTranslation`/`useAccentColors` 훅만 재사용한다.

## 구현 순서

1. `locales/en.ts`에 `guideVideoPanel.addLinkLabel` 키 추가 → `ko.ts`/`ja.ts`/`zh.ts`에도 값 채우기 (타입 체크로 누락 여부 즉시 확인 가능)
2. `GuideVideoPanel.tsx`의 `Props`에 `exerciseId`, `onSaved` 추가, "링크 없음" 상태의 추가 버튼 UI 구현 (아직 폼은 없이 버튼만) → 링크 있는 운동/없는 운동 두 케이스가 올바르게 갈리는지 확인
3. 추가 버튼 탭 시 펼쳐지는 입력 폼(입력란 + 저장/취소) 구현, `handleCancelAdd`까지 연결 → 펼침·취소 동작 확인
4. `handleSaveLink`(검증 + `updateExercise` + `onSaved(id)` 호출) 연결
5. `ExerciseScreen.tsx`에 `exerciseState`·`handleGuideVideoSaved` 추가, `TimerScreen`/`RepsScreen`에 `exerciseState`와 콜백을 내려줌
6. `TimerScreen.tsx`, `RepsScreen.tsx`가 `onGuideVideoSaved` prop을 받아 `<GuideVideoPanel exerciseId={exercise.id} onSaved={onGuideVideoSaved} />`로 그대로 전달
7. `npx tsc --noEmit` 최종 확인 후, 유효한 링크 저장 시 같은 화면에서 바로 토글 버튼으로 바뀌는지, 잘못된 링크는 에러 메시지가 뜨는지, **타이머 측정을 한 번 돌리거나 기록 탭에 갔다 와도 저장된 링크가 유지되는지**, 실제 화면에서 시간형·횟수세트형 운동 각각 확인 → 홈 화면 수정 모달에도 반영되는지 확인

## 스펙 요구사항 대응

| 스펙 요구사항 | 설계 대응 |
|---|---|
| 1. 링크 없으면 추가 버튼 표시 | `videoId`가 없을 때의 렌더 분기 |
| 2. 탭하면 입력란+저장/취소 펼침 | `addingLink` 상태 |
| 3. 유튜브 형식 아니면 거부+안내 | `extractYoutubeVideoId` + `linkError`(`t.editExercise.errorInvalidVideoLink` 재사용) |
| 4. 저장 성공 시 화면 재진입 없이 토글로 전환 | `onSaved` → `ExerciseScreen.exerciseState` 갱신 → `videoId` prop 즉시 갱신 (타이머 단계·탭 전환에도 유지) |
| 5. 취소 시 입력 폐기, 원상복구 | `handleCancelAdd` |
| 6. 타이머·세트 화면 둘 다 동일 동작 | 컴포넌트 하나(`GuideVideoPanel`)를 양쪽이 공유, `ExerciseScreen`이 둘 다에 같은 `exerciseState`/콜백을 내려줌 |
| 7. 홈 화면 수정 모달에도 동일 반영 | 같은 `updateExercise`/저장소 키를 씀 (별도 저장소 없음) |
| 8. 기존 "링크 있음" 동작 그대로 유지 | 그 분기 코드는 수정하지 않고 그대로 둠 |
