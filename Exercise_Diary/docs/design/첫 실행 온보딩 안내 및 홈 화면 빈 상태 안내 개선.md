# 첫 실행 온보딩 안내 및 홈 화면 빈 상태 안내 개선 — 설계

> **개정 (2차)**: `/qa`를 두 번 거치며 아래 사항들이 드러나 반영했다.
> 1. "건너뛰기/시작하기 버튼은 항상 onClose"라고 설계했지만, 스펙 요구사항 3("스와이프하거나 다음 버튼으로 넘길 수 있고")을 충족하려면 페이지를 진짜로 넘기는 "다음" 버튼이 별도로 필요해 `t.onboarding.next` 키와 `handleNext`를 추가했다.
> 2. `HelpModal`과 `OnboardingModal`을 동시에 `visible=true`로 띄워두는 원래 설계는 iOS에서 RN `<Modal>` 두 개를 동시에 열어두는 게 실제로 지원되지 않아 버그였다 — 1차 수정으로 "하나를 끄고 300ms 뒤 다른 하나를 켠다"는 고정 지연을 넣었지만, 재검증에서 iOS 모달 전환 애니메이션이 300ms보다 길 수 있고 그 틈에 사용자가 도움말(?) 버튼을 다시 누르면 똑같이 두 Modal이 동시에 열릴 수 있다는 점이 드러났다. **최종적으로는 고정 지연 대신 `Modal`의 `onDismiss`(iOS 전용, 닫힘 애니메이션이 실제로 끝난 시점에 호출됨)를 써서 결정론적으로 순서를 보장**하고, 전환이 끝날 때까지 도움말(?) 버튼도 잠가 그 틈에 사용자가 끼어들 수 없게 했다. Android는 `visible=false`가 되는 즉시 내용이 사라지므로 지연·`onDismiss` 없이 바로 이어서 연다.
> 3. 온보딩 "다음" 버튼을 빠르게 연타하면, 스크롤 애니메이션이 끝나기 전에 마지막 페이지로 앞서간 `page` state 때문에 버튼 라벨이 "시작하기"로 먼저 바뀌어 마지막 장을 못 보고 닫히는 문제가 있어, 스크롤 애니메이션이 끝날 때까지 주 버튼을 잠그는 `isScrolling` 가드를 추가했다.
>
> **개정 (3차)**: 2차 개정에서 도입한 가드들 자체가 새로운 좁은 엣지 케이스를 남겨 추가로 손봤다.
> 4. `isScrolling`이 `onMomentumScrollEnd` 단 하나에만 의존해 풀리는데, 사용자가 스크롤 애니메이션 도중 화면을 터치해 감속 없이 드래그가 끝나면(iOS) 그 이벤트가 안 와서 버튼이 영구히 잠길 수 있었다 — 애니메이션 예상 시간(600ms)이 지나면 강제로 풀어주는 타임아웃 안전망을 추가했다.
> 5. `modalTransitioning`은 "?" 버튼만 막고 있어, 전환 도중 운동 카드·수정(연필) 버튼·"운동 추가" 카드를 누르면 여전히 두 Modal이 겹치거나 전환이 조용히 끊길 수 있었다 — 이 세 곳에도 `disabled={modalTransitioning}`을 걸었다. `modalTransitioning` 자체도 `onDismiss`가 유실될 경우를 대비해 1초 타임아웃 안전망을 뒀다(`beginModalTransition` 헬퍼로 통합).
> 6. 첫 실행 자동 노출 판단이 `getOnboardingSeen()`의 비동기 조회 완료 시점에 `helpVisible`을 직접 참조하려 했으나, 이펙트가 마운트 시점 클로저라 실제로는 항상 초기값(`false`)만 보고 있었다(스테일 클로저) — `helpVisibleRef`로 최신값을 따로 추적하도록 고쳤다.
> 7. `setOnboardingSeen()`이 AsyncStorage에 실제로 쓰기 전에 홈 화면이 재마운트(다른 화면 갔다 옴)되면 `getOnboardingSeen()`이 아직 반영 안 된 값을 읽어 온보딩이 다시 뜰 수 있었다 — `storage.ts`에 세션 내 메모리 캐시를 둬서 `setOnboardingSeen()` 호출 즉시(쓰기 완료를 기다리지 않고) 이후의 모든 `getOnboardingSeen()` 호출이 `true`를 보게 했다.
>
> **개정 (4차, 코드 리뷰 반영)**:
> 8. `beginModalTransition`의 1초 워치독이 `pendingModalOpenRef`를 그냥 버려서, `onDismiss`가 1초보다 늦게 도착하면 열려야 할 모달이 조용히 안 열리는 경우가 있었다 — 워치독이 pending을 버리는 대신 **직접 실행**하도록 바꿨다(먼저 도착하는 쪽이 소비하는 방식이라 늦게 온 `onDismiss`는 이미 소비된 걸 보고 안전하게 no-op).
> 9. `helpVisibleRef`를 갱신하던 `useEffect`가 패시브 이펙트라 스케줄링이 밀리면 `getOnboardingSeen().then(...)` 콜백보다 늦게 반영될 수 있어, 여전히 아주 좁은 경합 창이 있었다 — `setHelpVisibleSynced` 헬퍼로 `helpVisible` state와 ref를 상태 변경 지점에서 동시에 갱신하도록 바꿔 이펙트 자체를 없앴다.
> 10. `AddExerciseScreen`의 `setLayoutAnimationEnabledExperimental` 호출이 New Architecture(RN 0.86 기본값)에서 완전히 no-op이고 dev 경고만 찍어서 제거했다(`LayoutAnimation.configureNext`는 이 호출 없이도 Fabric 경로로 정상 동작).
> 11. `OnboardingModal`의 페이지 갱신이 `onMomentumScrollEnd` 하나에만 걸려 있어, 감속 없이 드래그가 끝나면(천천히 끌어다 놓는 경우) 페이지 인디케이터·버튼 라벨이 안 갱신될 수 있었다 — `onScrollEndDrag`도 같은 핸들러에 연결했다.
> 12. "매달리기" 프리셋을 목록에서 뺀 것과 별개로, 도움말·온보딩 2번째 장 문구가 4개 언어 모두 "매달리기처럼 시간을 재는 운동"을 예시로 들고 있어 더 이상 프리셋으로 못 만드는 운동을 안내 문구의 대표 예시로 쓰는 모순이 있었다 — 예시를 "플랭크"(각 언어 표현)로 교체했다.
> 아래 내용은 이를 모두 반영한 최종 설계다.

## 화면 구조

- `src/components/OnboardingModal.tsx` (신규) — 전체화면 `Modal`. 가로 스와이프 페이저 5장 + 페이지 인디케이터(점) + "건너뛰기"/"시작하기" 버튼. 각 장의 아이콘·제목·설명은 새로 안 만들고 기존 `HELP_SECTION_ICONS`(`src/lib/helpContent.ts`)와 `t.help.sections`(번역)의 앞 5개를 그대로 재사용한다 (도움말의 6개 항목 중 "운동 커스터마이징"만 제외한 순서가 스펙이 요구하는 5장 순서와 정확히 일치).
- `src/screens/HomeScreen.tsx` (수정) — 앱 첫 진입 화면이라 온보딩 자동 노출 여부를 여기서 판단한다. `FlatList`에 `ListEmptyComponent`를 추가해 운동이 0개일 때의 안내 문구를 보여준다 (기존 `RecordsScreen`의 빈 상태 문구/아이콘 패턴을 그대로 따름).
- `src/components/HelpModal.tsx` (수정) — 맨 아래에 "온보딩 다시보기" 버튼 추가, 탭하면 `onReplayOnboarding` 콜백으로 부모(HomeScreen)에 알린다.
- `src/lib/storage.ts` (수정) — 온보딩을 한 번이라도 닫았는지 여부를 읽고 쓰는 함수 2개 추가.
- `src/lib/i18n/locales/*.ts` (수정) — `onboarding` 네임스페이스(건너뛰기/다음/시작하기/다시보기 버튼 라벨 4개)와 `home.emptyExercises`(빈 상태 문구) 추가. 온보딩 각 장의 제목·설명은 새 키 없이 `t.help.sections`를 재사용.

## 상태 설계

- `HomeScreen`에 `onboardingVisible: boolean`(초기값 `false`) 추가. 마운트 시 `getOnboardingSeen()`을 한 번 읽어 `false`(아직 안 봄)면 `true`로 바꿔 자동으로 띄운다 — `ThemeContext`가 저장된 프리셋을 비동기로 읽어와 반영하는 기존 패턴과 동일한 결(로딩 전까지는 그냥 안 보이는 상태이므로 깜빡임 없음).
- `HomeScreen`에 `onboardingReplay: boolean`(초기값 `false`)을 추가로 둔다 — 온보딩을 "도움말 다시보기"로 열었는지 기록한다. **두 Modal(`HelpModal`/`OnboardingModal`)을 동시에 `visible=true`로 두지 않는다**(iOS에서 RN Modal 두 개가 동시에 열리는 걸 지원하지 않아 실제로 깨짐) — 대신 항상 하나를 닫고, iOS에서는 그 `onDismiss`(닫힘 애니메이션이 실제로 끝난 시점) 콜백을 받은 뒤에야 다른 하나를 연다. `pendingModalOpenRef`(ref)에 "닫힘이 끝나면 실행할 다음 동작"을 담아두고, `handleHelpDismiss`/`handleOnboardingDismiss`가 그걸 꺼내 실행한다. Android는 `visible=false` 즉시 내용이 사라지므로 이 과정 없이 바로 이어서 연다.
- 전환이 진행 중인 동안(`modalTransitioning: boolean`)엔 홈 화면의 "?" 도움말 버튼을 비활성화한다 — 그 틈에 사용자가 도움말을 다시 열면 온보딩과 동시에 두 Modal이 열리는 상황이 재현될 수 있어서다.
- 온보딩을 닫는 동작(건너뛰기/다음/시작하기)은 `handleCloseOnboarding` 하나로 처리한다 — `setOnboardingSeen().catch(() => {})` 호출 후, `onboardingReplay`가 참이면 `onboardingReplay`를 끄고 온보딩이 완전히 닫힌 뒤(iOS는 `onDismiss`, Android는 즉시) `setHelpVisible(true)`로 도움말을 다시 연다.
- `HomeScreen`은 이미 있는 `exercises: Exercise[]` state에 `exercisesLoaded: boolean`(초기값 `false`)을 추가한다 — `getExercises()` 응답이 오기 전까지는 `ListEmptyComponent` 자체를 렌더하지 않아, 운동이 있는 사용자가 화면 진입 시 빈 상태 문구가 잠깐 깜빡이는 것을 막는다. 로드가 끝난 뒤에는 `exercises.length === 0`일 때만 빈 상태 문구를 보여준다.
- `OnboardingModal` 내부에는 현재 페이지 인덱스를 `page`(렌더용 state)와 `pageRef`(계산용 ref) 둘로 관리한다. `onClose` 콜백 하나로만 부모에 닫힘을 알리고, 저장소나 "다시보기 여부" 같은 문맥은 몰라도 되게 한다(그 구분은 전부 `HomeScreen` 쪽 책임) — `visible`이 `true`로 바뀌는 순간 `useEffect`로 페이지를 0으로 리셋한다(닫을 때가 아니라 열 때 리셋 — 아래 핵심 로직 참고).

## 데이터 모델

새 도메인 타입은 없다. 저장은 boolean 플래그 하나뿐이다.

```ts
// src/lib/storage.ts
const ONBOARDING_SEEN_KEY = 'timecheck:onboardingSeen:v1';

export async function getOnboardingSeen(): Promise<boolean> {
  return readJson<boolean>(ONBOARDING_SEEN_KEY, false);
}

export function setOnboardingSeen(): Promise<void> {
  return AsyncStorage.setItem(ONBOARDING_SEEN_KEY, JSON.stringify(true));
}
```
`getThemePreset`/`setThemePreset`과 같은 자리(파일 하단, 테마 저장 함수들 옆)에 둔다. 단순 덮어쓰기라 `enqueueWrite` 직렬화 큐는 필요 없다(테마 저장과 동일한 이유).

번역 스키마에 추가되는 키:
```ts
onboarding: {
  skip: string;   // "건너뛰기"
  next: string;   // "다음" — 페이지를 실제로 넘기는 버튼
  start: string;  // "시작하기"
  replayLabel: string; // 도움말 안의 "온보딩 다시보기" 버튼
},
home: {
  ...기존,
  emptyExercises: string; // "아직 등록된 운동이 없어요. 첫 운동을 추가해보세요" 등
}
```
재사용: `t.help.sections[0..4]`(각 장 제목·설명), `HELP_SECTION_ICONS[0..4]`(각 장 아이콘).

## 핵심 로직

### 온보딩 자동 노출 및 도움말과의 순차 전환 (`HomeScreen.tsx`)
```ts
const [onboardingVisible, setOnboardingVisible] = useState(false);
const [onboardingReplay, setOnboardingReplay] = useState(false);
const [modalTransitioning, setModalTransitioning] = useState(false);
const pendingModalOpenRef = useRef<(() => void) | null>(null);

useEffect(() => {
  getOnboardingSeen().then((seen) => {
    if (!seen) setOnboardingVisible(true);
  });
}, []);

const handleReplayOnboarding = () => {
  setOnboardingReplay(true);
  if (Platform.OS === 'ios') {
    setModalTransitioning(true);
    pendingModalOpenRef.current = () => {
      setModalTransitioning(false);
      setOnboardingVisible(true);
    };
    setHelpVisible(false); // onDismiss가 pendingModalOpenRef를 실행할 때까지 대기
  } else {
    setHelpVisible(false);
    setOnboardingVisible(true); // Android는 dismiss가 즉시 끝나 바로 이어 연다
  }
};

const handleHelpDismiss = () => {
  pendingModalOpenRef.current?.();
  pendingModalOpenRef.current = null;
};

const handleCloseOnboarding = () => {
  setOnboardingSeen().catch(() => {});
  if (onboardingReplay) {
    setOnboardingReplay(false);
    if (Platform.OS === 'ios') {
      setModalTransitioning(true);
      pendingModalOpenRef.current = () => {
        setModalTransitioning(false);
        setHelpVisible(true);
      };
      setOnboardingVisible(false);
    } else {
      setOnboardingVisible(false);
      setHelpVisible(true);
    }
  } else {
    setOnboardingVisible(false);
  }
};

const handleOnboardingDismiss = () => {
  pendingModalOpenRef.current?.();
  pendingModalOpenRef.current = null;
};
```
`<HelpModal onDismiss={handleHelpDismiss} .../>`, `<OnboardingModal onDismiss={handleOnboardingDismiss} .../>`로 연결한다. `HelpModal`과 `OnboardingModal`은 **절대 동시에 `visible=true`가 되지 않는다** — iOS는 닫힘 애니메이션이 실제로 끝난 뒤(`onDismiss`)에만 다음 것을 열고, 그사이 홈 화면의 "?" 버튼도 `modalTransitioning`으로 잠가 사용자가 끼어들 수 없다. 자동 노출 경로(`onboardingReplay=false`)는 애초에 도움말이 열려 있지 않으므로 이 전환 자체가 필요 없다.

### 페이지 넘김 (`OnboardingModal.tsx`)
가로 `ScrollView`(`pagingEnabled`) + `onMomentumScrollEnd`으로 현재 페이지를 계산하는, 별도 라이브러리 없는 표준 패턴을 쓴다. 화면 표시용 `page` state와 별개로 `pageRef`를 둬서, "다음" 버튼을 연타해도(스크롤 애니메이션이 끝나 `onMomentumScrollEnd`가 발동하기 전에 또 눌러도) 항상 최신 페이지 기준으로 계산되게 한다. 스크롤 애니메이션이 도는 동안엔 `isScrolling`으로 주 버튼을 잠가, "다음"을 눌러 마지막 페이지 직전에서 라벨이 곧장 "시작하기"로 바뀌는 틈에 연타해 마지막 장을 못 보고 닫히는 걸 막는다:
```ts
const pageRef = useRef(0);
const [page, setPage] = useState(0);
const [isScrolling, setIsScrolling] = useState(false);
const pages = t.help.sections.slice(0, 5); // 아이콘은 HELP_SECTION_ICONS.slice(0, 5)로 같은 인덱스 사용
const isLast = page === pages.length - 1;

// Modal이 열릴 때(닫힐 때가 아니라) 페이지를 리셋한다 — iOS는 닫히는 애니메이션 중에도
// 내용이 계속 보이므로, 닫을 때 리셋하면 닫히는 도중 1장으로 튕기는 게 보인다.
useEffect(() => {
  if (visible) {
    pageRef.current = 0;
    setPage(0);
    setIsScrolling(false);
    scrollRef.current?.scrollTo({ x: 0, animated: false });
  }
}, [visible]);

const handleMomentumEnd = (e: NativeSyntheticEvent<NativeScrollEvent>) => {
  const next = Math.round(e.nativeEvent.contentOffset.x / width);
  pageRef.current = next;
  setPage(next);
  setIsScrolling(false);
};

const handleNext = () => {
  if (isScrolling) return;
  const next = Math.min(pageRef.current + 1, pages.length - 1);
  if (next === pageRef.current) return;
  setIsScrolling(true);
  pageRef.current = next;
  setPage(next);
  scrollRef.current?.scrollTo({ x: next * width, animated: true });
};
```
"건너뛰기"는 마지막 장이 아닐 때만 노출되고 항상 `onClose`를 호출한다(스펙 요구사항 4). 하단 주 버튼은 `disabled={isScrolling}`로 애니메이션 중엔 눌리지 않고, 마지막 장이 아니면 "다음"(`handleNext`로 실제 페이지 이동), 마지막 장이면 "시작하기"(`onClose`)로 라벨과 동작이 함께 바뀐다(스펙 요구사항 3·5).

### 빈 상태 (`HomeScreen.tsx`)
```tsx
<FlatList
  data={exercises}
  ListEmptyComponent={
    exercisesLoaded ? (
      <View style={styles.empty}>
        <Ionicons name="body-outline" size={40} color={accent.textFaint} />
        <Text style={[styles.emptyText, { color: accent.textMuted }]}>{t.home.emptyExercises}</Text>
      </View>
    ) : null
  }
  ...
  ListFooterComponent={/* 기존 "운동 추가" 카드, 그대로 유지 */}
/>
```
`exercisesLoaded`가 `false`인 동안(최초 로드 전)은 `ListEmptyComponent`가 `null`이라 아무 것도 안 보인다 — 운동이 있는 사용자에게 빈 상태 문구가 잠깐 깜빡이는 걸 막는다. `ListFooterComponent`는 데이터가 비어 있어도 항상 렌더링되므로(RN `FlatList` 기본 동작), 로드가 끝나고 실제로 0개면 빈 상태 문구와 "운동 추가" 카드가 함께 보인다 — 요구사항 9·10을 위한 추가 조건 분기가 필요 없다.

## 의존성

없음. `ScrollView`(가로 페이징)와 `Modal`은 `react-native` 내장. 새 온보딩 라이브러리(`react-native-onboarding-swiper` 등)는 페이지 5장짜리 단순 구성에 과하다고 판단해 직접 구현한다.

## 구현 순서

1. `storage.ts`에 `getOnboardingSeen`/`setOnboardingSeen` 추가 (테마 저장 함수 옆)
2. `locales/en.ts`에 `onboarding.{skip,next,start,replayLabel}`, `home.emptyExercises` 키 추가 → `ko`/`ja`/`zh` 채우기 (타입 체크로 누락 확인)
3. `OnboardingModal.tsx` 작성 — 우선 스와이프 없이 5장을 다 한 화면에 세로로 나열해 내용(아이콘·제목·설명)이 올바르게 재사용되는지부터 확인
4. 가로 페이징(`ScrollView` + `pagingEnabled` + `onMomentumScrollEnd`) 붙이고 페이지 인디케이터 추가 → 스와이프·버튼 넘김 확인
5. "건너뛰기"/"시작하기" 버튼과 `onClose` 연결 → 마지막 장에서만 라벨이 바뀌는지 확인
6. `HomeScreen.tsx`에 자동 노출 로직(`onboardingVisible`, `handleCloseOnboarding`) 연결 → 저장된 플래그를 지워보며(수동으로 AsyncStorage 값 삭제) 첫 실행 자동 노출 확인
7. `HelpModal.tsx`에 "다시보기" 버튼 + `onReplayOnboarding` prop 추가, `HomeScreen`에서 연결 → 도움말에서 다시 열리는지, 닫으면 도움말로 돌아가는지 확인
8. `HomeScreen`의 `FlatList`에 `ListEmptyComponent` 추가 → 운동 0개/1개 이상 상태 전환 시 안내가 나타나고 사라지는지 확인
9. `npx tsc --noEmit` 최종 확인 후 실기기/시뮬레이터에서 전체 흐름(설치 후 첫 실행 → 건너뛰기/끝까지 보기 → 재실행 시 안 뜸 → 도움말에서 다시보기) 확인

## 스펙 요구사항 대응

| 스펙 요구사항 | 설계 대응 |
|---|---|
| 1. 첫 실행 시 자동 표시 | `HomeScreen`의 `getOnboardingSeen()` 확인 후 `onboardingVisible` |
| 2. 5장 구성, 기존 도움말 내용 재사용 | `t.help.sections.slice(0,5)` + `HELP_SECTION_ICONS.slice(0,5)` |
| 3. 스와이프/버튼 넘김 + 페이지 인디케이터 | `ScrollView pagingEnabled` + `page`/`pageRef` + "다음" 버튼(`handleNext`) |
| 4. 아무 장에서나 건너뛰기 | 마지막 장이 아닐 때 노출되는 "건너뛰기" 버튼(`onClose`) |
| 5. 마지막 장 "시작하기" | `isLast` 조건부로 주 버튼 라벨·동작이 "다음"→"시작하기"로 바뀜 |
| 6. 한 번 닫으면 재노출 안 함 | `setOnboardingSeen()` 저장 |
| 7. 도움말에 "다시보기" | `HelpModal`의 `onReplayOnboarding` → `handleReplayOnboarding` |
| 8. 다시보기 닫으면 도움말로 복귀 | `onboardingReplay` 플래그로 `handleCloseOnboarding`이 도움말을 다시 염 — `onDismiss`(iOS)로 완전히 닫힌 뒤에만 열어 두 Modal이 동시에 뜨지 않음 |
| 9~10. 빈 상태 안내, 탭 동작 없음 | `ListEmptyComponent`(순수 표시), 탭 이벤트 미부착 |
| 11. 운동 추가 시 안내 사라짐 | `exercises.length === 0` 조건이 `ListEmptyComponent` 렌더 여부를 그대로 결정 |
