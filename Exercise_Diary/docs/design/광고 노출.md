# 광고 노출 — 설계

## 화면 구조

새 화면 신설 없음. 홈 화면 레이아웃을 살짝 재구성해 하단에 배너 광고 자리를 만들고, 운동 추가 화면의 저장 흐름에 전면 광고를 끼워 넣는다.

| 파일 | 역할 |
|---|---|
| `src/lib/ads.ts` (신규) | AdMob 초기화, 광고 단위 ID 상수, 전면 광고 로드·표시·프리로드 관리 — UI와 분리된 순수 로직 |
| `src/components/BottomBannerAd.tsx` (신규) | 배너 광고 자체를 감싸는 컴포넌트. 로드 성공 전/실패 시엔 자기 자신을 접어(height 0) 빈 공간을 남기지 않는다 |
| `src/screens/HomeScreen.tsx` (수정) | 레이아웃을 바깥(화면 전체) / 안(기존 헤더+검색+목록+FAB, 좌우 padding 유지) 두 겹으로 나누고, 바깥 컨테이너 맨 아래에 `BottomBannerAd`를 전체 너비로 배치 |
| `src/screens/AddExerciseScreen.tsx` (수정) | `handleAdd()`에서 저장 직후, 새 총 운동 개수가 조건에 맞으면 `showInterstitialAndWait()`를 기다렸다가 `onCreated()` 호출 |
| `App.tsx` (수정) | 기존 오디오 모드 설정 `useEffect` 옆에 `initializeAds()` 1회 호출 추가 |
| `app.json` (수정) | `plugins`에 `react-native-google-mobile-ads` config plugin과 `androidAppId`/`iosAppId` 추가 |
| `docs/privacy-policy.html` (수정) | 광고 SDK(Google AdMob)를 통한 데이터 수집 사실 문구 추가 |

**HomeScreen 레이아웃 (배너는 좌우 padding 바깥, 전체 너비)**

표준 적응형 배너(`ANCHORED_ADAPTIVE_BANNER`)는 기기 전체 너비를 기준으로 크기가 계산되므로, 기존 `styles.container`의 `paddingHorizontal: spacing.md` 바깥에 둬야 한다. 그래서 바깥 컨테이너를 하나 더 두고, 기존 헤더+검색+목록+FAB 묶음을 padding이 있는 안쪽 컨테이너로 옮긴다.

```
screen (flex:1, background)
├─ content (flex:1, paddingHorizontal: spacing.md)  ← 기존 styles.container 내용 그대로
│   ├─ header (제목, 백업/도움말 아이콘, 검색창)
│   ├─ FlatList (flex, 운동 목록)
│   └─ FAB (absolute, content 기준 bottom: spacing.md — 배너와 무관하게 항상 content 하단 바로 위)
└─ BottomBannerAd (전체 너비, content 바깥 맨 아래)
```

`content`가 `flex:1`인 나머지 공간을 차지하고 `BottomBannerAd`는 자기 높이만큼만 차지하는 일반 flex 자식이라, 배너가 로드/실패로 높이가 바뀌어도(0 ↔ 실제 배너 높이) FAB는 여전히 `content`의 바닥 기준으로 붙어 있어 별도 높이 측정·상태 동기화 없이 항상 배너 바로 위에 자연스럽게 위치한다. `FlatList`의 `contentContainerStyle.paddingBottom`(FAB 가림 방지용 기존 여백)도 그대로 둔다 — FAB 위치 기준이 바뀌지 않았으므로.

측정 화면(`ExerciseScreen.tsx`)과 운동 추가/수정 화면(`AddExerciseScreen.tsx`)은 이 레이아웃 변경과 무관하며 코드도 건드리지 않는다(요구사항 2).

## 상태 설계

**`BottomBannerAd.tsx` (로컬 상태)**
- `loaded: boolean` — `BannerAd`의 `onAdLoaded`/`onAdFailedToLoad` 콜백으로 갱신. `false`면 컴포넌트가 `height: 0, overflow: 'hidden'`으로 접혀 빈 공간을 차지하지 않는다(요구사항 3, 9).

**`ads.ts` (모듈 스코프, React state 아님)**
- 전면 광고 인스턴스(`InterstitialAd`)와 로드 완료 여부를 모듈 top-level 변수로 들고 있는다. 여러 화면에서 재사용하는 게 아니라 앱 전체에 하나만 필요하고, React 컴포넌트 생명주기와 무관하게(운동 추가 화면이 마운트되기 전부터) 미리 로드해 둬야 표시 시점에 지연이 없기 때문이다.
- 표시 후에는 같은 인스턴스를 재사용할 수 없으므로(광고 라이브러리 특성상 1회성) 새 인스턴스를 만들어 즉시 다시 `load()`를 걸어 다음 트리거를 미리 준비해 둔다.

**`AddExerciseScreen.tsx` (기존 상태 재사용)**
- 새 상태 추가 없음. 기존 `saving: boolean`을 저장 API 호출부터 `showInterstitialAndWait()` 대기까지 계속 `true`로 유지해, 전면 광고가 뜨는 동안 저장 버튼 중복 탭을 막는다(화면은 `onCreated()` 호출 전까지 언마운트되지 않으므로 자연스럽게 유지된다).

## 데이터 모델

새로 저장하는 데이터 없음. "등록 운동 개수"는 항상 `src/lib/storage.ts`의 `getExercises()`가 반환하는 배열 길이를 그 자리에서 계산해 쓴다 — 별도 카운터를 저장하지 않으므로 삭제 후 재등록 시에도 항상 실제 상태와 일치한다(스펙 요구사항 7이 요구하는 실시간성을 별도 로직 없이 자연히 만족).

## 핵심 로직

### 전면 광고 트리거 판정 (`src/lib/ads.ts`)

```ts
export function shouldShowInterstitial(totalExerciseCount: number): boolean {
  return totalExerciseCount >= 3 && totalExerciseCount % 3 === 0;
}
```

- `AddExerciseScreen`은 저장 직전 이미 갖고 있는 `existingExercises`(마운트 시 `getExercises()`로 불러온, 지금 막 추가하는 운동을 제외한 목록)에 `+1`을 더한 값을 `totalExerciseCount`로 넘긴다. 3, 6, 9…에서만 `true`가 되어 스펙의 "3번째부터, 이후 3개씩" 조건(요구사항 4, 5)을 그대로 구현한다.

### 전면 광고 로드·표시 (`src/lib/ads.ts`)

```ts
import mobileAds, { AdEventType, InterstitialAd, TestIds } from 'react-native-google-mobile-ads';

// TODO: AdMob 콘솔에서 앱을 등록하고 발급받은 실제 광고 단위 ID로 교체.
// 실제 ID가 준비되기 전(및 __DEV__)에는 항상 테스트 ID를 써서 개발 중 실수로
// 진짜 광고에 노출/클릭이 잡히는 일을 막는다.
export const BANNER_AD_UNIT_ID = __DEV__ ? TestIds.BANNER : 'ca-app-pub-XXXXXXXXXXXXXXXX/XXXXXXXXXX';
export const INTERSTITIAL_AD_UNIT_ID = __DEV__ ? TestIds.INTERSTITIAL : 'ca-app-pub-XXXXXXXXXXXXXXXX/XXXXXXXXXX';

let interstitial = InterstitialAd.createForAdRequest(INTERSTITIAL_AD_UNIT_ID);
let interstitialLoaded = false;

function preloadInterstitial() {
  interstitialLoaded = false;
  const unsubscribe = interstitial.addAdEventListener(AdEventType.LOADED, () => {
    interstitialLoaded = true;
  });
  interstitial.load();
  return unsubscribe;
}

let unsubscribeLoad = preloadInterstitial();

export function initializeAds() {
  mobileAds().initialize();
}

export function showInterstitialAndWait(): Promise<void> {
  return new Promise((resolve) => {
    if (!interstitialLoaded) {
      resolve(); // 아직 못 불러왔으면 건너뛴다 — 운동 추가 흐름을 절대 막지 않는다 (요구사항 9)
      return;
    }
    const unsubscribeClosed = interstitial.addAdEventListener(AdEventType.CLOSED, finish);
    const unsubscribeError = interstitial.addAdEventListener(AdEventType.ERROR, finish);
    function finish() {
      unsubscribeClosed();
      unsubscribeError();
      unsubscribeLoad(); // 방금 소비한 인스턴스를 버리고 다음 트리거를 위해 새로 준비
      interstitial = InterstitialAd.createForAdRequest(INTERSTITIAL_AD_UNIT_ID);
      unsubscribeLoad = preloadInterstitial();
      resolve();
    }
    interstitial.show();
  });
}
```

- `AdEventType.ERROR`도 `resolve()`로 이어지게 해, `show()` 호출 시점 사이에 광고가 만료되는 등 드문 실패에도 대기가 영원히 안 끝나는 일이 없게 한다.
- 정확한 API 이름(`createForAdRequest`, `addAdEventListener`, `AdEventType` 값 등)은 실제 설치될 `react-native-google-mobile-ads` 버전 문서로 구현 시점에 다시 확인한다 — AGENTS.md의 "Expo가 자주 바뀐다" 원칙과 같은 이유로, 이 문서는 설계 의도(프리로드 → 트리거 시 표시 → 다음 것 미리 로드)를 고정하는 것이고 세부 메서드 시그니처는 구현 단계에서 검증 대상이다.

### 운동 추가 화면 연동 (`src/screens/AddExerciseScreen.tsx`)

`handleAdd()`의 `await addExercise(exercise);` 직후, `onCreated()` 호출 전에 끼워 넣는다:

```ts
await addExercise(exercise);
const totalCount = existingExercises.length + 1;
if (shouldShowInterstitial(totalCount)) {
  await showInterstitialAndWait();
}
onCreated();
```

이 시점(저장 완료 ~ 홈 화면 전환 사이)이 스펙 요구사항 6이 지정한 정확한 노출 지점이다.

### 배너 광고 (`src/components/BottomBannerAd.tsx`)

```tsx
export default function BottomBannerAd() {
  const accent = useAccentColors();
  const [loaded, setLoaded] = useState(false);
  return (
    <View style={[{ width: '100%', alignItems: 'center', backgroundColor: accent.background }, !loaded && { height: 0, overflow: 'hidden' }]}>
      <BannerAd
        unitId={BANNER_AD_UNIT_ID}
        size={BannerAdSize.ANCHORED_ADAPTIVE_BANNER}
        onAdLoaded={() => setLoaded(true)}
        onAdFailedToLoad={() => setLoaded(false)}
      />
    </View>
  );
}
```

배너 로드 실패 시 별도 재시도 로직은 만들지 않는다 — 화면 전환(측정 화면 갔다가 홈으로 복귀 등)으로 `HomeScreen`이 다시 마운트될 때 자연스럽게 재시도된다. 컨테이너 배경을 `accent.background`로 맞춰, 로드된 배너와 앱 배경 사이 이질감을 줄인다(요구사항 10) — 광고 소재 자체의 배경색까지는 앱이 관여할 수 없다.

### 초기화 (`App.tsx`)

기존 오디오 모드 설정 `useEffect`와 같은 위치(마운트 시 1회)에 `initializeAds()`를 호출한다. 이 호출이 끝나기 전에 `BottomBannerAd`/전면 광고 `load()`가 먼저 실행돼도 라이브러리 자체가 내부 큐잉을 하므로 순서를 엄격히 기다릴 필요는 없다.

### 타이머 관련

이 기능은 시간 측정을 다루지 않으므로 `Date.now()` 기반 경과시간 규칙과 무관하다.

## 의존성

| 패키지 | 이유 | 비고 |
|---|---|---|
| `react-native-google-mobile-ads` | 배너·전면 광고(Google AdMob) | 네이티브 모듈이라 **Expo Go에서 실행 불가**. `npx expo install react-native-google-mobile-ads`로 설치 |
| `expo-dev-client` | 커스텀 네이티브 모듈이 포함된 개발용 빌드 실행 | 현재 `package.json`에 없음 — 함께 설치 필요. `eas.json`의 `development` 프로필이 이미 `developmentClient: true`로 이를 전제하고 있어, 이번에 처음 실제로 쓰게 된다 |

**app.json 변경**

```json
[
  "react-native-google-mobile-ads",
  {
    "androidAppId": "ca-app-pub-XXXXXXXXXXXXXXXX~YYYYYYYYYY",
    "iosAppId": "ca-app-pub-XXXXXXXXXXXXXXXX~ZZZZZZZZZZ"
  }
]
```

실제 App ID·광고 단위 ID는 AdMob 콘솔에서 iOS/Android 앱을 각각 등록해야 발급된다 — 이건 코드 작업이 아니라 사용자가 AdMob 계정에서 먼저 해야 하는 선행 작업이다. 발급 전까지는 플레이스홀더 값과 `TestIds`로 전체 흐름을 개발·검증한다.

새 네이티브 모듈이 추가되므로 `app.json` 변경 후 `npx expo prebuild`(또는 `npx expo run:ios` / `run:android`)로 네이티브 프로젝트를 다시 생성해야 반영된다.

**참고(이번 구현엔 포함하지 않음)**: Google 정책상 EEA/영국 사용자에게는 광고 표시 전 동의(UMP consent) 절차가 요구된다. 이번 스펙의 제외 범위(정책 커스터마이징)에 해당해 이번엔 만들지 않지만, 실제 스토어 배포 전에는 별도로 검토가 필요하다는 점만 남겨둔다.

## 구현 순서

1. AdMob 콘솔에서 iOS/Android 앱을 등록해 App ID·배너/전면 광고 단위 ID를 받는다(사용자 작업). 받기 전까지는 아래 단계를 `TestIds`로 그대로 진행할 수 있다.
2. `npx expo install react-native-google-mobile-ads expo-dev-client` → `app.json`에 plugin 추가 → `npx expo prebuild` 후 `npx expo run:ios` / `run:android`로 네이티브 빌드가 정상적으로 되는지 확인 → `npx tsc --noEmit`.
3. `src/lib/ads.ts` 작성 → `App.tsx`에 `initializeAds()` 연결.
4. `src/components/BottomBannerAd.tsx` 작성 → `HomeScreen.tsx` 레이아웃을 outer/inner로 재구성해 삽입 → 실기기/에뮬레이터에서 배너가 항상 최하단에 뜨고 FAB가 배너 위로 자연스럽게 위치하는지 확인.
5. `AddExerciseScreen.tsx`의 `handleAdd()`에 `shouldShowInterstitial`/`showInterstitialAndWait` 연결 → 운동을 1개씩 순서대로 추가해보며 3번째·6번째에만 전면 광고가 뜨고 나머지는 안 뜨는지, 삭제 후 다시 그 지점에 도달하면 재노출되는지 확인.
6. 라이트/다크 테마 전환, 기내 모드로 광고 로드 실패 상황을 각각 재현해 레이아웃이 깨지지 않는지 확인.
7. `docs/privacy-policy.html`에 Google AdMob 데이터 수집 관련 문구 추가.
8. 스펙 성공 기준을 실기기로 하나씩 검증(`/qa`).

## 스펙 요구사항 ↔ 설계 대응

| 스펙 요구사항 | 설계 반영 |
|---|---|
| 1. 배너, 개수 무관 상시 노출 | `BottomBannerAd`가 트리거 조건 없이 `HomeScreen`에 항상 렌더링됨 |
| 2. 배너는 홈 화면에서만 | `ExerciseScreen`/`AddExerciseScreen`은 수정 대상에서 제외 |
| 3. 스크롤과 무관하게 최하단 고정 | `content`(FlatList 포함) 바깥, 화면 최하단 별도 flex 자식으로 배치 |
| 4·5. 3번째부터, 이후 3개씩 전면 광고 | `shouldShowInterstitial(totalCount)` = `count % 3 === 0 && count >= 3` |
| 6. 저장 직후~홈 전환 전 노출 시점 | `handleAdd()`에서 `addExercise()` 이후 `onCreated()` 이전에 `await showInterstitialAndWait()` |
| 7. 실시간 등록 개수 기준 | 저장 카운트를 별도 저장하지 않고 매번 `getExercises()` 결과 길이로 계산 |
| 8. Google AdMob 사용 | `react-native-google-mobile-ads`의 `BannerAd`/`InterstitialAd` |
| 9. 로드 실패/지연 시 흐름 유지 | 배너: `loaded=false`면 높이 0으로 접힘 / 전면: `interstitialLoaded=false`면 즉시 `resolve()`로 건너뜀 |
| 10. 테마와 자연스러운 배경 | `BottomBannerAd` 컨테이너 배경을 `accent.background`로 맞춤 |
| 11. 테스트 ID → 실제 ID 교체 가능 | `BANNER_AD_UNIT_ID`/`INTERSTITIAL_AD_UNIT_ID` 상수 하나씩만 바꾸면 되는 구조 |
| 12. 개인정보처리방침 반영 | `docs/privacy-policy.html`에 AdMob 데이터 수집 문구 추가(구현 순서 7) |
