# 테마 컬러 커스터마이징 — 설계

> 스펙: [`docs/specs/테마 컬러 커스터마이징.md`](../specs/테마%20컬러%20커스터마이징.md)

## 왜 단순 치환이 안 되는가

`src/theme.ts`의 `colors`는 모듈이 처음 로드될 때 딱 한 번 평가되는 상수 객체다. 화면 15곳(`src/screens/*`, `src/components/*`)이 `StyleSheet.create({...})` 안에서 `colors.primary` 등을 참조하는데, 이 값은 그 시점의 문자열로 그대로 굳어져(freeze) 이후 `colors` 객체를 바꿔도 이미 만들어진 스타일엔 반영되지 않는다. 즉 "탭하면 즉시 전체 화면에 반영"(요구사항 4)을 만족하려면 `colors.primary` 참조를 **렌더 시점에 읽는 값**으로 바꿔야 한다 — React Context + 훅으로 전환하는 이유가 이것이다.

다행히 바뀌는 건 포인트 컬러 5개 롤(`primary/primaryPressed/primarySoft/accent/accentSoft`)과 `buttonShadow`의 `shadowColor`뿐이다(요구사항 5 — 배경·카드·텍스트·경고색은 고정). 정적 스타일(패딩·폰트크기 등)은 그대로 두고, 이 롤을 참조하던 **개별 스타일 속성만** 인라인 오버라이드로 뺀다. 전체 파일을 리팩터링하지 않아도 된다.

### 스와치 배치

스펙엔 "제목 옆"이라 적혀 있지만, 실측해보면 제목("나의 운동 일지") + 도움말 버튼 + 스와치 5개가 한 줄에 다 들어가긴 빠듯하다(작은 화면에서 줄바꿈 위험). 이전에 승인받은 아티팩트와 동일하게 **헤더 블록(제목+부제) 바로 아래, 전체 폭 한 줄**에 배치한다 — "제목 옆" 자리를 헤더 영역 안으로 넓게 해석. 다른 배치를 원하시면 말씀해주세요.

## 상태 설계

- **ThemeProvider (Context)** — 앱 최상단(`App.tsx`)에서 한 번 마운트. 내부 상태: `presetId: ThemePresetId` (`useState`, 초기값 `'default'`).
  - 마운트 시 `useEffect`로 `getThemePreset()`을 불러와 `presetId`를 갱신 (저장된 값이 없으면 `'default'` 유지).
  - `setPresetId(id)` 호출 시: ① state를 즉시 갱신(화면 즉시 반영, 요구사항 3) ② `setThemePreset(id)`를 fire-and-forget으로 호출해 기기에 저장(요구사항 6). 저장 실패는 사용자에게 노출하지 않음 — 다음 실행 시 마지막 성공한 값으로 복원.
- **useAccentColors() 훅** — `useContext(ThemeContext)`를 감싸, 현재 프리셋의 5개 색 + `presetId` + `setPresetId` + `THEME_PRESETS`(스와치 렌더용)를 반환. 화면/컴포넌트는 이 훅 하나만 쓰면 됨.
- 그 외 상태 없음. `spacing/radius/fontSize`와 배경·카드·텍스트 등 고정 색상은 지금처럼 `src/theme.ts`의 정적 export 그대로 — Context를 타지 않는다.

### onPrimary — 밝은 primary 위 텍스트 대비 보정

리뷰에서 발견: 민트(`#00D9A3`)는 매우 밝아서 그 위에 흰 텍스트를 얹으면 명암비가 약 1.8:1로 사실상 안 보인다(WCAG 최소 3:1도 미달). "시작"·"기록 저장"·"운동 추가" 버튼, "최고" 배지 등 `primary`를 배경으로 쓰고 그 위에 텍스트·아이콘을 얹는 모든 자리가 대상이었다.

다른 4개 프리셋은 흰 텍스트로 충분한 대비가 나오는데 민트만 예외라, `primary`(스펙에서 확정한 브랜드 색)를 바꾸는 대신 프리셋마다 `onPrimary`(그 위에 얹을 전경색)를 별도로 정의했다 — 기본/오렌지/레드/블루는 `#FFFFFF`, 민트만 앱 배경색을 재사용한 `#141013`(대비 약 10:1). `colors.white`를 직접 쓰던 자리들을 `accent.onPrimary`로 교체했다(`TimerScreen`, `RepsScreen`, `AddExerciseScreen`, `EditExerciseModal`, `CameraPermissionModal`, `RecordsScreen`의 `BestCard`, `RecordItem`/`RepsRecordItem`의 최고 배지). `buttonDanger`처럼 배경이 `colors.danger`로 고정인 곳은 대상이 아니라 그대로 흰 텍스트를 쓴다.

## 핵심 로직

### 1. ThemeContext.tsx

```ts
// src/lib/ThemeContext.tsx
import { createContext, useContext, useEffect, useRef, useState, ReactNode } from 'react';
import { THEME_PRESETS } from './themePresets';
import { getThemePreset, setThemePreset } from './storage';
import { ThemePresetId, ThemePreset } from './types';

type ThemeContextValue = ThemePreset & {
  presetId: ThemePresetId;
  setPresetId: (id: ThemePresetId) => void;
  presets: ThemePreset[];
};

const ThemeContext = createContext<ThemeContextValue | null>(null);

export function ThemeProvider({ children }: { children: ReactNode }) {
  const [presetId, setPresetIdState] = useState<ThemePresetId>('default');
  // 저장된 값을 불러오는 동안 사용자가 먼저 스와치를 탭하면, 뒤늦게 끝난 로딩 결과가
  // 방금 고른 색을 덮어쓰지 않도록 막는 가드 (QA 중 발견한 경합 수정)
  const userChangedRef = useRef(false);

  useEffect(() => {
    getThemePreset().then((stored) => {
      if (!userChangedRef.current) setPresetIdState(stored);
    });
  }, []);

  const setPresetId = (id: ThemePresetId) => {
    userChangedRef.current = true;
    setPresetIdState(id); // 화면에 즉시 반영
    setThemePreset(id);   // 저장은 백그라운드
  };

  const preset = THEME_PRESETS.find((p) => p.id === presetId) ?? THEME_PRESETS[0];

  return (
    <ThemeContext.Provider value={{ ...preset, presetId, setPresetId, presets: THEME_PRESETS }}>
      {children}
    </ThemeContext.Provider>
  );
}

export function useAccentColors() {
  const ctx = useContext(ThemeContext);
  if (!ctx) throw new Error('useAccentColors must be used within ThemeProvider');
  return ctx;
}
```

### 2. 기존 화면의 전환 패턴

레이아웃 스타일은 그대로 `StyleSheet.create`에 남기고, accent 색을 쓰던 속성만 지워서 렌더 시 인라인으로 합친다.

```tsx
// Before
import { colors } from '../theme';
...
<View style={styles.iconBadge}><Ionicons color={colors.primary} .../></View>
...
const styles = StyleSheet.create({
  iconBadge: { width: 48, height: 48, backgroundColor: colors.primarySoft, ... },
});

// After
import { useAccentColors } from '../lib/ThemeContext';
...
const accent = useAccentColors();
...
<View style={[styles.iconBadge, { backgroundColor: accent.primarySoft }]}>
  <Ionicons color={accent.primary} .../>
</View>
...
const styles = StyleSheet.create({
  iconBadge: { width: 48, height: 48, /* backgroundColor 제거 */ ... },
});
```

`buttonShadow`(그림자 색이 `colors.primary`)는 `...buttonShadow` 스프레드 대신, `theme.ts`에 그림자 모양만 남긴 상수를 두고 `shadowColor`만 인라인으로 덧붙인다:

```ts
// theme.ts: shadowColor 없이 모양만
export const buttonShadowShape = { shadowOffset: {width:0,height:6}, shadowOpacity:0.35, shadowRadius:14, elevation:5 };
```
```tsx
style={[styles.button, buttonShadowShape, { shadowColor: accent.primary }]}
```

### 3. ThemeSwatchRow.tsx

```tsx
export default function ThemeSwatchRow() {
  const { presetId, setPresetId, presets } = useAccentColors();
  return (
    <View style={styles.row}>
      {presets.map((p) => (
        <Pressable
          key={p.id}
          onPress={() => setPresetId(p.id)}
          hitSlop={6}
          accessibilityLabel={`${p.name} 테마로 변경`}
          accessibilityState={{ selected: p.id === presetId }}
          style={[
            styles.dot,
            { backgroundColor: p.primary },
            p.id === presetId && styles.dotActive, // borderColor: colors.text (고정색, accent 아님)
          ]}
        />
      ))}
    </View>
  );
}
```

선택 표시 테두리는 프리셋 색이 아니라 고정된 `colors.text`(다크 배경 기준 밝은색)를 써서 어떤 프리셋을 골라도 항상 또렷하게 보이게 한다 — 아티팩트에서 검증한 방식 그대로.

### 4. storage.ts 추가분

```ts
const THEME_KEY = 'timecheck:theme:v1'; // 기존 키 네이밍 규칙(timecheck: 프리픽스) 그대로 따름

export async function getThemePreset(): Promise<ThemePresetId> {
  const raw = await readJson<ThemePresetId | null>(THEME_KEY, null);
  const valid: ThemePresetId[] = ['default', 'orange', 'mint', 'red', 'blue'];
  return raw && valid.includes(raw) ? raw : 'default';
}

export function setThemePreset(id: ThemePresetId): Promise<void> {
  return AsyncStorage.setItem(THEME_KEY, JSON.stringify(id));
}
```

`enqueueWrite` 큐를 안 써도 되는 이유: 이 키는 다른 값을 읽어와 합치는 read-modify-write가 아니라 단순 덮어쓰기라 동시 호출 충돌 위험이 없다.

## 의존성

추가 패키지 없음. React Context와 기존 `@react-native-async-storage/async-storage`만 사용 — AGENTS.md의 "최소화" 원칙 그대로 유지.

## 구현 순서

1. **데이터 계층**: `types.ts`에 타입 추가 → `themePresets.ts` 작성 → `storage.ts`에 get/setThemePreset 추가. (화면 변경 없음, 타입체크만으로 확인 가능)
2. **ThemeContext.tsx 작성 + App.tsx에 Provider 연결.** 아직 어떤 화면도 훅을 안 쓰므로 앱은 지금과 똑같이 보여야 함 — 이 시점에 `npm run ios`로 회귀 없음을 확인.
3. **ThemeSwatchRow 작성 + HomeScreen 전환** (헤더에 배치, HomeScreen 자체의 accent 참조도 훅으로 교체). 여기서 처음으로 스와치를 눌러 홈 화면 색이 실시간으로 바뀌는 걸 눈으로 확인 — 핵심 동작 검증 지점.
4. **나머지 화면을 순서대로 전환**: AddExerciseScreen/EditExerciseModal → TimerScreen → RepsScreen → RecordsScreen/RecordItem/RepsRecordItem → 남은 소품(GuideVideoPanel, VideoPlayerModal, CaptureVideoRow, CameraPermissionModal, NumberStepper, HelpModal, ExerciseScreen). 화면 단위로 옮길 때마다 그 화면에 들어가 프리셋을 바꿔보며 확인.
5. **잔여 참조 점검**: `grep -rn "colors\.\(primary\|primaryPressed\|primarySoft\|accent\|accentSoft\)\|buttonShadow" src`가 0건이어야 함(모두 훅 기반으로 옮겨졌는지 확인).
6. **마무리 확인**: `npx tsc --noEmit`, 앱 재시작 후 마지막 선택 유지되는지 확인.

## 스펙 요구사항 ↔ 설계 대응

| 스펙 요구사항 | 설계 대응 |
|---|---|
| 1. 스와치 5개 표시(표의 HEX) | `ThemeSwatchRow` + `THEME_PRESETS` |
| 2. 선택 표시 | `ThemeSwatchRow`의 `dotActive` 스타일(고정 `colors.text` 테두리) |
| 3. 탭 즉시 반영 | `setPresetId`가 state를 동기적으로 갱신 → Context 구독 컴포넌트 즉시 리렌더 |
| 4. 전체 화면 일관 반영 | 14개 파일의 accent 참조를 `useAccentColors()`로 통일 전환 |
| 5. 배경/카드/텍스트/경고색 고정 | 해당 색은 Context에 안 넣고 `theme.ts` 정적 export 그대로 유지 |
| 6. 재시작 후 유지 | `ThemeProvider` 마운트 시 `getThemePreset()`으로 복원 |
| 7. 최초 설치 시 기본값 | `presetId` 초기 state `'default'` + `getThemePreset()`의 fallback `'default'` |
| 8. 앱 아이콘 불변 | 이번 설계는 JS 런타임 색상만 다루며 네이티브 아이콘 리소스는 건드리지 않음 |
