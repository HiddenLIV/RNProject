# 무게 있는 운동 최고 기록 볼륨 기준 변경 — 설계

## 화면 구조

새 화면은 없다. 기존 컴포넌트 두 곳에 "볼륨 표기"를 추가한다.

- `src/lib/records.ts` — 볼륨 계산 함수(`totalVolume`, 내부용 `totalVolumeKg`)와 `bestRepsRecord`의 분기 로직 추가
- `src/screens/RecordsScreen.tsx`의 `RepsRecordsScreen` — 최고 기록 카드(`BestCard`)에 넘기는 `value` 문자열을 `usesWeight`일 때 볼륨 포함 문구로 변경
- `src/components/RepsRecordItem.tsx` — 기록 목록의 각 항목 헤더 줄(`t.records.setsAndReps(...)`)을, 그 기록이 무게 기록(`record.weightUnit != null`)이면 볼륨 포함 문구로 변경
- `src/lib/i18n/locales/{ko,en,ja,zh}.ts` — 새 번역 함수 `records.setsRepsVolume` 추가

`TimeRecordsScreen`, `RecordItem`(시간형), `BestCard` 자체 구조는 변경 없음 — 문자열 조립만 호출부에서 분기한다.

## 상태 설계

새 state 없음. `RepsRecordsScreen`은 이미 `exercise`, `records`를 갖고 있어 렌더 시점에 `exercise.usesWeight` 여부로 문자열을 분기하면 된다.

`RepsRecordItem`은 처음에는 새 prop 없이 **레코드 자체의 `weightUnit` 필드**(`record.weightUnit != null`)로 판단하려 했으나, QA 검증 중 다음 불일치가 발견되어 `usesWeight?: boolean` prop을 추가하는 쪽으로 수정했다:
- 운동의 무게 기록을 나중에 **껐을 때** — 과거 기록엔 `weightUnit`이 남아 있어 목록 항목은 계속 볼륨을 보여주는데, 최고 기록 카드(`exercise.usesWeight` 기준)는 볼륨을 감춰 화면 간 기준이 어긋남
- 무게 기록을 나중에 **켰을 때** — 과거 기록엔 `weightUnit`이 없어 목록엔 볼륨이 안 나오는데 그 기록이 최고 기록이면 카드엔 "0kg"으로 표시되는 등 역시 불일치

`RecordsScreen.tsx`가 `RepsRecordItem`에 `usesWeight={exercise.usesWeight}`를 넘기고, `RepsRecordItem`은 `BestCard`와 동일하게 **운동 설정(`usesWeight`)만을 기준**으로 분기한다 — `record.weightUnit`은 (있으면) 단위 라벨을 고르는 데만 쓰고, 없으면 기존 `formatSet`과 같은 방식으로 kg으로 대체한다.

## 데이터 모델

새 타입 없음. 기존 `RepsRecord`/`RepsSet`을 그대로 쓴다. `records.ts`에 비교용 환산 상수만 추가(스펙 요구사항 4, 변경 없음):

```ts
const LB_TO_KG = 0.45359237;
```

## 핵심 로직

`src/lib/records.ts`:

```ts
function toKg(weight: number, unit?: 'kg' | 'lb'): number {
  return unit === 'lb' ? weight * LB_TO_KG : weight;
}

// 세트별 (무게×횟수)의 합. 화면에 그대로 보여줄 수 있도록 record 저장 당시 단위 기준 값을
// 반환한다(요구사항 7 — kg로 강제 환산하지 않음). 부동소수점 합산 오차 방지를 위해 소수 둘째
// 자리에서 반올림한다. 무게 없는 세트(weight undefined)는 0으로 취급(요구사항 3).
export function totalVolume(record: RepsRecord): number {
  const raw = record.sets.reduce((sum, s) => sum + (s.weight ?? 0) * s.reps, 0);
  return Math.round(raw * 100) / 100;
}

// bestRepsRecord 내부 비교 전용 — 단위가 다른 기록끼리도 정확히 비교할 수 있도록 kg으로
// 환산한다(요구사항 4). 화면에는 절대 이 값을 쓰지 않는다(totalVolume을 쓴다).
function totalVolumeKg(record: RepsRecord): number {
  return toKg(totalVolume(record), record.weightUnit);
}

export function bestRepsRecord(
  records: RepsRecord[],
  resetAt?: string,
  usesWeight?: boolean,
): RepsRecord | null {
  const pool = resetAt ? records.filter((r) => r.measuredAt >= resetAt) : records;
  if (pool.length === 0) return null;
  return usesWeight
    ? pool.reduce((best, r) => (totalVolumeKg(r) > totalVolumeKg(best) ? r : best))
    : pool.reduce((best, r) => (totalReps(r) > totalReps(best) ? r : best));
}
```

- 요구사항 1·2·5·6: 기존 설계와 동일(변경 없음) — `usesWeight` 분기, `resetAt` 필터 유지, 저장 로직 무변경.
- 요구사항 3: `s.weight ?? 0`.
- 요구사항 4: 비교는 `totalVolumeKg`(kg 환산)로만 하고, 화면 표시용 `totalVolume`은 환산하지 않는다 — 두 함수를 분리한 이유.
- 요구사항 7: `totalVolume(record)`가 "저장 당시 단위 그대로의 볼륨"을 반환하므로, 이 값과 `record.weightUnit`을 그대로 화면에 넘긴다.

## 의존성

새 패키지 없음.

## 구현 순서

1. `src/lib/records.ts`에 `toKg`, `totalVolume`, `totalVolumeKg` 추가하고 `bestRepsRecord`에 `usesWeight?: boolean` 추가·분기
2. `src/lib/records.test.ts`에 무게 포함 헬퍼(`weightedRepsRecord`) 추가 후 케이스 보강:
   - 볼륨 큰(횟수 적은) 기록이 선택되는 케이스 / 볼륨 작은(횟수 많은) 기록이 선택 안 되는 케이스
   - `usesWeight` false/undefined일 때 기존과 동일한 결과(회귀 없음)
   - 무게 없는 세트가 0으로 계산되는 케이스
   - kg/lb 혼합 기록 비교 케이스
   - `resetAt` + `usesWeight` 조합 케이스
   - `totalVolume()`이 record 자체 단위 기준(환산 없이) 값을 반환하는 케이스
3. `npm test` 통과 확인
4. `src/lib/i18n/locales/{ko,en,ja,zh}.ts`에 `records.setsRepsVolume` 추가, `Translations` 타입(`en.ts` 기준 타입 소스라면 그쪽)도 갱신
5. `src/screens/RecordsScreen.tsx` — `bestRepsRecord` 호출부 인자 추가, `BestCard`용 `value` 조립 분기 추가
6. `src/components/RepsRecordItem.tsx` — 헤더 줄 문자열 조립 분기 추가
7. `npx tsc --noEmit`, 수정한 파일 대상 `npx eslint`
8. 에뮬레이터에서 무게 있는 운동으로: (a) "무게↓횟수↑" 후 "무게↑횟수↓" 기록 저장 시 최고 기록이 후자로 옮겨가며 볼륨 문구가 함께 보이는지, (b) 목록의 각 기록 항목에도 볼륨이 표시되는지, (c) 무게 없는 운동은 기존처럼 볼륨 없이 세트·횟수만 보이는지 수동 확인

## 요구사항 대응 확인

| 스펙 요구사항 | 설계 반영 위치 |
|---|---|
| 1. usesWeight=true는 볼륨 기준 판정 | `bestRepsRecord`의 `usesWeight` 분기 → `totalVolumeKg` |
| 2·3. usesWeight=false는 기존 유지, 화면도 볼륨 미노출 | `else` 분기(`totalReps`) + `RepsRecordItem`/`BestCard` 문자열 분기 조건(`weightUnit`/`usesWeight` 없으면 기존 문구) |
| 3(세트). 무게 없는 세트는 0 | `s.weight ?? 0` (`totalVolume`) |
| 4. 단위 다르면 환산 후 비교, 표시는 원 단위 | 비교 전용 `totalVolumeKg` vs 표시 전용 `totalVolume` 분리 |
| 5. 리셋 기능 유지 | `pool` 필터 로직 변경 없음 |
| 6. 기존 데이터 미수정 | 저장 로직 무변경, 조회 시점 계산 유지 |
| 7. 최고 기록 카드 + 목록에 볼륨 표시(저장 당시 단위) | `RecordsScreen.tsx`(BestCard value), `RepsRecordItem.tsx`(헤더 줄) |
| 8. 4개 언어 i18n 반영 | `ko/en/ja/zh.ts`에 `setsRepsVolume` 추가 |
