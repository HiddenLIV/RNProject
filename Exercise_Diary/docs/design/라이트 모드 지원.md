# 라이트 모드 지원 — 설계

> 스펙: [`docs/specs/라이트 모드 지원.md`](../specs/라이트%20모드%20지원.md)

## 기존 구조와의 관계

"테마 컬러 커스터마이징" 기능에서 이미 같은 문제(정적 `StyleSheet.create`에 색이 굳어버리는 문제)를 `ThemeContext`/`useAccentColors()` 훅으로 풀어뒀다. 이번 기능은 그 훅이 다루는 범위를 **포인트 컬러(accent) 롤 6개**에서 **배경·카드·텍스트 같은 베이스 톤 11개**까지 넓히는 확장이다 — 새 아키텍처를 만드는 게 아니라 같은 패턴을 반복 적용한다.

지금 `src/theme.ts`의 `colors.background/card/cardMuted/text/textMuted/textFaint/border/danger/dangerSoft/white/shadow`는 여전히 정적 상수이고, 앱 전체 19개 파일·124곳에서 이 값을 `StyleSheet.create()` 모듈 스코프에 직접 박아 쓰고 있다. 라이트/다크는 기기 설정에 따라 **런타임에** 바뀌어야 하므로, accent 때와 마찬가지로 이 참조들을 렌더 시점에 읽는 값으로 바꿔야 한다.

## 화면 구조

새 화면 없음. 다음 파일만 변경한다.

| 파일 | 변경 |
|---|---|
| `app.json` | `expo.userInterfaceStyle`를 `"dark"` → `"automatic"`으로 변경 (네이티브 설정 — 이후 리빌드 필요) |
| `src/lib/types.ts` | `ColorScheme`, `BaseColors` 타입 추가 |
| `src/theme.ts` | 정적 `colors` export를 제거하고 `DARK_COLORS`/`LIGHT_COLORS`(둘 다 `BaseColors`)로 교체. 이미 안 쓰인 지 오래된 `primary/primaryPressed/primarySoft/accent/accentSoft` 레거시 필드(테마 컬러 기능에서 남겨뒀던 참고용 상수)도 이 참에 제거 |
| `src/lib/ThemeContext.tsx` | `useColorScheme()`(react-native)로 시스템 설정을 읽어 `DARK_COLORS`/`LIGHT_COLORS` 중 하나를 accent 프리셋과 합쳐 반환 |
| `App.tsx` | 컨테이너 배경을 훅 값으로 전환, `<StatusBar style="light" />` → `style="auto"` |
| 아래 18개 파일 | `colors.background/card/...` 정적 참조를 훅 값으로 전환 (레이아웃은 그대로) |

18개: `HomeScreen`, `ExerciseScreen`, `RecordsScreen`, `RepsScreen`, `TimerScreen`, `AddExerciseScreen`, `EditExerciseModal`, `CameraPermissionModal`, `CaptureVideoRow`, `GuideVideoPanel`, `HelpModal`, `NumberStepper`, `RecordItem`, `RepsRecordItem`, `VideoPlayerModal`, `ThemeSwatchRow`, `MeasureTypeTag`, `TimeDisplay` (뒤 두 개는 지금 accent 훅을 안 쓰던 파일이라 새로 훅 호출을 추가해야 함).

### 훅을 다시 쪼개지 않는 이유

`useAccentColors()` 하나에 베이스 톤까지 얹어 반환 타입만 넓힌다 (훅 이름·기존 호출부의 지역 변수명 `accent`는 그대로 둔다). 별도 `useBaseColors()` 훅을 새로 만들면 이미 15곳에서 호출 중인 `useAccentColors()`와 함께 두 번씩 호출해야 해서 diff와 실수 여지만 늘어난다. 단점은 "accent"라는 이름에 배경색까지 들어있어 이름이 정확히 맞진 않는다는 것 — 실용성을 택한 트레이드오프로, 나중에 이름이 거슬리면 `useThemeColors()` 등으로 리네임만 하면 된다(로직 변경 없음).

## 상태 설계

- **색 스킴(라이트/다크) 자체는 저장하지 않는다.** `react-native`의 `useColorScheme()`은 시스템 설정을 실시간 구독하는 훅이라, 값을 들고 있거나 AsyncStorage에 저장할 필요가 없다 — 스펙 요구사항 3("실행 중 즉시 반영")이 이 훅의 기본 동작만으로 충족된다.
- `ThemeProvider` 안에서 `useColorScheme()`이 반환하는 `'light' | 'dark' | null | undefined` 중 `'light'`가 아니면 전부 `'dark'`로 취급(안전한 기본값 — 지금까지의 다크 전용 동작과 동일).
- 포인트 컬러 프리셋(`presetId`) 상태는 지금처럼 그대로 유지 — 색 스킴과 완전히 독립된 별개 상태라 서로 간섭하지 않는다(요구사항 5).

## 데이터 모델

```ts
// src/lib/types.ts에 추가
export type ColorScheme = 'light' | 'dark';

export type BaseColors = {
  background: string;
  card: string;
  cardMuted: string;
  text: string;
  textMuted: string;
  textFaint: string;
  border: string;
  danger: string;
  dangerSoft: string;
  white: string;
  shadow: string;
};
```

```ts
// src/theme.ts — 기존 colors를 대체
export const DARK_COLORS: BaseColors = {

```

라이트 팔레트는 다크 팔레트와 같은 "따뜻한 중립(살짝 마젠타 쪽으로 치우친 그레이)" 톤을 유지해, 모드를 바꿔도 같은 앱처럼 느껴지게 잡은 제안값이다 — `/dev`에서 실제 화면 보며 조정 가능.

**accent 프리셋(5종)의 `primary/primaryPressed/accent/onPrimary`는 라이트/다크 공통으로 지금 값 그대로 쓴다.** 브랜드 컬러 자체는 배경이 밝든 어둡든 안 바뀌는 게 자연스럽고, `onPrimary`는애초에 "그 색 위에 얹는 글자색"이라 페이지 배경과 무관하기 때문이다. 다만 `primarySoft`/`accentSoft`(다크 배경과 섞어 만든 "은은한 틴트")는 이번엔 손대지 않고 다크용 값을 라이트 모드에서도 그대로 재사용한다 — 아이콘 배지 등이 라이트 화면에서 미묘한 틴트 대신 살짝 또렷한 색 배지로 보이는 정도의 차이이고, 스펙의 제외 범위("색상 팔레트 전환 외 구조 변경 없음")에 맞춰 범위를 좁힌 의도적 단순화다. `/dev` 단계에서 실제로 어색해 보이면 그때 다시 논의.

## 핵심 로직

### 1. app.json

```jsonc
"userInterfaceStyle": "automatic"  // 기존 "dark"에서 변경
```

이 값이 "dark"로 고정된 채로는 OS가 앱을 강제로 다크로만 인식해 JS의 `useColorScheme()`도 항상 `'dark'`만 반환한다. **네이티브 설정이라 JS 변경만으론 반영되지 않고, 안드로이드 매니페스트를 다시 생성하는 리빌드(`npx expo run:android`, 또는 최소 `npx expo prebuild`)가 필요하다.**

확인해둔 사실: `android/app/src/main/AndroidManifest.xml`의 `MainActivity`에 이미 `android:configChanges="...|uiMode|..."`가 포함돼 있어, 시스템 다크/라이트를 바꿔도 액티비티가 재시작되지 않고 `useColorScheme()` 값만 갱신된다 — 요구사항 3(재시작 없이 즉시 반영)이 추가 설정 없이 충족된다.

### 2. ThemeContext.tsx 확장

```ts
import { useColorScheme } from 'react-native';
import { DARK_COLORS, LIGHT_COLORS } from '../theme';
import { BaseColors, ColorScheme } from './types';

type ThemeContextValue = ThemePreset & BaseColors & {
  presetId: ThemePresetId;
  setPresetId: (id: ThemePresetId) => void;
  presets: ThemePreset[];
  colorScheme: ColorScheme;
};

export function ThemeProvider({ children }: { children: ReactNode }) {
  // ...presetId 관련 기존 로직 그대로...

  const systemScheme = useColorScheme();
  const colorScheme: ColorScheme = systemScheme === 'light' ? 'light' : 'dark';
  const base = colorScheme === 'light' ? LIGHT_COLORS : DARK_COLORS;

  const preset = THEME_PRESETS.find((p) => p.id === presetId) ?? THEME_PRESETS[0];

  return (
    <ThemeContext.Provider value={{ ...base, ...preset, presetId, setPresetId, presets: THEME_PRESETS, colorScheme }}>
      {children}
    </ThemeContext.Provider>
  );
}
```

`useAccentColors()` 함수 자체는 이름·시그니처 변경 없음 — 반환 타입만 넓어진다.

### 3. 기존 화면의 전환 패턴 (accent 때와 동일)

```tsx
// Before
import { colors } from '../theme';
...
<View style={styles.card}>...
const styles = StyleSheet.create({
  card: { backgroundColor: colors.card, borderColor: colors.border, ... },
});

// After
import { useAccentColors } from '../lib/ThemeContext';
...
const accent = useAccentColors();
...
<View style={[styles.card, { backgroundColor: accent.card, borderColor: accent.border }]}>...
const styles = StyleSheet.create({
  card: { /* backgroundColor, borderColor 제거 */ ... },
});
```

`MeasureTypeTag.tsx`, `TimeDisplay.tsx`는 지금 accent 훅을 안 쓰므로 `const accent = useAccentColors();` 호출을 새로 추가한다. `App.tsx`는 `AppContent` 함수 안에서 훅을 호출해 `SafeAreaView`의 배경색을 인라인으로 덧붙이고, `<StatusBar style="auto" />`로 바꾼다(라이트/다크에 맞는 상태표시줄 아이콘 색을 expo-status-bar가 알아서 고름 — 요구사항 7).

## 의존성

추가 패키지 없음. `useColorScheme`은 `react-native` 코어에 이미 포함돼 있다 — AGENTS.md 최소화 원칙 유지.

## 구현 순서

1. **app.json 변경 + 리빌드**: `userInterfaceStyle`을 `automatic`으로 바꾸고 `npx expo run:android`로 다시 설치. 이 시점엔 아직 JS가 안 바뀌었으니 화면은 그대로 다크로 보여야 함(회귀 확인) — 다만 기기를 라이트로 바꿔도 아직 앱은 안 바뀌는 게 정상(JS 미반영 상태).
2. **타입 + 팔레트 데이터**: `types.ts`에 `ColorScheme`/`BaseColors` 추가 → `theme.ts`를 `DARK_COLORS`/`LIGHT_COLORS`로 교체. (아직 아무도 안 씀 — 타입체크만으로 확인)
3. **ThemeContext.tsx 확장**: `useColorScheme()` 연결, context 값에 베이스 톤 병합. 아직 화면들은 예전 `colors.xxx` 정적 참조라 눈에 보이는 변화 없음 — 이 시점에 `npx tsc --noEmit`으로 타입 오류(특히 `colors` import가 사라진 곳)부터 정리.
4. **App.tsx 전환**: 컨테이너 배경 인라인화 + `StatusBar style="auto"`. 기기를 라이트로 바꿔보면 최상위 배경만 밝아지고 그 안 화면들은 아직 다크로 보이는 과도기 상태 — 배선이 제대로 됐는지 확인하는 지점.
5. **화면을 하나씩 전환**: HomeScreen → ExerciseScreen/TimerScreen/RepsScreen/RecordsScreen → AddExerciseScreen/EditExerciseModal → 나머지 소품(NumberStepper, RecordItem, RepsRecordItem, CameraPermissionModal, CaptureVideoRow, GuideVideoPanel, HelpModal, VideoPlayerModal, ThemeSwatchRow, MeasureTypeTag, TimeDisplay). 화면 하나 옮길 때마다 기기 설정을 라이트⇄다크로 토글해 그 화면이 잘 따라가는지 확인.
6. **잔여 참조 점검**: `grep -rn "colors\." src App.tsx`가 (theme.ts 자체 정의 제외하고) 0건이어야 함.
7. **마무리 확인**: `npx tsc --noEmit`, 라이트/다크 각각에서 앱 전체를 훑으며 텍스트 가독성 확인, 실행 중 시스템 설정 전환이 재시작 없이 반영되는지 확인, 포인트 컬러 프리셋이 두 모드 모두에서 정상 동작하는지 확인.

## 스펙 요구사항 ↔ 설계 대응

| 스펙 요구사항 | 설계 대응 |
|---|---|
| 1. 시스템 다크 → 앱 다크 | `useColorScheme()` 결과가 `'dark'`(또는 null/undefined 폴백)일 때 `DARK_COLORS` 적용 |
| 2. 시스템 라이트 → 앱 라이트 | `useColorScheme()`이 `'light'`일 때 `LIGHT_COLORS` 적용 |
| 3. 실행 중 전환 시 재시작 없이 반영 | `useColorScheme()`이 실시간 구독 훅 + AndroidManifest의 `uiMode` configChanges 확인 완료 |
| 4. 라이트·다크 모두 충분한 대비 | `LIGHT_COLORS`/`DARK_COLORS` 값 설계 (제안값, `/dev`에서 조정 가능) |
| 5. 포인트 컬러 프리셋 5종이 양쪽 모드에서 동작·유지 | `presetId` 상태가 `colorScheme`과 독립적으로 관리됨 |
| 6. 앱 내 수동 토글 없음 | 별도 UI·저장 로직을 추가하지 않음 — `useColorScheme()` 결과를 그대로 반영 |
| 7. 상태표시줄 자동 전환 | `<StatusBar style="auto" />` |
