# 측정 화면에서 자세 안내 영상 링크 수정·삭제 — 설계

직전 기능("측정 화면에서 자세 안내 영상 링크 추가")이 만든 구조를 그대로 확장한다. 새 화면·새 컴포넌트 파일은 없다.

## 화면 구조

- `src/components/GuideVideoPanel.tsx` — 수정. 링크가 있을 때(토글 버튼) 그 옆에 수정(연필) 아이콘을 추가한다. 탭하면 기존 "추가" 폼과 같은 모양의 입력 폼이 펼쳐지되, 현재 링크가 미리 채워져 있고 삭제 버튼이 추가로 보인다.
- `src/screens/ExerciseScreen.tsx` — 수정. 직전 기능에서 추가한 `handleGuideVideoSaved(guideVideoId: string)`을 `handleGuideVideoChange(guideVideoId: string | undefined)`로 일반화한다 (저장=문자열, 삭제=undefined를 같은 콜백 하나로 처리).
- `src/screens/TimerScreen.tsx`, `src/screens/RepsScreen.tsx` — 수정. prop 이름을 `onGuideVideoSaved` → `onGuideVideoChange`로 맞춰 그대로 통과시킨다.
- `src/lib/i18n/locales/*.ts` — `guideVideoPanel` 네임스페이스에 키 3개 추가(수정 아이콘 접근성 라벨, 삭제 확인 팝업 제목·본문). 나머지 문구(입력란 placeholder, 검증 실패 메시지, 저장·취소·삭제 버튼 라벨)는 기존 `editExercise`/`common` 네임스페이스 키를 그대로 재사용한다.

## 상태 설계

`GuideVideoPanel` 내부 폼 관련 state를 불리언 2개(`addingLink`/`editingLink`)에서 **3방향 열거값 하나**로 정리한다 — "추가 폼도 열려 있고 수정 폼도 열려 있는" 불가능한 상태가 애초에 만들어지지 않게 한다.

```ts
type FormMode = 'closed' | 'add' | 'edit';
const [formMode, setFormMode] = useState<FormMode>('closed');
const [linkText, setLinkText] = useState('');
const [linkError, setLinkError] = useState('');
const [expanded, setExpanded] = useState(false); // 기존 — 플레이어 펼침 여부, 폼과 무관
```

저장된 값 자체는 여전히 로컬로 들고 있지 않는다(직전 기능의 개정 설계를 그대로 따름) — `ExerciseScreen.exerciseState`가 진실이고, `GuideVideoPanel`은 `videoId` prop을 그대로 읽어 렌더링하며 변경 시 `onGuideVideoChange`로 알리기만 한다. 타이머 단계 전환·탭 전환에도 결과가 유지되는 이유(스펙 요구사항 9)는 직전 기능 설계 문서에 적어둔 것과 동일하다: `ExerciseScreen`이 이 두 unmount 경로 모두에서 계속 떠 있는 지점이기 때문이다.

## 데이터 모델

새 타입은 필요 없다. `Exercise.guideVideoId?: string`(기존), `updateExercise(id, patch)`(기존)를 그대로 쓴다. 삭제는 `updateExercise(exerciseId, { guideVideoId: undefined })` 호출로 표현한다 — `EditExerciseModal`이 링크를 빈 문자열로 저장할 때와 동일한 매커니즘(patch에서 `undefined`로 덮어쓰면 저장 시 JSON 직렬화 과정에서 키 자체가 사라짐, `storage.ts`의 기존 동작 그대로).

```ts
// GuideVideoPanel.tsx
type Props = {
  exerciseId: string;
  videoId?: string;
  onGuideVideoChange: (guideVideoId: string | undefined) => void; // 기존 onSaved를 대체
};
```

번역 스키마에 추가되는 키 3개:
```ts
guideVideoPanel: {
  toggleLabel: string;        // 기존
  addLinkLabel: string;       // 기존
  editAccessibility: string;  // 신규 — 수정 아이콘의 accessibilityLabel, 예: "링크 수정"
  deleteConfirmTitle: string; // 신규 — 삭제 확인 팝업 제목
  deleteConfirmBody: string;  // 신규 — 삭제 확인 팝업 본문
}
```
재사용하는 기존 키: `t.editExercise.videoLinkPlaceholder`, `t.editExercise.errorInvalidVideoLink`, `t.editExercise.save`, `t.editExercise.cancel`(폼의 저장/취소 버튼), `t.common.cancel`/`t.common.delete`(삭제 확인 팝업 버튼 + 폼 안의 삭제 버튼 라벨).

## 핵심 로직

`extractYoutubeVideoId`(기존), `updateExercise`(기존)를 그대로 재사용한다. 저장·취소 핸들러는 추가 폼과 수정 폼이 공유한다 — 둘의 차이는 진입 시점에 `linkText`를 비워두는지 현재 링크로 채워두는지, 그리고 폼 안에 삭제 버튼이 보이는지뿐이다.

```ts
// GuideVideoPanel.tsx 내부
const openAddForm = () => {
  setFormMode('add');
  setLinkText('');
  setLinkError('');
};

const openEditForm = () => {
  setExpanded(false); // 펼쳐져 있던 플레이어가 있으면 접는다
  setFormMode('edit');
  setLinkText(videoId ? `https://youtu.be/${videoId}` : ''); // EditExerciseModal과 동일한 프리필 방식
  setLinkError('');
};

const closeForm = () => {
  setFormMode('closed');
  setLinkText('');
  setLinkError('');
};

const handleSave = async () => {
  const id = extractYoutubeVideoId(linkText);
  if (!id) {
    setLinkError(t.editExercise.errorInvalidVideoLink);
    return;
  }
  await updateExercise(exerciseId, { guideVideoId: id });
  onGuideVideoChange(id);
  closeForm();
};

const handleDeletePress = () => {
  Alert.alert(t.guideVideoPanel.deleteConfirmTitle, t.guideVideoPanel.deleteConfirmBody, [
    { text: t.common.cancel, style: 'cancel' },
    {
      text: t.common.delete,
      style: 'destructive',
      onPress: async () => {
        await updateExercise(exerciseId, { guideVideoId: undefined });
        onGuideVideoChange(undefined);
        closeForm();
      },
    },
  ]);
};
```

렌더 분기 (`formMode`가 최우선, 그다음 `videoId` 유무):
```tsx
if (formMode !== 'closed') {
  return (
    <Form>
      <TextInput value={linkText} .../>
      {linkError && <ErrorText />}
      <ButtonRow>
        {formMode === 'edit' && <DeleteButton onPress={handleDeletePress} />}
        <CancelButton onPress={closeForm} />
        <SaveButton onPress={handleSave} />
      </ButtonRow>
    </Form>
  );
}

if (!videoId) {
  return <AddLinkButton onPress={openAddForm} />; // 기존 그대로
}

return (
  <>
    <Row>
      <ToggleButton onPress={() => setExpanded((v) => !v)} />  {/* 기존 그대로, flex:1로 폭 확보 */}
      <EditIconButton onPress={openEditForm} accessibilityLabel={t.guideVideoPanel.editAccessibility} />
    </Row>
    {expanded && <Player />}
  </>
);
```

## 의존성

없음. `react-native`의 `Alert`(신규 import, 다른 화면들에서 이미 쓰는 컴포넌트)만 추가로 import한다. `extractYoutubeVideoId`, `updateExercise`, 기존 훅들 재사용.

## 구현 순서

1. `locales/en.ts`에 `guideVideoPanel.editAccessibility`/`deleteConfirmTitle`/`deleteConfirmBody` 키 추가 → `ko`/`ja`/`zh`에도 채우기 (타입 체크로 누락 확인)
2. `GuideVideoPanel.tsx`의 `addingLink` 불리언을 `formMode: FormMode`로 교체하고, 기존 "추가" 흐름이 `formMode === 'add'` 기준으로 동일하게 동작하는지 확인 (회귀 방지)
3. 링크 있을 때의 토글 버튼 옆에 수정 아이콘 추가, `openEditForm`으로 `formMode: 'edit'` 진입 + 현재 링크 프리필 연결 → 수정 폼이 뜨는지, 필드가 채워지는지 확인
4. 폼 안에 `formMode === 'edit'`일 때만 보이는 삭제 버튼 추가, `handleDeletePress`(Alert 확인) + 확인 시 삭제 로직 연결
5. `Props`를 `onSaved` → `onGuideVideoChange: (id: string | undefined) => void`로 변경, `handleSave`/삭제 콜백 모두 이 함수 호출로 통일
6. `ExerciseScreen.tsx`의 `handleGuideVideoSaved`를 `handleGuideVideoChange(guideVideoId: string | undefined)`로 일반화, `TimerScreen`/`RepsScreen`에 새 이름으로 전달
7. `TimerScreen.tsx`, `RepsScreen.tsx`의 prop 이름과 `<GuideVideoPanel onGuideVideoChange={...} />` 호출부 갱신
8. `npx tsc --noEmit` 확인 후, 실기기/시뮬레이터에서 수정 저장·삭제·취소 각각 확인, 타이머 1회 측정 후·기록 탭 전환 후에도 결과가 유지되는지, 홈 화면 수정 모달에도 반영되는지 확인

## 스펙 요구사항 대응

| 스펙 요구사항 | 설계 대응 |
|---|---|
| 1. 링크 있으면 토글 옆 수정 아이콘 | `videoId` 있을 때의 `Row` 렌더 (`EditIconButton`) |
| 2. 탭하면 프리필된 입력폼+삭제/취소/저장 | `openEditForm` → `formMode: 'edit'` |
| 3. 유튜브 형식 아니면 거부+안내 | `handleSave`의 `extractYoutubeVideoId` 검증 (추가 폼과 동일 로직 공유) |
| 4. 유효 링크 저장 시 갱신+토글 복귀 | `handleSave` → `onGuideVideoChange(id)` → `ExerciseScreen.exerciseState` 갱신 |
| 5. 삭제 시 확인 팝업, 확인해야 삭제 | `handleDeletePress`의 `Alert.alert` destructive 버튼 |
| 6. 취소 시 변경 없이 원래 토글 복귀 | `closeForm` (linkText/linkError만 초기화, `updateExercise` 미호출) |
| 7. 타이머·세트 화면 둘 다 동일 동작 | 컴포넌트 하나(`GuideVideoPanel`)를 양쪽이 공유 |
| 8. 홈 수정 모달에도 동일 반영 | 같은 `updateExercise`/저장소 키 (별도 저장소 없음) |
| 9. 타이머 1회·탭 전환 후에도 유지 | `ExerciseScreen.exerciseState`가 두 unmount 경로 모두에서 유지 (직전 기능과 동일 메커니즘) |
| 10. 기존 "추가" 흐름 무변화 | `formMode === 'add'` 분기는 로직 변경 없이 진입 조건만 열거값으로 정리 |
