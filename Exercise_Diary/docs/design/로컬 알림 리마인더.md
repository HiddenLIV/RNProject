# 로컬 알림 리마인더 — 설계

## 화면 구조

새 화면은 없다. 기존 설정 바텀시트(`SettingsSheetContent`)에 새 섹션 하나를 추가한다 — 포인트 컬러·화면 모드·백업/복원과 같은 자리에, 같은 패턴(`섹션 라벨 + 독립적으로 storage를 읽고 쓰는 컴포넌트`)으로 얹는다.

| 위치                                                | 역할                                                                                                               |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `src/components/SettingsSheetContent.tsx` (수정)    | 새 섹션 `<ReminderSettingsSection />` 한 줄 추가                                                                   |
| `src/components/ReminderSettingsSection.tsx` (신규) | 켜기/끄기 토글, 방식 선택(세그먼트 2개), 알림 시각 네이티브 피커, N일 스테퍼. 권한 흐름까지 이 컴포넌트가 책임진다 |
| `src/lib/notifications.ts` (신규)                   | 권한 조회/요청, 안드로이드 채널 생성, 예약·취소 로직                                                               |

**권한 거부/차단 안내에 대한 수정(QA 중 발견)**: 처음엔 `CameraPermissionModal.tsx`를 본떠 전용 `<Modal>` 컴포넌트(`NotificationPermissionModal.tsx`)를 만들었으나, `ReminderSettingsSection`은 항상 설정 바텀시트(`BottomSheet.tsx`)의 `<Modal>` 안에서만 렌더된다는 점을 놓쳤다 — iOS는 이미 present된 Modal 위에 또 다른 Modal을 present하면 조용히 실패한다(`BottomSheet.tsx`·`alert.ts`에 이미 문서화된 제약). `CameraPermissionModal`은 항상 전체 화면(Timer/RepsScreen)에서만 쓰여 이 제약을 안 받았던 것과 다르다. 이 코드베이스는 정확히 이 상황을 위해 `src/lib/alert.ts`의 `showAlert()`(BottomSheet가 마운트해 둔 `<AlertHost embedded />`가 대신 받는다)를 이미 갖추고 있었으므로, 전용 Modal 컴포넌트 대신 `showAlert(title, body, buttons)`를 호출하는 방식으로 바꿨다. `NotificationPermissionModal.tsx`는 삭제.

**재예약 직렬화 큐의 실패 처리에 대한 수정(코드 리뷰 중 발견)**: `updateAndReschedule`이 반환하는 프로미스 체인이 한 번이라도 reject되면 `rescheduleQueueRef.current`에 rejected 상태가 남아, 그 뒤로는 `.then()`이 전부 건너뛰어져 이 화면이 떠 있는 동안 저장·재예약이 조용히 전부 무시되는 상태에 빠질 수 있었다. 세그먼트·시각 피커·스테퍼처럼 반환값을 기다리지 않는 호출부에서는 unhandled rejection도 발생했다. `updateAndReschedule`이 항상 `.catch(() => {})`로 감싼(항상 fulfilled인) 프로미스를 큐에 남기고 그것을 그대로 반환하도록 고쳤다 — 알림 예약 실패를 사용자 흐름까지 전파하지 않는 건 `notifyReminderRecordSaved`와 같은 기존 관례다.

**N일간 미기록 모드의 재무장(코드 리뷰 중 발견)**: N일 모드는 `SchedulableTriggerInputTypes.DATE`(1회성) 트리거라, 알림이 한 번 울린 뒤 사용자가 계속 기록을 안 남기면 재예약할 계기가 전혀 없었다(설정 변경도 새 기록도 없으므로) — 정작 이 기능이 겨냥하는 "습관이 끊긴 사용자"에게 정확히 이 문제가 생긴다. 진짜 백그라운드 재예약(`expo-task-manager` 등 별도 네이티브 백그라운드 작업)은 이번 기능 범위를 넘어서므로, 최소한의 완화책으로 앱을 다시 열 때마다(`App.tsx` 콜드 스타트) 저장된 설정 기준으로 예약을 다시 계산해 미는 `resyncReminderSchedule()`(`notifications.ts`)을 추가했다. `computeDaysSinceTarget`이 이미 지난 시각은 "다음으로 돌아오는 hour:minute"으로 앞당기므로, 앱을 열 때마다 최소한 그 시점 기준으로 재무장된다. 사용자가 앱을 아예 다시 열지 않는 경우까지는 커버하지 못한다 — 완전한 해결은 후속 과제(로드맵)로 남긴다.

**시각 선택 UI에 대한 결정**: `@react-native-community/datetimepicker`로 네이티브 시간 피커를 쓴다(사용자 요청 반영). `DESIGN.md`의 Don't 목록을 "시스템 시간/날짜 피커는 예외적으로 네이티브 그대로 쓸 수 있다"로 함께 갱신했다 — 커스텀으로 다시 만드는 비용 대비 이점이 낮고, 사용자에게 이미 익숙한 OS 표준 입력이라는 이유다. 플랫폼별로 렌더링 방식이 다르다:

- **iOS**: `display="compact"` — 항상 작은 버튼 형태로 떠 있고, 탭하면 시스템이 알아서 팝오버를 띄운다. 별도의 열림/닫힘 상태 관리가 필요 없다.
- **Android**: `display="default"` — 값을 보여주는 `Pressable`을 탭해야 다이얼로그가 뜨는 방식이라, "피커를 지금 띄울지"를 로컬 state(`pickerOpen`) 하나로 관리하고 `onChange`의 `event.type`이 `'set'`일 때만 값을 반영한다.

N일(며칠 뒤 알릴지)은 시각이 아니라 개수이므로 이 예외 대상이 아니다 — 기존과 동일하게 `NumberStepper`(1~14)를 그대로 쓴다.

## 상태 설계

| 상태                                         | 위치                                                                                                                                                                                                                                             | 수명                                                                                                            |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| `ReminderSettings`(켜짐 여부·방식·시·분·N일) | `ReminderSettingsSection`의 로컬 `useState`, 마운트 시 `getReminderSettings()`로 초기화                                                                                                                                                          | 화면에 머무는 동안 즉시 반영, 변경마다 `saveReminderSettings()`로 영구 저장                                     |
| 재예약 직렬화 큐                             | `ReminderSettingsSection`의 로컬 `useRef(Promise.resolve())`                                                                                                                                                                                     | 컴포넌트 생애주기 내내 — 매 `updateAndReschedule` 호출이 이 체인 뒤에 이어붙는다(QA 중 발견한 동시성 버그 수정) |
| 권한 거부/차단 안내                          | 로컬 state 없음 — 전역 `showAlert()`를 즉시 호출해 표시(BottomSheet의 embedded `AlertHost`가 받는다)                                                                                                                                             | 알림 하나의 생애주기(사용자가 버튼을 누르면 사라짐), 컴포넌트 state로 추적하지 않는다                           |
| 예약된 알림 자체                             | OS(iOS `UNUserNotificationCenter` / Android `AlarmManager`)가 들고 있다 — 앱 프로세스가 꺼져 있어도 살아남는다. 앱은 "무엇이 예약돼 있는지"를 따로 추적하지 않고, 설정이 바뀔 때마다 전부 취소하고 새로 예약하는 방식으로 항상 설정과 일치시킨다 |                                                                                                                 |

## 데이터 모델

`src/lib/types.ts`에 추가:

```ts
export type ReminderMode = 'dailyTime' | 'daysSinceLastRecord';

export type ReminderSettings = {
  enabled: boolean;
  mode: ReminderMode;
  hour: number; // 0~23
  minute: number; // 0~59 (UI는 5분 단위로만 고르게 하지만 타입 자체엔 제약을 두지 않는다)
  daysSinceLastRecord: number; // 1~14 — mode가 'daysSinceLastRecord'일 때만 의미 있음
};

export const DEFAULT_REMINDER_SETTINGS: ReminderSettings = {
  enabled: false,
  mode: 'dailyTime',
  hour: 20,
  minute: 0,
  daysSinceLastRecord: 3,
};

export const REMINDER_MINUTE_STEP = 5;
export const REMINDER_DAYS_MIN = 1;
export const REMINDER_DAYS_MAX = 14;
```

`src/lib/storage.ts`에 추가 (기존 `voiceGuideEnabled`와 같은 앱 전체 공통 키 하나):

```ts
const REMINDER_SETTINGS_KEY = 'timecheck:reminderSettings:v1';

export async function getReminderSettings(): Promise<ReminderSettings> {
  const raw = await readJson<Partial<ReminderSettings>>(REMINDER_SETTINGS_KEY, {});
  return { ...DEFAULT_REMINDER_SETTINGS, ...raw };
}

export function saveReminderSettings(settings: ReminderSettings): Promise<void> {
  return AsyncStorage.setItem(REMINDER_SETTINGS_KEY, JSON.stringify(settings));
}

// N일간 미기록 모드의 기준 시각 — 시간형·횟수형을 가리지 않고 모든 운동을 통틀어
// 가장 최근 기록의 measuredAt을 찾는다. 기록이 하나도 없으면 null.
export async function getMostRecentRecordAt(): Promise<string | null> {
  const exercises = await getExercises();
  const allDates = (
    await Promise.all(
      exercises.map(async (e) => {
        const [records, repsRecords] = await Promise.all([getRecords(e.id), getRepsRecords(e.id)]);
        return [...records, ...repsRecords].map((r) => r.measuredAt);
      }),
    )
  ).flat();
  if (allDates.length === 0) return null;
  return allDates.reduce((latest, d) => (d > latest ? d : latest));
}
```

(ISO 8601 문자열은 사전순 비교가 시간순 비교와 같으므로 `Date` 파싱 없이 문자열 비교만으로 최댓값을 구한다.)

`getReminderSettings`는 다른 앱 전체 설정처럼 백업 파일에 포함하지 않는다 — 스펙 자체가 "앱을 지웠다 다시 깔면 유지되지 않는다"(시나리오 10)고 명시했고, 알림 예약은 기기 로컬 OS 상태이지 옮겨 다닐 데이터가 아니다. `backup.ts`/`BackupPayload`는 건드리지 않는다.

## 핵심 로직

### `src/lib/notifications.ts`

```ts
import * as Notifications from 'expo-notifications';
import { Platform } from 'react-native';
import { getMostRecentRecordAt, getReminderSettings } from './storage';
import { ReminderSettings } from './types';

export type NotificationPermissionState = 'granted' | 'undetermined' | 'denied' | 'blocked';

// video.ts의 getVideoPermissionState와 같은 매핑 규칙 — canAskAgain이 false면 '다시 묻지 않음'으로
// 영구 거부된 상태이므로 OS 설정으로 보내야 한다.
export async function getNotificationPermissionState(): Promise<NotificationPermissionState> {
  const { granted, canAskAgain, status } = await Notifications.getPermissionsAsync();
  if (granted) return 'granted';
  if (canAskAgain === false) return 'blocked';
  if (status === 'undetermined') return 'undetermined';
  return 'denied';
}

export async function requestNotificationPermission(): Promise<boolean> {
  const { granted } = await Notifications.requestPermissionsAsync();
  return granted;
}

// 안드로이드 8+는 채널이 있어야 알림을 보낼 수 있다 — 앱 시작 시 한 번 호출(멱등).
export async function ensureAndroidChannelAsync(): Promise<void> {
  if (Platform.OS !== 'android') return;
  await Notifications.setNotificationChannelAsync('reminders', {
    name: 'Reminders',
    importance: Notifications.AndroidImportance.DEFAULT,
  });
}

// 기본값(핸들러 미설정)은 앱이 포그라운드일 때 알림을 표시하지 않는다(QA 중 발견) — 앱을
// 이미 열어 쓰는 중에 리마인더가 도착해도 배너로 보이게 앱 시작 시 한 번 등록한다.
export function registerNotificationHandler(): void {
  Notifications.setNotificationHandler({
    handleNotification: async () => ({
      shouldShowBanner: true,
      shouldShowList: true,
      shouldPlaySound: true,
      shouldSetBadge: false,
    }),
  });
}

// N일간 미기록 모드의 다음 발송 시각을 계산한다. "기준일 + N일, 그날의 hour:minute"이
// 이미 과거라면(설정을 켠 시점에 이미 N일이 지나 있던 경우 등) 다음으로 hour:minute이 돌아오는
// 시점까지 앞당긴다 — 최소 지금부터 1분 뒤.
function computeDaysSinceTarget(baseIso: string, days: number, hour: number, minute: number): Date {
  const base = new Date(baseIso);
  const target = new Date(base);
  target.setDate(target.getDate() + days);
  target.setHours(hour, minute, 0, 0);

  const now = Date.now();
  if (target.getTime() <= now) {
    target.setTime(now);
    target.setHours(hour, minute, 0, 0);
    if (target.getTime() <= now) target.setDate(target.getDate() + 1);
  }
  return target;
}

// 설정과 "가장 최근 기록 시각"을 받아 예약을 현재 상태와 일치시킨다. 무엇이 이미 예약돼
// 있었는지 추적하지 않고 항상 전부 취소 후 다시 예약한다 — 이 앱에 알림 기능이 이거 하나뿐이라
// 다른 예약과 뒤섞일 일이 없고, 상태 불일치보다 단순함을 우선한다.
export async function applyReminderSchedule(
  settings: ReminderSettings,
  lastRecordAt: string | null,
): Promise<void> {
  await Notifications.cancelAllScheduledNotificationsAsync();
  if (!settings.enabled) return;

  if (settings.mode === 'dailyTime') {
    await Notifications.scheduleNotificationAsync({
      content: { title: DAILY_TITLE, body: DAILY_BODY }, // 4개 언어 문구는 구현 시 i18n에서 가져온다
      trigger: {
        type: Notifications.SchedulableTriggerInputTypes.DAILY,
        hour: settings.hour,
        minute: settings.minute,
      },
    });
    return;
  }

  const baseIso = lastRecordAt ?? new Date().toISOString();
  const target = computeDaysSinceTarget(
    baseIso,
    settings.daysSinceLastRecord,
    settings.hour,
    settings.minute,
  );
  await Notifications.scheduleNotificationAsync({
    content: { title: DAYS_SINCE_TITLE, body: DAYS_SINCE_BODY },
    trigger: { type: Notifications.SchedulableTriggerInputTypes.DATE, date: target },
  });
}

// 시간형·횟수형 어느 쪽이든 새 기록이 저장된 직후 호출한다 — N일간 미기록 모드일 때만
// "지금을 기준으로 N일 뒤"로 예약을 다시 민다(카운트 리셋). 다른 경우는 즉시 반환한다.
export async function notifyReminderRecordSaved(): Promise<void> {
  const settings = await getReminderSettings();
  if (!settings.enabled || settings.mode !== 'daysSinceLastRecord') return;
  await applyReminderSchedule(settings, new Date().toISOString());
}
```

(`DAILY_TITLE` 등은 실제로는 호출 시점에 `useTranslation()`으로 가져온 문구를 파라미터로 넘긴다 — 이 함수들은 화면 밖 순수 로직이라 훅을 직접 쓸 수 없으므로, `applyReminderSchedule`은 문구를 인자로 받는 시그니처로 만들고 `ReminderSettingsSection`이 `t.reminder.*`를 채워 넘긴다. 구현 시 정확한 시그니처를 정한다.)

### 호출 지점 — "새 기록 저장" 훅

`notifyReminderRecordSaved()`는 기록이 실제로 저장되는 두 지점에서 호출한다(둘 다 이미 이 앱에서 모든 운동을 아우르는 유일한 저장 경로다):

- **시간형**: `src/lib/useTimerResult.ts`의 `save()`가 `addRecord`를 호출하는 분기, `adjust()`가 `addRecord`/`updateRecord`를 호출하는 분기.
- **횟수형**: `src/screens/RepsScreen.tsx`의 `handleSave()`가 `addRepsRecord` 저장에 성공한 직후.

`storage.ts` 자체에는 훅을 걸지 않는다 — 이 코드베이스는 이미 "저장 직후 부수효과(햅틱 등)는 호출부에서, `storage.ts`는 순수 데이터 계층으로 유지"하는 규칙을 따르고 있고(예: `notifySuccess()`가 항상 화면 쪽에서 호출됨), `storage.ts`가 `notifications.ts`를 참조하면 `notifications.ts` → `storage.ts`(설정 조회용) 역참조와 맞물려 순환 참조가 생긴다.

### 설정 변경 → 재예약

`ReminderSettingsSection`의 모든 변경 핸들러(토글/방식/시/분/일수)는 공통 함수 하나를 거친다:

```ts
// 세그먼트·시각 피커·스테퍼를 빠르게 연달아 조작하면 각 호출의 cancelAll+schedule이 겹쳐
// 실행될 수 있어(QA 중 발견) 컴포넌트 로컬 useRef(Promise.resolve())에 항상 이어붙이는
// 방식으로 직렬화한다 — 이전 재예약이 끝난 뒤에만 다음 재예약이 시작된다.
function updateAndReschedule(next: ReminderSettings) {
  setSettings(next); // 화면 즉시 반영
  rescheduleQueueRef.current = rescheduleQueueRef.current
    .then(() => saveReminderSettings(next))
    .then(() => getMostRecentRecordAt())
    .then((lastRecordAt) => applyReminderSchedule(next, lastRecordAt));
  return rescheduleQueueRef.current;
}
```

### 토글 on 흐름 (권한 게이트)

```
사용자가 토글 on
  → getNotificationPermissionState()
    - 'granted'         → updateAndReschedule({ ...settings, enabled: true })
    - 'blocked'         → showAlert(설정으로 안내), 토글은 꺼짐 유지
    - 'undetermined'/'denied' → requestNotificationPermission()
        - 허용됨 → updateAndReschedule({ ...settings, enabled: true })
        - 거부됨 → showAlert(재조회한 상태 기준), 토글은 꺼짐 유지
          (이 알림에서도 다시 거부되면 재조회한 상태로 showAlert를 다시 띄운다)
```

## 의존성

- **`expo-notifications`** (신규, 필수) — 로컬 알림 예약·취소·권한의 유일한 API. 대체 불가.
- **`@react-native-community/datetimepicker`** (신규) — 알림 시각을 고르는 네이티브 시간 피커. `DESIGN.md`에 추가한 예외 규칙에 따라 커스텀으로 다시 만들지 않고 그대로 쓴다.
- N일(며칠 뒤 알릴지)은 기존 `NumberStepper` 재사용, 별도 패키지 불필요.
- **네이티브 재빌드 필요**: 이 프로젝트는 `android/`·`ios/`가 `.gitignore` 대상인 CNG(Continuous Native Generation) 구조라, `expo-notifications`·`@react-native-community/datetimepicker`처럼 네이티브 코드가 있는 모듈을 추가하면 `npm run android`만으로는 반영되지 않는다. `app.json`의 `plugins`에 `"expo-notifications"`를 추가한 뒤(데이트피커는 별도 config plugin이 없어 plugins 배열에 넣지 않는다) `npx expo prebuild`로 네이티브 프로젝트를 다시 생성해야 한다(자세한 순서는 아래).

## 구현 순서

1. **패키지 + 설정 파일**: `npx expo install expo-notifications @react-native-community/datetimepicker`, `app.json` `plugins`에 `"expo-notifications"` 추가. `npx expo prebuild`로 네이티브 프로젝트 재생성 후 `npm run android`로 정상 빌드되는지만 확인(아직 기능 없음).
2. **데이터 모델 + storage**: `types.ts`에 `ReminderSettings` 등 추가, `storage.ts`에 `getReminderSettings`/`saveReminderSettings`/`getMostRecentRecordAt` 추가. `npx tsc --noEmit`.
3. **`notifications.ts` 핵심 로직**: 권한 조회/요청, 채널 생성, `applyReminderSchedule`, `computeDaysSinceTarget`. 이 시점엔 임시로 콘솔 로그나 실제 문구를 하드코딩해 함수 자체가 옳게 예약되는지 실기기에서 확인(기기 알림 설정 > 예약된 알림 목록으로 확인 가능한 플랫폼도 있고, 아니면 시각을 1~2분 뒤로 짧게 잡아 실제로 울리는지 확인).
4. **`NotificationPermissionModal` + i18n**: `CameraPermissionModal`을 참고해 작성, 4개 언어 키 추가.
5. **`ReminderSettingsSection`**: 토글·방식 세그먼트·네이티브 시각 피커(iOS `compact`/Android `default`+state)·N일 스테퍼 UI, 권한 흐름 연결. `SettingsSheetContent`에 얹어 설정 바텀시트에서 눈으로 확인 — 두 플랫폼(에뮬레이터/시뮬레이터) 모두에서 피커가 정상 동작하는지 확인.
6. **"새 기록 저장" 훅 연결**: `useTimerResult.ts`, `RepsScreen.tsx`에 `notifyReminderRecordSaved()` 호출 추가. N일 모드를 켜둔 채 기록을 저장하면 예약이 뒤로 밀리는지 확인.
7. **App.tsx**: 시작 시 `ensureAndroidChannelAsync()`·`registerNotificationHandler()`·`resyncReminderSchedule()` 호출 추가(`initializeAds()` 등과 같은 자리).
8. **최종 점검**: 두 모드 각각 실기기에서 실제로 알림이 오는지, 권한 거부/차단 흐름, 토글 껐을 때 취소되는지, 앱 재시작 후 설정 유지 확인.

## 신규 i18n 키 (`t.reminder` 아래)

| 키                                                                | 용도                                 |
| ----------------------------------------------------------------- | ------------------------------------ |
| `enabledLabel`                                                    | 토글 라벨                            |
| `modeDailyTimeLabel` / `modeDaysSinceLabel`                       | 방식 세그먼트 라벨                   |
| `timeLabel`                                                       | 시각 피커 위 섹션 라벨("알림 시각")  |
| `daysLabel`                                                       | N일 스테퍼 라벨                      |
| `dailyNotificationTitle` / `dailyNotificationBody`                | 매일 모드 알림 문구                  |
| `daysSinceNotificationTitle(days)` / `daysSinceNotificationBody`  | N일 모드 알림 문구(제목에 일수 삽입) |
| `permissionTitle` / `permissionBody`                              | 권한 안내 모달 문구                  |
| `permissionGrant` / `permissionOpenSettings` / `permissionCancel` | 권한 안내 모달 버튼                  |

## 스펙 요구사항 ↔ 설계 대응표

| 스펙 요구사항                          | 설계에서 충족되는 위치                                                                                                                                                               |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1. 토글 기본 꺼짐                      | `DEFAULT_REMINDER_SETTINGS.enabled = false`                                                                                                                                          |
| 2. 켜졌을 때만 세부 설정 노출          | `ReminderSettingsSection`의 `settings.enabled` 조건부 렌더링                                                                                                                         |
| 3. 매일 모드 시:분 선택, 기본 20:00    | `@react-native-community/datetimepicker`(`mode="time"`) + `DEFAULT_REMINDER_SETTINGS.hour/minute`                                                                                    |
| 4. N일 모드 일수(1~14, 기본 3) + 시:분 | `REMINDER_DAYS_MIN/MAX` + `NumberStepper`(일수) + 네이티브 시간 피커(시:분) + 기본값                                                                                                 |
| 5. 권한 없을 때 요청                   | 토글 on 흐름의 `requestNotificationPermission()`                                                                                                                                     |
| 6. 거부 시 설정 안내, 토글 꺼짐 유지   | 토글 on 흐름의 `blocked`/거부 분기 → `showAlert()`, `updateAndReschedule` 미호출                                                                                                     |
| 7. 매일 모드 매일 발송                 | `SchedulableTriggerInputTypes.DAILY`                                                                                                                                                 |
| 8. N일 모드, 전체 운동 기준            | `getMostRecentRecordAt()`(모든 운동의 records+repsRecords 통합) + `computeDaysSinceTarget`                                                                                           |
| 9. 새 기록 저장 시 카운트 리셋         | `notifyReminderRecordSaved()` → `useTimerResult`/`RepsScreen` 호출 지점                                                                                                              |
| 10. 기록 없을 때 켠 시점 기준          | `notifyReminderRecordSaved`가 아닌 `updateAndReschedule`의 `getMostRecentRecordAt()`이 `null` 반환 시 `applyReminderSchedule`의 `baseIso = lastRecordAt ?? new Date().toISOString()` |
| 11. 설정 변경 시 재예약                | `updateAndReschedule`이 매 변경마다 `applyReminderSchedule` 호출(내부에서 `cancelAllScheduledNotificationsAsync` 선행)                                                               |
| 12. 토글 끄면 즉시 취소                | `updateAndReschedule({ enabled: false })` → `applyReminderSchedule`의 `cancelAll` 후 `return`                                                                                        |
| 13. 알림 탭 시 앱 열림                 | 로컬 알림의 기본 OS 동작(추가 구현 불필요)                                                                                                                                           |
| 14. 앱 전체 공통 설정                  | 운동 id와 무관한 단일 저장 키(`REMINDER_SETTINGS_KEY`)                                                                                                                               |
| 15. 재시작 후 유지                     | AsyncStorage 영구 저장                                                                                                                                                               |
| 16. 4개 언어 번역                      | `t.reminder.*` 키를 en/ko/ja/zh 모두 추가                                                                                                                                            |
