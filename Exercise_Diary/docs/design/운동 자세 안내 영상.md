# 운동 자세 안내 영상 — 설계

스펙: `docs/specs/운동 자세 안내 영상.md` (요구사항 1~6)

## 화면 구조

| 파일 | 역할 |
|---|---|
| `src/lib/youtube.ts` | **(신규)** `extractYoutubeVideoId(input): string \| null` — watch/youtu.be/shorts 링크에서 11자리 영상 ID를 뽑아낸다. 형식이 아니면 `null`. |
| `src/components/GuideVideoPanel.tsx` | **(신규)** `videoId?: string`를 받아 링크 없으면 아무것도 렌더링하지 않고, 있으면 "자세 영상 보기" 토글 버튼 + 펼쳤을 때의 `YoutubePlayer`를 보여준다. `TimerScreen`(idle 단계)과 `RepsScreen` 양쪽에서 재사용. |
| `src/screens/AddExerciseScreen.tsx` | (수정) 이름 입력 아래에 "자세 영상 링크(선택)" `TextInput` 추가, 저장 시 `extractYoutubeVideoId`로 검증 |
| `src/components/EditExerciseModal.tsx` | (수정) 같은 입력란 추가. 기존 값이 있으면 `https://youtu.be/<id>` 형태로 프리필 |
| `src/screens/TimerScreen.tsx` | (수정) idle 단계 상단에 `<GuideVideoPanel videoId={exercise.guideVideoId} />` 삽입 |
| `src/screens/RepsScreen.tsx` | (수정) 세트 시트 위에 `<GuideVideoPanel videoId={exercise.guideVideoId} />` 삽입 |
| `src/lib/types.ts` | (수정) `Exercise`에 `guideVideoId?: string` 추가 |

## 상태 설계

- **`GuideVideoPanel`**: `expanded: boolean` 로컬 state(초기값 `false`)만 자체적으로 갖는다. `videoId`가 없으면(falsy) `null`을 반환해 아무것도 렌더링하지 않는다 — 요구사항 4("링크 없으면 버튼 자체가 안 보임")를 컴포넌트 안에서 그대로 보장한다.
  - 요구사항 6(화면 전환 시 접힌 상태로 초기화)은 별도 로직이 필요 없다 — `ExerciseScreen`이 탭 전환 시 `TimerScreen`/`RepsScreen`을 조건부 렌더링으로 언마운트하고(`{tab === 'measure' ? ... : <RecordsScreen />}`), `App.tsx`도 홈으로 나가면 `ExerciseScreen` 자체를 언마운트한다(기존 "운동 커스터마이징" 설계와 동일한 이유). `GuideVideoPanel`도 함께 언마운트되므로 다시 들어오면 `expanded`가 항상 `false`로 시작한다.
- **`AddExerciseScreen`**: 로컬 state `videoLinkText: string`(초기값 `''`) 추가. 저장 시에만 검증(기존 이름 검증과 동일한 타이밍 — 입력 중엔 형식을 따지지 않는다).
- **`EditExerciseModal`**: 로컬 state `videoLinkText: string`, `exercise`가 바뀔 때(`useEffect`, 기존 `name`/`usesWeight` 초기화와 같은 곳) `exercise.guideVideoId ? \`https://youtu.be/${exercise.guideVideoId}\` : ''`로 초기화.

## 데이터 모델

```ts
// src/lib/types.ts
export type Exercise = {
  id: string;
  name: string;
  icon: keyof typeof Ionicons.glyphMap;
  measureType: MeasureType;
  usesWeight?: boolean;
  weightUnit?: 'kg' | 'lb';
  builtin: boolean;
  guideVideoId?: string; // 유튜브 영상 ID(11자리). 없으면 자세 영상 버튼이 안 보인다
};
```

원본 링크 전체가 아니라 **추출된 영상 ID만** 저장한다 — 재생 시 매번 다시 파싱할 필요가 없고, 저장 형식이 항상 짧고 일정하다. 수정 화면에서 편집할 때는 `https://youtu.be/<id>`로 재구성해 보여준다(다시 저장해도 같은 ID로 파싱되어 원형 유지).

## 핵심 로직

1. **링크 파싱** (요구사항 3) — `src/lib/youtube.ts`:
   ```ts
   const PATTERNS = [
     /youtube\.com\/watch\?[^#]*\bv=([\w-]{11})/,
     /youtu\.be\/([\w-]{11})/,
     /youtube\.com\/shorts\/([\w-]{11})/,
   ];

   export function extractYoutubeVideoId(input: string): string | null {
     const trimmed = input.trim();
     if (!trimmed) return null;
     for (const re of PATTERNS) {
       const match = trimmed.match(re);
       if (match) return match[1];
     }
     return null;
   }
   ```
   RN의 `URL` 전역 파서에 기대지 않고 정규식만 쓴다 — Hermes/신규 아키텍처에서의 `URL` 지원 여부와 무관하게 동작하고, 의존성도 늘지 않는다.

2. **저장 시 검증** (요구사항 1~3) — `AddExerciseScreen.handleAdd`/`EditExerciseModal.handleSave` 양쪽에서 동일한 패턴:
   ```ts
   const trimmedLink = videoLinkText.trim();
   let guideVideoId: string | undefined;
   if (trimmedLink) {
     const id = extractYoutubeVideoId(trimmedLink);
     if (!id) {
       setError('유튜브 영상 링크 형식이 아닙니다 (watch, youtu.be, shorts 링크만 지원)');
       return;
     }
     guideVideoId = id;
   }
   ```
   빈 문자열이면 `guideVideoId`는 `undefined` — 기존 `weightUnit: usesWeight ? weightUnit : undefined` 패턴과 동일하게, 지운 경우 `updateExercise`의 patch에 `guideVideoId: undefined`가 그대로 들어가 필드가 사라진다(요구사항 2 "삭제").

3. **영상 표시/재생** (요구사항 4~5) — `GuideVideoPanel`:
   ```tsx
   export default function GuideVideoPanel({ videoId }: { videoId?: string }) {
     const [expanded, setExpanded] = useState(false);
     if (!videoId) return null;
     return (
       <View style={styles.container}>
         <Pressable style={styles.toggle} onPress={() => setExpanded((v) => !v)}>
           <Ionicons name={expanded ? 'chevron-up' : 'play-circle-outline'} size={18} color={colors.primary} />
           <Text style={styles.toggleText}>자세 영상 보기</Text>
         </Pressable>
         {expanded && (
           <View style={styles.player}>
             <YoutubePlayer height={200} videoId={videoId} />
           </View>
         )}
       </View>
     );
   }
   ```
   `react-native-youtube-iframe`가 내부적으로 `react-native-webview`의 `WebView`에 유튜브 iframe API를 로드해 재생한다 — 자동재생 없이(요구사항 제외범위) 기본 컨트롤로 사용자가 직접 재생 버튼을 누른다.

4. **배치 위치** — `TimerScreen`은 `timer.phase === 'idle'`일 때만(측정 중엔 방해되지 않게) 제목 아래·설정 카드 위에 배치. `RepsScreen`은 세트 시트 위, 화면 최상단에 배치.

## 의존성

- `react-native-webview` — `npx expo install react-native-webview`로 설치 (Expo SDK 버전에 맞는 버전을 자동으로 맞춰줌)
- `react-native-youtube-iframe` — Expo 레지스트리에 없는 커뮤니티 패키지라 `npm install react-native-youtube-iframe`로 설치 (위 webview를 peer dependency로 사용)
- **확인 필요**: 이 프로젝트는 RN 0.86(신규 아키텍처) 기반이다. 두 패키지 모두 신규 아키텍처를 지원하는 버전인지 설치 직후 최소 렌더링(`GuideVideoPanel`에 아무 영상 ID나 하드코딩해 시뮬레이터에서 실제로 펼쳐지고 재생되는지)으로 제일 먼저 확인한다 — 안 되면 이 설계 문서의 `GuideVideoPanel` 내부 구현만 바꾸면 되고(예: 순수 WebView로 직접 embed URL을 로드), 나머지 화면 구조·데이터 모델은 영향받지 않는다.

## 구현 순서

각 단계 끝에서 기존 기능(측정·기록)이 깨지지 않았는지 확인한다.

1. **의존성 설치 + 최소 동작 확인** — `react-native-webview`, `react-native-youtube-iframe` 설치 후, 테스트용 영상 ID를 하드코딩한 `GuideVideoPanel`을 아무 화면에나 임시로 띄워 실제로 펼쳐지고 재생되는지 시뮬레이터에서 먼저 확인한다 (구조를 더 짓기 전에 가장 리스크 큰 부분부터 검증).
2. **데이터 계층** — `types.ts`에 `guideVideoId` 추가, `src/lib/youtube.ts` 작성. 타입 체크.
3. **`GuideVideoPanel` 컴포넌트** — 1번에서 만든 임시 코드를 정식 컴포넌트로 옮긴다.
4. **운동 추가/수정에 링크 입력 추가** — `AddExerciseScreen`, `EditExerciseModal`에 입력란 + 검증. 잘못된 형식 거부, 빈 문자열 허용, 기존 값 프리필까지 확인.
5. **측정 화면에 삽입** — `TimerScreen`(idle 단계), `RepsScreen` 상단에 배치. 링크 있는 운동/없는 운동 각각에서 버튼 노출 여부, 펼치기·접기, 탭 전환 후 재진입 시 접힌 상태로 초기화되는지 확인.
6. `npx tsc --noEmit` + 실기기 확인 → `/qa`.
