# 다국어 지원 — 설계

## 화면 구조

새 화면은 없다 (스펙에서 수동 언어 전환 UI를 제외했으므로). 대신 번역 데이터와 이를 읽는 공용 훅을 새로 만들고, 기존 화면·컴포넌트가 하드코딩된 한국어 문자열 대신 이 훅을 통해 문구를 가져오도록 고친다.

### 새로 추가하는 파일

```
src/lib/i18n/
  types.ts        # SupportedLanguage, Translations 타입
  locales/
    en.ts         # 기준(source of truth) — 번역 스키마의 실제 구조를 정의
    ko.ts
    ja.ts
    zh.ts
  detectLanguage.ts  # expo-localization으로 기기 언어 → SupportedLanguage 매핑
  speechLocale.ts    # SupportedLanguage → expo-speech 언어 코드, 화면 언어별 "시작" 낱말
  LanguageContext.tsx  # LanguageProvider, useTranslation(), useLanguage() 훅
  index.ts           # 위 항목 재export (다른 코드는 'src/lib/i18n'에서만 import)
```

### 대체(내용 이전) 및 삭제하는 기존 파일

- `src/lib/quotes.ts` → 내용을 4개 로케일 파일의 `quotes` 배열로 이전 후 파일 삭제, `TimerScreen`은 `useTranslation()`으로 획득
- `src/lib/helpContent.ts` → `HelpSection`의 `title`/`description`을 로케일 파일의 `help.sections`로 이전, `icon`만 언어 무관 상수 배열(`HELP_ICONS`)로 남겨 `HelpModal`에서 `icon`은 상수에서, 텍스트는 `t.help.sections`에서 인덱스로 매칭

### 문구를 옮겨야 하는 기존 화면/컴포넌트 (하드코딩 한국어 → `useTranslation()`)

`HomeScreen`, `AddExerciseScreen`, `TimerScreen`, `RepsScreen`, `RecordsScreen`, `EditExerciseModal`, `CameraPermissionModal`, `HelpModal`, `MeasureTypeTag`, `RecordItem`, `RepsRecordItem`, `NumberStepper`, `GuideVideoPanel`, `CaptureVideoRow`, `VideoPlayerModal`, `App.tsx`(뒤로가기 관련 텍스트가 있다면)

## 상태 설계

- **언어 값 자체는 컴포넌트 로컬 state나 AsyncStorage에 두지 않는다.** 스펙에서 수동 전환·기기 언어 변경 시 즉시 반영을 요구하지 않으므로, 앱 시작 시 `expo-localization`으로 한 번 감지해 앱 생명주기 동안 고정되는 값으로 취급한다 (기기 언어를 바꾸면 앱을 재시작해야 반영 — 스펙의 제외 범위와 일치).
- `LanguageProvider`(신규, `App.tsx` 최상단에서 `ThemeProvider`와 나란히 마운트)가 앱 시작 시 1회 `detectLanguage()`를 호출해 `SupportedLanguage` 값을 계산하고, React Context로 하위에 내려준다. `ThemeContext.tsx`처럼 `getThemePreset()` 비동기 로딩 패턴이 필요 없다 — 동기 함수이므로 초기 `useState` 값으로 바로 계산해 첫 렌더부터 확정된 언어로 그린다 (로딩 중 깜빡임 없음).
- `useTranslation()` 훅: `LanguageContext`에서 현재 언어를 읽어 그 언어의 번역 객체(`Translations`)를 반환한다. 컴포넌트는 `const t = useTranslation()` 한 줄로 `t.home.title`처럼 중첩 프로퍼티 접근만 하면 되고, 문자열 키 조회(`t('home.title')`) 방식은 쓰지 않는다 — 오타가 곧 TS 컴파일 에러가 되어 4개 언어 전부 같은 구조를 갖도록 강제된다.
- `useLanguage()` 훅: 현재 `SupportedLanguage` 코드만 필요한 곳(예: `feedback.ts`에 넘길 음성 언어 코드) 용도로 별도 제공.
- 화면별 로컬 state(예: `AddExerciseScreen`의 입력값)는 지금처럼 그대로 두되, placeholder·에러 메시지 등 화면에 보여줄 문자열만 `t`에서 가져오도록 교체한다.

## 데이터 모델

```ts
// src/lib/i18n/types.ts
export type SupportedLanguage = 'ko' | 'en' | 'ja' | 'zh';
export const SUPPORTED_LANGUAGES: SupportedLanguage[] = ['ko', 'en', 'ja', 'zh'];
export const DEFAULT_LANGUAGE: SupportedLanguage = 'en';

// locales/en.ts가 구조의 기준. `as const`를 쓰지 않아 다른 로케일이 같은 타입으로
// 다른 문자열 값을 넣을 수 있게 한다.
const en = {
  common: {
    save: 'Save', cancel: 'Cancel', delete: 'Delete', edit: 'Edit', add: 'Add', confirm: 'Confirm',
  },
  measureType: { time: 'Time', reps: 'Reps & Sets' },
  units: { seconds: 'sec', reps: 'reps', sets: 'sets', kg: 'kg', lb: 'lb' },
  weekdays: ['Sun', 'Mon', 'Tue', 'Wed', 'Thu', 'Fri', 'Sat'],
  exercisePresets: {
    hang: 'Dead Hang', plank: 'Plank', pullup: 'Pull-up',
    pushup: 'Push-up', squat: 'Squat', lunge: 'Lunge',
  },
  home: { title: 'Exercise Diary', subtitle: 'Pick an exercise to begin', addExercise: 'Add Exercise', help: 'Help' },
  addExercise: { /* 화면 문구·검증 메시지 */ },
  editExercise: {
    deleteTitle: 'Delete Exercise',
    deleteBody: (name: string) => `Delete "${name}" and all of its records?`,
    /* ... */
  },
  timer: {
    speechStart: 'Start', // TTS로 읽을 "시작" 낱말
    captureFailedTitle: 'Recording Failed',
    captureFailedBody: 'Could not save the video. Please try again.',
    permissionFailedBody: 'Could not verify permission. Please try again.',
    /* ... */
  },
  reps: { /* ... */ },
  records: { title: 'Records', empty: 'No records yet.\nFinish a set to record your first one.', best: 'Best' },
  help: {
    sections: [
      { title: 'Add Exercise', description: '...' },
      // helpContent.ts의 6개 섹션과 1:1 대응 (아이콘 제외)
    ],
  },
  cameraPermission: { /* ... */ },
  quotes: ['Quit now, and you\'ll only find excuses.', /* 총 100개 */],
};

export type Translations = typeof en;

// locales/ko.ts / ja.ts / zh.ts
const ko: Translations = { /* en과 동일 구조, 값만 한국어 */ };
export default ko;
```

- `Exercise` 타입(`src/lib/types.ts`)에 선택 필드 추가: `presetKey?: PresetKey` (`PresetKey`는 `'hang' | 'plank' | 'pullup' | 'pushup' | 'squat' | 'lunge'`, `exercisePresets.ts`에서 export). 프리셋으로 추가된 운동은 이 값을 저장해, 나중에 언어가 바뀌어도 이름을 다시 그 언어로 표시할 수 있게 한다. 직접 입력한 운동은 `presetKey`가 없고 `name`을 그대로 표시한다(번역 대상 아님, 스펙 요구사항 6).
- **기존 데이터 호환**: `presetKey` 필드가 없던 과거 버전에서 이미 저장된 프리셋 기반 운동(예: 예전 한국어 프리셋 이름이 그대로 `name`에 박제된 "매달리기", "턱걸이" 등)을 위해, `inferPresetKey(name: string): PresetKey | undefined` 헬퍼를 두어 옛 한국어 프리셋 이름 문자열과 정확히 일치하면 해당 `PresetKey`로 간주한다. 화면에 이름을 표시할 때는 항상 `getExerciseDisplayName(exercise, t)` 헬퍼를 통하는데, 이 헬퍼는 `exercise.presetKey ?? inferPresetKey(exercise.name)`이 있으면 `t.exercisePresets[key]`를, 없으면 `exercise.name`을 그대로 반환한다. AsyncStorage 데이터 자체를 마이그레이션(덮어쓰기)하지는 않는다 — 표시 시점에만 매핑하므로 안전하고 되돌리기도 쉽다.
- 새로 프리셋을 추가할 때(`AddExerciseScreen`)는 `addExercise`에 `presetKey: preset.key`와 함께, 하위 호환·중복이름 검사용으로 그 시점 언어의 번역된 이름을 `name`에도 스냅샷으로 저장한다.

## 핵심 로직

### 언어 감지 (`detectLanguage.ts`)

```ts
import * as Localization from 'expo-localization';

export function detectLanguage(): SupportedLanguage {
  const codes = Localization.getLocales().map((l) => l.languageCode);
  return codes.find((c): c is SupportedLanguage => SUPPORTED_LANGUAGES.includes(c as SupportedLanguage))
    ?? DEFAULT_LANGUAGE;
}
```
기기 우선순위 언어 목록(`getLocales()`가 사용자가 기기에 설정한 순서대로 반환)에서 지원 언어와 처음 일치하는 것을 쓰고, 없으면 영어로 폴백한다 (요구사항 1·2).

### 프리셋 이름 표시 (`exercisePresets.ts`)

`getExerciseDisplayName(exercise, t)` — 위 데이터 모델 절에서 설명한 대로, `presetKey`(저장값 또는 레거시 이름 추론)가 있으면 번역된 이름을, 없으면 저장된 `name`을 그대로 반환. `HomeScreen`, `TimerScreen`/`RepsScreen` 제목, `EditExerciseModal` 등 운동 이름을 보여주는 모든 곳이 `item.name` 대신 이 헬퍼를 쓰도록 교체한다.

### 음성 안내 언어 (`feedback.ts` 수정)

```ts
const SPEECH_LOCALE: Record<SupportedLanguage, string> = {
  ko: 'ko-KR', en: 'en-US', ja: 'ja-JP', zh: 'zh-CN',
};

function speak(text: string, language: SupportedLanguage) {
  Speech.stop();
  Speech.speak(text, { language: SPEECH_LOCALE[language] });
}

export function speakCountdown(remainingSec: number, language: SupportedLanguage) {
  speak(String(remainingSec), language);
}
export function speakStart(language: SupportedLanguage, startWord: string) {
  speak(startWord, language);
}
export function speakSecond(second: number, language: SupportedLanguage) {
  speak(String(second), language);
}
```
숫자 읽기는 `Speech.speak('5', { language })`처럼 언어 코드만 바꾸면 해당 언어 발음으로 읽으므로 숫자 자체는 번역이 필요 없다. "시작"만 언어별 낱말이 필요해 `t.timer.speechStart` 문자열을 `TimerScreen`에서 넘겨준다. `TimerScreen`은 `useLanguage()`로 언어 코드를, `useTranslation()`으로 `speechStart` 문구를 가져와 각 `speak*` 호출에 실어준다 (요구사항 9).

### 프리셋 이름·나머지 문구

나머지는 전형적인 치환 작업: 각 화면에서 `const t = useTranslation();`을 선언하고, JSX의 리터럴 한국어 문자열과 `Alert.alert(...)` 인자를 `t.<namespace>.<key>`로 바꾼다. 사용자 입력값을 문구에 끼워 넣어야 하는 경우(삭제 확인 문구에 운동 이름 등)는 번역 값 자체를 함수(`(name: string) => string`)로 정의해 호출부에서 `t.editExercise.deleteBody(exercise.name)`처럼 쓴다.

## 의존성

- **`expo-localization` 신규 추가** (`npx expo install expo-localization`) — 기기 언어 목록을 읽는 유일한 목적. Expo SDK 57과 호환되는 버전이 자동으로 맞춰 설치된다.
- 그 외 신규 패키지 없음. `i18next`/`react-intl` 등 범용 i18n 라이브러리는 쓰지 않는다 — 번역 대상이 앱 자체 문구뿐이고(복수형·통화 등 복잡한 포맷팅 불필요), TS 객체 리터럴 + Context만으로 타입 안전하게 충분히 구현 가능하기 때문 (의존성 최소화).

## 구현 순서

1. `expo-localization` 설치, `src/lib/i18n/types.ts`·`detectLanguage.ts` 작성 후 `console.log`로 기기 언어 감지가 되는지만 확인 (화면 변경 없음, 가장 먼저 동작 확인 가능한 단위)
2. `locales/en.ts`에 전체 스키마를 실제 쓰는 모든 화면 문구로 채우고(영어가 기준), `ko.ts`는 기존 하드코딩 한국어 문자열을 그대로 옮겨 채운다 (최소 2개 언어로 우선 골격 완성)
3. `LanguageContext.tsx`(`LanguageProvider`, `useTranslation`, `useLanguage`) 작성, `App.tsx`에 `ThemeProvider`와 함께 마운트
4. `HomeScreen`부터 시작해 화면 하나씩 하드코딩 문자열을 `t.*`로 교체, 매 화면마다 `npx tsc --noEmit`으로 즉시 확인 (순서: HomeScreen → AddExerciseScreen/EditExerciseModal → TimerScreen(+feedback.ts 언어 연동) → RepsScreen → RecordsScreen/RecordItem/RepsRecordItem → HelpModal/CameraPermissionModal/기타 컴포넌트)
5. `Exercise.presetKey` 필드·`getExerciseDisplayName`·`inferPresetKey` 추가, 프리셋 관련 화면 반영
6. `quotes.ts`→`locales/*.ts` 이전, `TimerScreen`이 `t.quotes` 사용하도록 교체 후 기존 `quotes.ts` 삭제
7. `helpContent.ts` 텍스트를 `locales/*.ts`의 `help.sections`로 이전(아이콘 배열은 별도 상수로 유지), `HelpModal` 반영 후 기존 텍스트 필드 제거
8. `ja.ts`, `zh.ts` 채우기 (같은 `Translations` 타입이라 TS가 누락 키를 컴파일 에러로 알려줌)
9. 기기 언어를 4개+미지원 언어(예: 프랑스어)로 각각 바꿔가며 실제 기기/시뮬레이터에서 전 화면 확인, `npx tsc --noEmit` 최종 통과 확인

## 스펙 요구사항 대응

| 스펙 요구사항 | 설계 대응 |
|---|---|
| 1. 기기 언어 감지해 4개 언어 중 적용 | `detectLanguage()` + `LanguageProvider` |
| 2. 미지원 언어는 영어 폴백 | `detectLanguage()`의 `?? DEFAULT_LANGUAGE` |
| 3. 수동 전환 UI 없음 | 새 화면·설정 항목을 추가하지 않음 (구조상 원천 배제) |
| 4. 전 화면 정적 문구 번역 | 화면별 `useTranslation()` 교체 (구현 순서 4) |
| 5. 프리셋 운동 이름 번역 | `exercisePresets.ts`의 `presetKey` + `t.exercisePresets` |
| 6. 사용자 직접 입력 이름은 번역 안 함 | `getExerciseDisplayName`이 `presetKey` 없으면 원문 그대로 반환 |
| 7. 날짜·요일 로케일 표기 | `t.weekdays` 배열로 `RecordsScreen`의 `WEEKDAYS` 교체 |
| 8. 단위 라벨 로케일 표기 | `t.units` (초/회/세트/kg/lb) |
| 9. 음성 안내 언어 전환 | `feedback.ts`의 `SPEECH_LOCALE` 매핑 + `speechStart` 문구 전달 |
| 10. 동기부여 문구 번역 | `quotes.ts` → `locales/*.ts`의 `quotes` 배열 이전 |
