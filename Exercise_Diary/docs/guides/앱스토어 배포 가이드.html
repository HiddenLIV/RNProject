01

실질적으로 남은 것 — 자료 준비는 거의 끝났다. 남은 진짜 작업은 (1) Play/Apple 계정 실제 가입 여부 확인, (2) Google Play 서비스 계정 JSON 발급, (3) 테스터 12명 모집, (4) eas build → eas submit 실행, (5) iOS 스크린샷 촬영이다.

02

남은 사전 준비

식별자·개인정보처리방침·아이콘·등록 카피·Android 스크린샷은 이미 끝났으므로(01 참고), 여기서는 아직 손대지 않은 것만 정리한다.

iOS 스크린샷

App Store Connect는 6.7인치 기기 화면 스크린샷을 최소 3장 요구한다. store-assets/에는 현재 android/ 폴더만 있고 iOS용은 없다. iOS 시뮬레이터(iPhone 15 Pro Max 등 6.7인치 기종)로 앱을 실행해 홈/측정/기록 화면을 캡처해 store-assets/ios/screenshots/ 정도의 위치에 정리해두면 된다.

참고 — 이미 끝난 항목

  • 식별자 — com.hiddenlab.hiddenreps로 iOS/Android 모두 확정, app.json에 반영됨. 스토어에 한 번 올리면 이후 변경 불가하므로 재확인만 하면 됨.
  • 개인정보처리방침 — docs/privacy-policy.html 작성 및 GitHub Pages(gh-pages 브랜치)로 호스팅 완료. 제출 시 URL만 그대로 붙여넣으면 됨.
  • Android 스크린샷 — 홈·횟수측정·타이머측정·기록 4장을 현재 UI(2026-08-10 기준)로 에뮬레이터에서 재촬영해 store-assets/android/screenshots/에 반영됨.
  • 등록 카피 — docs/guides/play-store-listing-copy.md에 앱 이름·짧은 설명·긴 설명·데이터 안전 양식 답변·콘텐츠 등급 답변까지 정리되어 있음.
03

계정 만들기

먼저 Expo 계정이 필요하다 (무료, 양쪽 빌드/제출에 공통으로 사용). 이미 로그인되어 있다면 건너뛴다.

터미널
npx eas login

계정이 없으면 expo.dev/signup에서 이메일로 무료 가입한다. Apple/Google 계정 가입 여부는 저장소 안에서 확인할 수 없으니, 아래 두 계정이 실제로 준비되어 있는지 먼저 확인한다.

iOS · App Store

Apple Developer Program

연 $99 · developer.apple.com/programs/enroll 에서 기존 Apple ID로 가입 (2단계 인증 필수).

  • 개인 — 본인 실명이 판매자로 노출, 서류 없이 바로 진행. 처음이라면 이쪽을 권장.
  • 조직 — 사업자명 노출 가능하지만 D-U-N-S 번호(발급 며칠~몇 주) 필요.
  • 결제 후 승인까지 보통 몇 시간~48시간.
Android · Google Play

Google Play Console

최초 1회 $25 · play.google.com/console/signup 에서 Google 계정으로 가입 후 결제.

  • 본인 확인(신분증 등) 절차가 있을 수 있음.
  • 신규 개인 계정 제약 — 프로덕션 트랙으로 바로 못 가고, 비공개 테스트에 테스터 12명 이상을 등록해 14일 연속 테스트를 완료해야 함.
  • 조직/사업자 인증 계정은 이 요건이 면제되기도 함.
04

EAS 설정 — 현재 상태

eas.json은 이미 생성되어 있다. build:configure를 다시 돌릴 필요는 없다. 현재 내용은 다음과 같다.

eas.json (현재)
{
  "cli": {
    "version": ">= 21.0.0",
    "appVersionSource": "remote"
  },
  "build": {
    "development": {
      "developmentClient": true,
      "distribution": "internal"
    },
    "preview": {
      "distribution": "internal"
    },
    "production": {
      "autoIncrement": true
    }
  },
  "submit": {
    "production": {}
  }
}

appVersionSource: "remote"와 production.autoIncrement: true가 이미 켜져 있어 iOS buildNumber, Android versionCode는 EAS가 자동으로 올려준다. 다만 submit.production이 비어 있어 Android 자동 제출(eas submit)에 필요한 트랙·서비스 계정 정보가 아직 없다 — 08단계에서 채워 넣는다.

05

app.json — 현재 상태

식별자, 아이콘, 권한 관련 설정은 이미 정리되어 있다. 배포 관련 핵심 값만 발췌하면 다음과 같다.

app.json (발췌)
"name": "HiddenReps",
"version": "1.0.0",
"ios": {
  "supportsTablet": false,
  "bundleIdentifier": "com.hiddenlab.hiddenreps",
  "infoPlist": { "ITSAppUsesNonExemptEncryption": false }
},
"android": {
  "package": "com.hiddenlab.hiddenreps",
  "adaptiveIcon": {
    "backgroundColor": "#0B0B0E",
    "foregroundImage": "./assets/android-icon-foreground.png",
    "backgroundImage": "./assets/android-icon-background.png"
  }
},
"extra": {
  "eas": { "projectId": "26cd7654-0215-4e26-b32c-0f9aa0d89109" }
}

version(1.0.0)은 사용자에게 보이는 마케팅 버전 번호다 — 업데이트할 때마다 올린다. 빌드 번호/버전 코드는 04단계의 autoIncrement 설정 덕분에 수동으로 관리할 필요가 없다. 카메라·사진·마이크 권한 문구(expo-image-picker, expo-media-library 플러그인 설정)도 이미 들어가 있다.

06

빌드하기 (EAS Build)

인증서/키스토어는 EAS가 자동으로 생성·관리한다. 첫 빌드 시 "Generate new keystore?" 같은 대화형 질문에는 그대로 Yes를 선택하면 된다.

터미널
# iOS 프로덕션 빌드
npx eas build --platform ios --profile production

# Android 프로덕션 빌드
npx eas build --platform android --profile production

# 둘 다 한번에
npx eas build --platform all --profile production
  • iOS 빌드 중 Apple 계정 로그인을 요구하며, Apple Developer Program 가입이 완료된 계정이어야 한다. App Store Connect에 앱이 아직 없으면 EAS가 자동으로 만들어주는 옵션도 제공한다.
  • 빌드는 Expo 클라우드 서버에서 진행되며, 완료되면 .ipa(iOS) / .aab(Android) 파일을 터미널과 expo.dev 대시보드에서 확인할 수 있다.
  • Free 플랜은 월 빌드 횟수 제한이 있지만, 첫 배포와 몇 번의 재제출에는 충분하다.
07

스토어 등록 정보 작성

Android 쪽은 docs/guides/play-store-listing-copy.md에 이름·짧은 설명·긴 설명·데이터 안전 답변·콘텐츠 등급 답변이 전부 정리되어 있어 Play Console에 그대로 옮기면 된다. iOS는 아직 별도 카피 문서가 없어 아래 항목을 참고해 작성한다.

iOS · App Store Connect

앱 등록

appstoreconnect.apple.com → 나의 앱 → + → 새 앱. 번들 ID는 com.hiddenlab.hiddenreps 선택, SKU는 임의의 고유 문자열.

  • 앱 이름 · 부제 · 설명 · 스크린샷(6.7인치 필수, 02단계에서 준비)
  • 개인정보처리방침 URL — https://hiddenliv.github.io/RNProject/
  • App Privacy — 서버 전송 데이터 없으므로 "수집 없음" 답변 가능. 단 YouTube 영상 재생 기능이 있으므로 타사 콘텐츠 데이터 수집 가능성을 명시
  • 연령 등급 설문, 수출 규정 준수(표준 암호화만 사용 → 예), 광고 식별자 사용 → 아니오
Android · Play Console

앱 등록

Play Console → 앱 만들기. play-store-listing-copy.md의 이름·설명을 그대로 붙여넣고, 아이콘(icon-512.png)·피처 그래픽(feature-graphic-1024x500.png)·스크린샷을 업로드.

  • 개인정보처리방침 URL — https://hiddenliv.github.io/RNProject/
  • 데이터 보안(Data Safety) 양식 — 카피 문서의 표(수집 없음/전송 없음)를 그대로 입력
  • 콘텐츠 등급(IARC) — 카피 문서 답변대로 진행 시 예상 등급 "전체 이용가"
  • 대상 연령층 특정 아동 대상 아님, 광고 없음, 인앱 구매 없음
  • 비공개 테스트 트랙을 먼저 설정 — 테스트 → 비공개 테스트 → 트랙 생성 → 테스터 이메일 12명 이상 추가 → 08단계의 .aab를 이 트랙에 먼저 업로드
08

마켓 제출하기 (EAS Submit)

iOS
터미널
npx eas submit \
  --platform ios \
  --profile production

Apple ID 로그인 후 App Store Connect에 자동 업로드된다. 업로드 후 App Store Connect에서 "심사를 위해 제출" 버튼을 직접 눌러야 실제 심사가 시작된다 — EAS submit은 업로드까지만 자동화한다.

Android

자동 제출을 위해 서비스 계정(Service Account) JSON 키가 필요하다. 현재 이 저장소에는 아직 발급되어 있지 않다 (.gitignore에 google-service-account*.json 패턴만 미리 등록된 상태).

  1. Play Console → 설정 → API 액세스 → 새 서비스 계정 만들기 (Google Cloud Console 연동)
  2. 발급된 JSON 키를 프로젝트 루트에 저장 (예: google-service-account.json) — 이미 .gitignore에 등록되어 있어 실수로 커밋될 위험은 없음
  3. eas.json의 submit.production을 아래처럼 채워 넣는다
eas.json — submit 설정 (채워 넣을 값)
"submit": {
  "production": {
    "android": {
      "serviceAccountKeyPath": "./google-service-account.json",
      "track": "internal"
    }
  }
}
터미널
npx eas submit --platform android --profile production

처음에는 track을 internal 또는 alpha(비공개 테스트)로 지정해 14일 테스트를 먼저 진행하고, 09단계의 요건(테스터 12명, 14일 연속)을 충족한 뒤 Play Console에서 프로덕션으로 승격한다.

09

심사 및 배포

  • iOS — 보통 24~48시간 내 결과. 반려 시 App Store Connect의 "Resolution Center"에 사유가 명시되며, 수정 후 재제출한다.
  • Android — 신규 계정 첫 앱은 폐쇄 테스트 14일(03단계 참고) + 심사 며칠. 이후 업데이트 심사는 보통 몇 시간~수일.

두 곳 다 첫 심사가 가장 오래 걸리고, 이후 업데이트는 훨씬 빠르다.

10

이후 업데이트 배포 방법

네이티브 재빌드가 필요한 변경

새 네이티브 모듈 추가, 권한 추가, Expo SDK 업그레이드 등 — app.json에서 버전을 올리고 eas build → eas submit을 그대로 반복한다.

JS/TS 코드·에셋만 바뀐 경우

EAS Update로 스토어 재심사 없이 즉시 배포할 수 있다.

터미널
npx eas update --branch production --message "설명"

앱을 이미 설치한 사용자는 다음 실행 시 자동으로 최신 JS 번들을 받는다. 단, 최초 배포에는 해당하지 않는다 — 스토어 제출이 반드시 먼저 필요하다.

11

지금 실제로 남은 체크리스트
