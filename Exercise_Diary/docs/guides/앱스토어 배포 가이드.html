02

남은 사전 준비

iOS 스크린샷

App Store Connect는 6.7인치 기기 화면 스크린샷을 최소 3장 요구한다. iOS 시뮬레이터(iPhone 15 Pro Max 등 6.7인치 기종)로 앱을 실행해 홈/측정/기록 화면을 캡처해 store-assets/ios/screenshots/ 정도의 위치에 정리해두면 된다. Android 스크린샷(store-assets/android/screenshots/)과 같은 화면 구성으로 맞추면 일관성이 좋다.

참고 — 이미 끝난 항목

  • 식별자 — com.hiddenlab.hiddenreps로 확정, app.json에 반영됨. 스토어에 한 번 올리면 이후 변경 불가하므로 재확인만 하면 됨.
  • 개인정보처리방침 — docs/privacy-policy.html 작성 및 GitHub Pages로 호스팅 완료. 제출 시 URL만 그대로 붙여넣으면 됨.
03

계정 만들기

먼저 Expo 계정이 필요하다 (무료, Android와 공통으로 사용). 이미 로그인되어 있다면 건너뛴다.

터미널
npx eas login
iOS · App Store

Apple Developer Program

연 $99 · developer.apple.com/programs/enroll 에서 기존 Apple ID로 가입 (2단계 인증 필수).

  • 개인 — 본인 실명이 판매자로 노출, 서류 없이 바로 진행. 처음이라면 이쪽을 권장.
  • 조직 — 사업자명 노출 가능하지만 D-U-N-S 번호(발급 며칠~몇 주) 필요.
  • 결제 후 승인까지 보통 몇 시간~48시간.
04

EAS 설정 — 현재 상태

eas.json은 이미 생성되어 있다. Android와 같은 파일을 공유하며 build:configure를 다시 돌릴 필요는 없다.

eas.json (현재)
{
  "cli": {
    "version": ">= 21.0.0",
    "appVersionSource": "remote"
  },
  "build": {
    "development": {
      "developmentClient": true,
      "distribution": "internal"
    },
    "preview": {
      "distribution": "internal"
    },
    "production": {
      "autoIncrement": true
    }
  },
  "submit": {
    "production": {}
  }
}

appVersionSource: "remote"와 production.autoIncrement: true가 이미 켜져 있어 iOS buildNumber는 EAS가 자동으로 올려준다. submit.production은 Android 서비스 계정 설정용으로 채워질 예정이며, iOS 제출은 08단계에서 대화형 로그인으로 진행되므로 별도 사전 설정이 필요 없다.

05

app.json — 현재 상태 (iOS 관련부)

iOS 배포와 관련된 핵심 값만 발췌하면 다음과 같다.

app.json (iOS 발췌)
"name": "HiddenReps",
"version": "1.0.0",
"ios": {
  "supportsTablet": false,
  "bundleIdentifier": "com.hiddenlab.hiddenreps",
  "infoPlist": { "ITSAppUsesNonExemptEncryption": false }
},
"extra": {
  "eas": { "projectId": "26cd7654-0215-4e26-b32c-0f9aa0d89109" }
}

version(1.0.0)은 사용자에게 보이는 마케팅 버전 번호다 — 업데이트할 때마다 올린다. buildNumber는 04단계의 autoIncrement 설정 덕분에 수동으로 관리할 필요가 없다. 카메라·사진·마이크 권한 문구(expo-image-picker, expo-media-library 플러그인 설정)도 이미 들어가 있다.

06

빌드하기 (EAS Build)

서명 인증서는 EAS가 자동으로 생성·관리한다.

터미널
npx eas build --platform ios --profile production
  • 빌드 중 Apple 계정 로그인을 요구하며, Apple Developer Program 가입이 완료된 계정이어야 한다. App Store Connect에 앱이 아직 없으면 EAS가 자동으로 만들어주는 옵션도 제공한다.
  • 빌드는 Expo 클라우드 서버에서 진행되며, 완료되면 .ipa 파일을 터미널과 expo.dev 대시보드에서 확인할 수 있다.
  • Free 플랜은 월 빌드 횟수 제한이 있지만, 첫 배포와 몇 번의 재제출에는 충분하다.
07

스토어 등록 정보 작성

iOS는 아직 별도 카피 문서가 없다. Android용 play-store-listing-copy.md의 톤을 참고해 아래 항목을 작성한다.

iOS · App Store Connect

앱 등록

appstoreconnect.apple.com → 나의 앱 → + → 새 앱. 번들 ID는 com.hiddenlab.hiddenreps 선택, SKU는 임의의 고유 문자열.

  • 앱 이름 · 부제 · 설명 · 스크린샷(6.7인치 필수, 02단계에서 준비)
  • 개인정보처리방침 URL — https://hiddenliv.github.io/RNProject/
  • App Privacy — 서버 전송 데이터 없으므로 "수집 없음" 답변 가능. 단 YouTube 영상 재생 기능이 있으므로 타사 콘텐츠 데이터 수집 가능성을 명시
  • 연령 등급 설문, 수출 규정 준수(표준 암호화만 사용 → 예), 광고 식별자 사용 → 아니오
08

마켓 제출하기 (EAS Submit)

iOS
터미널
npx eas submit \
  --platform ios \
  --profile production

Apple ID 로그인 후 App Store Connect에 자동 업로드된다. 업로드 후 App Store Connect에서 "심사를 위해 제출" 버튼을 직접 눌러야 실제 심사가 시작된다 — EAS submit은 업로드까지만 자동화한다.

09

심사 및 배포

보통 24~48시간 내 결과가 나온다. 반려 시 App Store Connect의 "Resolution Center"에 사유가 명시되며, 수정 후 재제출한다. 첫 심사가 가장 오래 걸리고, 이후 업데이트는 훨씬 빠르다.

10

이후 업데이트 배포 방법

네이티브 재빌드가 필요한 변경

새 네이티브 모듈 추가, 권한 추가, Expo SDK 업그레이드 등 — app.json에서 버전을 올리고 eas build → eas submit을 그대로 반복한다.

JS/TS 코드·에셋만 바뀐 경우

EAS Update로 스토어 재심사 없이 즉시 배포할 수 있다.

터미널
npx eas update --branch production --message "설명"

앱을 이미 설치한 사용자는 다음 실행 시 자동으로 최신 JS 번들을 받는다. 단, 최초 배포에는 해당하지 않는다 — 스토어 제출이 반드시 먼저 필요하다.

착수 시점에 처리할 체크리스트
