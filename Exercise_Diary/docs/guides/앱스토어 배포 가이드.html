나의 운동 일지 — 스토어 배포 가이드

계정이 하나도 없는 상태에서 App Store(iOS)와 Google Play(Android)에 처음 배포하기까지의 전 과정. Expo가 현재 공식 권장하는 EAS Build + EAS Submit 방식 기준.

가장 중요한 차이 — iOS는 계정 승인 후 바로 심사 제출이 가능하지만, Android(신규 개인 개발자 계정)는 최소 12명의 테스터를 모아 14일 연속 비공개 테스트를 거쳐야 프로덕션 트랙이 열립니다. 실제 일정은 Android 쪽이 더 오래 걸립니다.

01

사전 준비 — 계정 없이 지금 할 수 있는 것

1.1 앱 식별자(Bundle ID / Package name) 확정 — 가장 먼저 할 일

현재 app.json에는 다음과 같이 되어 있습니다.

app.json
"ios": { "bundleIdentifier": "com.anonymous.timecheck" }
"android": { "package": "com.anonymous.timecheck" }

com.anonymous.*는 Expo가 자동으로 붙여준 임시 값이고, timecheck는 이 프로젝트의 옛 이름(현재는 "나의 운동 일지")입니다. 이 값은 스토어에 한 번 올리고 나면 절대 바꿀 수 없습니다 — iOS bundle ID, Android package name 모두 최초 업로드 후 고정됩니다. 지금 반드시 정리하고 넘어가야 합니다.

  • iOS와 Android 값이 같을 필요는 없지만, 보통 통일해서 관리합니다.
  • 도메인이 없어도 됩니다. 예: com.hiddenlab.hiddenreps처럼 본인/팀을 식별할 수 있는 이름이면 충분합니다.
  • 정하고 나면 app.json의 ios.bundleIdentifier, android.package 둘 다 수정합니다.

1.2 앱 아이콘 / 스플래시 확인

  • iOS — 1024×1024, 알파 채널(투명 배경) 없는 PNG 필요. App Store Connect에 별도 업로드.
  • Android — adaptive icon은 이미 app.json에 설정됨 (scripts/make-icons.js로 생성). 스토어에는 512×512 아이콘 1장 + 1024×500 피처 그래픽 1장이 추가로 필요.

1.3 개인정보처리방침 — 필수, 지금 준비

이 앱은 카메라, 사진 라이브러리, 마이크 권한을 사용하므로 양쪽 스토어 모두 개인정보처리방침 URL 등록이 필수입니다. 서버로 데이터를 전송하지 않고 AsyncStorage로 로컬 저장만 하므로, 내용은 "수집하는 개인정보 없음, 촬영한 영상/사진은 기기 내부에만 저장됨"으로 간단히 작성할 수 있습니다.

호스팅은 GitHub Pages(무료, 이 저장소에 정적 페이지 하나 추가) 또는 Notion 공개 페이지 링크로도 충분합니다. 심사 시 이 URL을 App Store Connect / Play Console 양쪽에 입력해야 합니다.

1.4 스토어 등록 소재 미리 준비

앱 소개 문구(짧은 설명 + 긴 설명) — 다국어 지원 중이므로(en/ja/ko/zh) 한국어는 필수, 영어는 권장. 스크린샷은 iOS 6.7인치 기기 화면 최소 3장, Android 폰 스크린샷 최소 2장. 시뮬레이터/에뮬레이터로 캡처하면 됩니다.

02

계정 만들기

먼저 Expo 계정이 필요합니다 (무료, 양쪽 빌드/제출에 공통으로 사용).

터미널
npx eas login

계정이 없으면 expo.dev/signup에서 이메일로 무료 가입합니다. 그 다음 두 플랫폼 계정을 병렬로 준비합니다.

iOS · App Store

Apple Developer Program

연 $99 · developer.apple.com/programs/enroll 에서 기존 Apple ID로 가입 (2단계 인증 필수).

  • 개인 — 본인 실명이 판매자로 노출, 서류 없이 바로 진행. 처음이라면 이쪽을 권장.
  • 조직 — 사업자명 노출 가능하지만 D-U-N-S 번호(발급 며칠~몇 주) 필요.
  • 결제 후 승인까지 보통 몇 시간~48시간.
Android · Google Play

Google Play Console

최초 1회 $25 · play.google.com/console/signup 에서 Google 계정으로 가입 후 결제.

  • 본인 확인(신분증 등) 절차가 있을 수 있음.
  • 신규 개인 계정 제약 — 프로덕션 트랙으로 바로 못 가고, 비공개 테스트에 테스터 12명 이상을 등록해 14일 연속 테스트를 완료해야 합니다.
  • 조직/사업자 인증 계정은 이 요건이 면제되기도 함.
03

EAS 설정하기

이 저장소에는 아직 eas.json이 없습니다. 프로젝트 루트에서 실행합니다.

터미널
npx eas login
npx eas build:configure

build:configure를 실행하면 app.json에 extra.eas.projectId가 자동 추가되고(Expo 서버에 앱 등록), development / preview / production 세 가지 빌드 프로필을 담은 eas.json이 생성됩니다. 스토어 제출용은 production 프로필을 사용합니다.

버전을 수동으로 올리지 않도록 자동 증가를 켜두는 것을 권장합니다 (iOS buildNumber, Android versionCode를 EAS가 자동 관리).

eas.json
{
  "cli": {
    "appVersionSource": "remote"
  },
  "build": {
    "production": {
      "autoIncrement": true
    }
  }
}
04

app.json 마무리 정리

1.1에서 정한 값으로 식별자를 교체합니다.

app.json
"ios": {
  "supportsTablet": true,
  "bundleIdentifier": "com.hiddenlab.hiddenreps"
},
"android": {
  "package": "com.hiddenlab.hiddenreps",
  // ...
}

version은 사용자에게 보이는 마케팅 버전 번호입니다 — 업데이트할 때마다 올립니다. 권한 사용 문구(expo-image-picker, expo-media-library 플러그인 설정)는 이미 들어가 있어 별도 작업이 필요 없습니다.

05

빌드하기 (EAS Build)

인증서/키스토어는 EAS가 자동으로 생성·관리합니다. 첫 빌드 시 "Generate new keystore?" 같은 대화형 질문에는 그대로 Yes를 선택하면 됩니다.

터미널
# iOS 프로덕션 빌드
npx eas build --platform ios --profile production

# Android 프로덕션 빌드
npx eas build --platform android --profile production

# 둘 다 한번에
npx eas build --platform all --profile production
  • iOS 빌드 중 Apple 계정 로그인을 요구하며, Apple Developer Program 가입이 완료된 계정이어야 합니다. App Store Connect에 앱이 아직 없으면 EAS가 자동으로 만들어주는 옵션도 제공합니다.
  • 빌드는 Expo 클라우드 서버에서 진행되며, 완료되면 .ipa(iOS) / .aab(Android) 파일을 터미널과 expo.dev 대시보드에서 확인할 수 있습니다.
  • Free 플랜은 월 빌드 횟수 제한이 있지만, 첫 배포와 몇 번의 재제출에는 충분합니다.
06

스토어 등록 정보 작성

iOS · App Store Connect

앱 등록

appstoreconnect.apple.com → 나의 앱 → + → 새 앱. 번들 ID는 5단계에서 등록한 값을 선택, SKU는 임의의 고유 문자열.

  • 앱 이름 · 부제 · 설명 · 스크린샷(6.7인치 필수)
  • 개인정보처리방침 URL
  • App Privacy — 서버 전송 데이터 없으므로 "수집 없음" 답변 가능. 단 YouTube 영상 재생 기능이 있다면 타사 콘텐츠 데이터 수집 가능성을 명시
  • 연령 등급 설문, 수출 규정 준수(표준 암호화만 사용 → 예), 광고 식별자 사용 → 아니오
Android · Play Console

앱 등록

Play Console → 앱 만들기. 스토어 등록정보, 개인정보처리방침 URL, 콘텐츠 등급(IARC) 설문을 작성합니다.

  • 데이터 보안(Data Safety) 양식 — App Privacy와 동일한 취지, "수집 없음"으로 작성 가능
  • 대상 연령층, 광고 포함 여부 → 없음
  • 비공개 테스트 트랙을 먼저 설정 — 테스트 → 비공개 테스트 → 트랙 생성 → 테스터 이메일 12명 이상 추가 → 07단계의 .aab를 이 트랙에 먼저 업로드
07

제출하기 (EAS Submit)

iOS
터미널
npx eas submit \
  --platform ios \
  --profile production

Apple ID 로그인 후 App Store Connect에 자동 업로드됩니다. 업로드 후 App Store Connect에서 "심사를 위해 제출" 버튼을 직접 눌러야 실제 심사가 시작됩니다 — EAS submit은 업로드까지만 자동화합니다.

Android

자동 제출을 위해 서비스 계정(Service Account) JSON 키가 필요합니다.

  1. Play Console → 설정 → API 액세스 → 새 서비스 계정 만들기
  2. 발급된 JSON 키를 저장 (.gitignore에 추가, 절대 커밋 금지)
  3. eas.json에 경로 지정 후 아래 명령 실행
터미널
npx eas submit \
  --platform android \
  --profile production
eas.json — submit 설정
"submit": {
  "production": {
    "android": {
      "serviceAccountKeyPath": "./google-service-account.json",
      "track": "internal"
    }
  }
}

처음에는 track을 internal 또는 alpha(비공개 테스트)로 지정해 14일 테스트를 먼저 진행하고, 요건 충족 후 Play Console에서 프로덕션으로 승격합니다.

08

심사 및 배포

  • iOS — 보통 24~48시간 내 결과. 반려 시 App Store Connect의 "Resolution Center"에 사유가 명시되며, 수정 후 재제출합니다.
  • Android — 신규 계정 첫 앱은 폐쇄 테스트 14일(2단계 참고) + 심사 며칠. 이후 업데이트 심사는 보통 몇 시간~수일.

두 곳 다 첫 심사가 가장 오래 걸리고, 이후 업데이트는 훨씬 빠릅니다.

09

이후 업데이트 배포 방법

네이티브 재빌드가 필요한 변경

새 네이티브 모듈 추가, 권한 추가, Expo SDK 업그레이드 등 — app.json에서 버전을 올리고 eas build → eas submit을 그대로 반복합니다.

JS/TS 코드·에셋만 바뀐 경우

EAS Update로 스토어 재심사 없이 즉시 배포할 수 있습니다.

터미널
npx eas update --branch production --message "설명"

앱을 이미 설치한 사용자는 다음 실행 시 자동으로 최신 JS 번들을 받습니다. 단, 최초 배포에는 해당하지 않습니다 — 스토어 제출이 반드시 먼저 필요합니다.
