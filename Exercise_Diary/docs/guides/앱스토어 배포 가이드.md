# iOS / Android 스토어 배포 가이드

계정이 하나도 없는 상태에서 App Store(iOS)와 Google Play(Android)에 이 앱을 처음 배포하기까지의 전 과정을 정리한 문서. 2026년 기준 Expo가 공식 권장하는 **EAS Build + EAS Submit** 방식을 사용한다. (예전 `expo build` 방식은 완전히 폐지되어 더 이상 사용할 수 없다.)

이 프로젝트는 Expo SDK 57 / React Native 0.86 managed workflow이며, `ios/`, `android/` 네이티브 폴더는 `.gitignore` 처리되어 있어(직접 커밋 안 함) EAS Build가 빌드할 때마다 `app.json` 설정을 기준으로 새로 생성한다. 즉 **네이티브 폴더를 직접 만지지 않고 `app.json`만 수정하면 되는 구조**다.

---

## 0. 전체 흐름 한눈에 보기

| 단계 | 내용 | 예상 소요 | 비용 |
|---|---|---|---|
| 1 | 사전 준비 (식별자 확정, 개인정보처리방침, 스크린샷 소재) | 반나절~1일 | 무료 |
| 2 | 계정 생성 (Expo, Apple, Google) | Apple 승인까지 최대 48시간 | Apple $99/년, Google $25(최초 1회) |
| 3 | EAS 설정 및 `app.json` 정리 | 1시간 이내 | 무료 |
| 4 | EAS Build (iOS/Android 빌드) | 각 10~20분 (대기 포함) | 무료(Free 플랜 월 빌드 한도 내) |
| 5 | 스토어 등록 정보 작성 (설명, 스크린샷, 등급, 개인정보 항목) | 반나절 | 무료 |
| 6 | EAS Submit (스토어 제출) | 10분 | 무료 |
| 7 | 심사 대기 | iOS 24~48시간, Android는 최초 앱은 폐쇄 테스트 14일 필수 | - |

가장 중요한 차이: **iOS는 계정만 승인되면 바로 심사 제출이 가능**하지만, **Android(신규 개인 개발자 계정)는 최소 12명의 테스터를 모아 14일 연속 비공개 테스트를 거쳐야 프로덕션(정식 출시) 트랙이 열린다.** 이 요건 때문에 실제 일정은 Android 쪽이 더 오래 걸린다.

## 1. 사전 준비 — 계정 없이 지금 할 수 있는 것

### 1.1 앱 식별자(Bundle ID / Package name) 확정 — 가장 먼저 할 일

현재 `app.json`에 다음과 같이 되어 있다.

```json
"ios": { "bundleIdentifier": "com.anonymous.timecheck" },
"android": { "package": "com.anonymous.timecheck" }
```

`com.anonymous.*`는 Expo가 자동으로 붙여준 임시 값이고, `timecheck`는 이 프로젝트의 옛 이름(현재는 `Exercise_Diary`/"나의 운동 일지")이다. **이 값은 스토어에 한 번 올리고 나면 절대 바꿀 수 없다** (iOS bundle ID, Android package name 둘 다 최초 업로드 후 고정). 지금 반드시 정리하고 넘어가야 한다.

- iOS와 Android 값은 같을 필요는 없지만, 보통 통일해서 관리한다.
- 도메인이 없어도 된다. 예: `com.hiddenliv.exercisediary` 처럼 본인/팀을 식별할 수 있는 이름이면 충분하다.
- 정하고 나면 `app.json`의 `ios.bundleIdentifier`, `android.package` 둘 다 수정.

### 1.2 앱 아이콘 / 스플래시 확인

- iOS: 1024×1024, 알파 채널(투명 배경) 없는 PNG 필요 — App Store Connect에 별도 업로드.
- Android: adaptive icon(foreground/background/monochrome) 이미 `app.json`에 설정되어 있음 (`scripts/make-icons.js`로 생성). 스토어에는 별도로 512×512 아이콘 1장 + 1024×500 피처 그래픽(feature graphic) 1장이 더 필요.

### 1.3 개인정보처리방침(Privacy Policy) — 필수, 지금 준비

이 앱은 카메라, 사진 라이브러리, 마이크 권한을 사용하므로 **양쪽 스토어 모두 개인정보처리방침 URL 등록이 필수**다. 이 앱은 서버로 데이터를 전송하지 않고 AsyncStorage로 로컬 저장만 하므로, 정책 내용 자체는 간단하게 "수집하는 개인정보 없음, 촬영한 영상/사진은 기기 내부에만 저장됨"으로 작성 가능하다.

- 호스팅 방법: GitHub Pages(무료, 이 저장소에 `docs/privacy-policy.html` 하나 만들어 Pages로 배포), 또는 Notion 공개 페이지 링크로도 충분함.
- 심사 시 이 URL을 App Store Connect / Play Console 양쪽에 입력해야 함.

### 1.4 스토어 등록에 필요한 소재 미리 준비

- 앱 소개 문구(짧은 설명 + 긴 설명), 다국어 지원 중이므로(en/ja/ko/zh) 스토어 등록 정보도 한국어는 필수, 영어는 권장.
- 스크린샷: iOS는 6.7인치 기기 화면(필수) 최소 3장, Android는 폰 스크린샷 최소 2장. 시뮬레이터/에뮬레이터로 캡처하면 됨.

## 2. 계정 만들기

### 2.1 Expo 계정 (무료)

```bash
npx eas login
```
계정이 없으면 https://expo.dev/signup 에서 이메일로 무료 가입. EAS Build/Submit을 쓰려면 필수.

### 2.2 Apple Developer Program — 연 $99

1. https://developer.apple.com/programs/enroll/ 에서 기존 Apple ID로 가입 (2단계 인증 필수).
2. **개인(Individual) vs 조직(Organization)** 선택
   - 개인: 본인 실명이 스토어의 "판매자" 이름으로 노출됨. 서류 없이 바로 진행 가능.
   - 조직: 사업자명으로 노출 가능하지만 D-U-N-S 번호(무료, 발급에 며칠~몇 주 소요)가 필요함. 처음이라면 **개인으로 먼저 시작하는 것을 권장**.
3. 결제 후 승인까지 보통 몇 시간~48시간 소요.
4. 승인되면 App Store Connect(https://appstoreconnect.apple.com) 접근 가능.

### 2.3 Google Play Console — 최초 1회 $25

1. https://play.google.com/console/signup 접속, Google 계정으로 가입, $25 결제.
2. 개인정보 인증(신분증 등) 절차가 있을 수 있음 — 2023년 이후 신규 계정은 본인 확인이 강화됨.
3. **중요 — 신규 개인 개발자 계정 제약**: 처음 앱을 배포하는 개인 계정은 프로덕션(정식 출시) 트랙으로 바로 못 가고, **비공개 테스트(Closed Testing) 트랙에 테스터 12명 이상을 등록해 14일 연속 테스트를 완료해야** 프로덕션 신청 자격이 열린다. (조직/사업자 인증 계정은 이 요건이 면제되는 경우가 있음.) 이 때문에 Android는 계정 승인 후에도 최소 2주는 걸린다고 생각하고 일정을 잡아야 한다.
   - 테스터 12명은 지인, 커뮤니티 등에서 이메일만 모으면 됨 (실제 다운로드 후 며칠 사용하도록 요청).

## 3. EAS 설정하기

이 저장소에는 아직 `eas.json`이 없다. 프로젝트 루트에서:

```bash
npx eas login
npx eas build:configure
```

`build:configure`를 실행하면:
- `app.json`에 `extra.eas.projectId`가 자동 추가됨 (Expo 서버에 이 앱을 등록).
- `eas.json` 파일이 생성되며 기본적으로 `development` / `preview` / `production` 3개 빌드 프로필이 만들어짐. 스토어 제출용은 `production` 프로필을 사용.

생성된 `eas.json`에 버전 자동 관리를 켜두는 것을 권장한다 (수동으로 iOS `buildNumber`, Android `versionCode`를 매번 올릴 필요 없이 EAS가 자동 증가):

```json
{
  "cli": {
    "appVersionSource": "remote"
  },
  "build": {
    "production": {
      "autoIncrement": true
    }
  }
}
```

## 4. `app.json` 마무리 정리

식별자 변경 예시 (1.1에서 정한 값으로 교체):

```json
"ios": {
  "supportsTablet": true,
  "bundleIdentifier": "com.hiddenliv.exercisediary"
},
"android": {
  "package": "com.hiddenliv.exercisediary",
  ...
}
```

추가로 `app.json`에 넣어두면 좋은 항목:
- `"version": "1.0.0"` — 마케팅 버전, 사용자에게 보이는 번호. 업데이트할 때마다 올림.
- iOS 전용 정보(`ios.infoPlist`)에 이미 권한 문구(`expo-image-picker`, `expo-media-library` 플러그인 설정)가 들어가 있어 별도 작업 불필요.

## 5. 빌드하기 (EAS Build)

인증서/키스토어는 EAS가 자동으로 생성·관리해준다 (처음 빌드 시 대화형으로 "Generate new keystore?" 등을 물어보면 그냥 Yes 선택하면 됨).

```bash
# iOS 프로덕션 빌드
npx eas build --platform ios --profile production

# Android 프로덕션 빌드
npx eas build --platform android --profile production

# 둘 다 한번에
npx eas build --platform all --profile production
```

- iOS 빌드 중 Apple 계정 로그인을 요구하며, Apple Developer Program 가입이 완료된 계정이어야 함. 이때 App Store Connect에 앱이 아직 없으면 EAS가 자동으로 만들어주는 옵션도 제공함(또는 6.1에서 먼저 만들어도 됨).
- 빌드는 Expo 클라우드 서버에서 진행되며, 완료되면 `.ipa`(iOS) / `.aab`(Android) 파일 링크를 터미널과 https://expo.dev 대시보드에서 확인 가능.
- Free 플랜은 월 빌드 횟수 제한이 있지만 처음 배포 + 몇 번의 재제출 정도는 충분함.

## 6. 스토어 등록 정보 작성

### 6.1 App Store Connect (iOS)

1. https://appstoreconnect.apple.com → "나의 앱" → "+" → 새 앱
   - 번들 ID: 5.에서 등록한 값 선택
   - SKU: 아무 고유 문자열(예: `exercisediary001`)
2. 입력해야 할 필수 항목
   - 앱 이름, 부제, 설명, 스크린샷(6.7인치 필수)
   - 개인정보처리방침 URL (1.3에서 준비한 것)
   - **앱 개인정보 보호(App Privacy)** 섹션 — 수집하는 데이터 항목을 체크. 이 앱은 서버 전송 데이터가 없으므로 "데이터 수집 없음"으로 답변 가능. 단, `react-native-youtube-iframe`/WebView로 유튜브 영상을 앱 내에서 재생하는 기능이 있다면 "타사 콘텐츠(YouTube)를 통한 데이터 수집 가능성"을 명시하는 게 안전함.
   - 연령 등급 설문
   - 수출 규정 준수(Export Compliance) — 표준 HTTPS만 쓰면 "예, 표준 암호화만 사용"으로 답변
   - 광고 식별자(IDFA) 사용 여부 — 광고 SDK 없으므로 "아니오"

### 6.2 Google Play Console (Android)

1. Play Console → "앱 만들기"
2. 필수 항목
   - 스토어 등록정보(제목, 설명, 스크린샷, 아이콘, 피처 그래픽)
   - 개인정보처리방침 URL
   - **데이터 보안(Data Safety) 양식** — iOS의 App Privacy와 동일한 취지. 수집 데이터 없음으로 작성 가능(위 YouTube 관련 유의사항 동일).
   - 콘텐츠 등급 설문(IARC)
   - 대상 연령층, 광고 포함 여부(없음)
3. **비공개 테스트 트랙 먼저 설정** (2.3에서 설명한 신규 계정 요건). Play Console → "테스트" → "비공개 테스트" → 트랙 생성 → 테스터 이메일 목록(12명 이상) 추가 → 7.에서 만든 `.aab`를 이 트랙에 먼저 업로드.

## 7. 제출하기 (EAS Submit)

### iOS

```bash
npx eas submit --platform ios --profile production
```
Apple ID 로그인 후 App Store Connect에 자동 업로드. 업로드 후 App Store Connect에서 "심사를 위해 제출" 버튼을 직접 눌러야 실제 심사가 시작됨(EAS submit은 업로드까지만 자동화).

### Android

Android는 자동 제출을 위해 **서비스 계정(Service Account) JSON 키**가 필요하다.

1. Play Console → 설정 → API 액세스 → 새 서비스 계정 만들기 (Google Cloud Console 연동)
2. 발급된 JSON 키 파일을 프로젝트에 저장(예: `google-service-account.json`, **반드시 `.gitignore`에 추가하고 절대 커밋하지 말 것**)
3. `eas.json`의 submit 설정에 경로 지정:
```json
"submit": {
  "production": {
    "android": {
      "serviceAccountKeyPath": "./google-service-account.json",
      "track": "internal"
    }
  }
}
```
4. 실행:
```bash
npx eas submit --platform android --profile production
```
- 처음에는 `track`을 `internal` 또는 `alpha`(비공개 테스트)로 지정해 14일 테스트를 먼저 진행하고, 요건 충족 후 Play Console에서 프로덕션으로 승격.

## 8. 심사 및 배포

- **iOS**: 보통 24~48시간 내 결과. 반려 시 App Store Connect의 "Resolution Center"에 사유가 명시되며, 수정 후 재제출.
- **Android**: 신규 계정 첫 앱은 폐쇄 테스트 14일(2.3 참고) + 심사 며칠 소요. 이후 업데이트 심사는 보통 몇 시간~수일.
- 두 곳 다 첫 심사가 가장 오래 걸리고, 이후 업데이트는 훨씬 빠르다.

---

## 9. 이후 업데이트 배포 방법

두 가지 경로가 있다.

1. **네이티브 재빌드가 필요한 변경** (새 네이티브 모듈 추가, 권한 추가, Expo SDK 업그레이드 등)
   → `app.json`에서 버전 올리고 → `eas build` → `eas submit` 그대로 반복.
2. **JS/TS 코드·에셋만 바뀐 경우** — EAS Update로 스토어 재심사 없이 즉시 배포 가능
   ```bash
   npx eas update --branch production --message "설명"
   ```
   앱을 이미 설치한 사용자는 다음 실행 시 자동으로 최신 JS 번들을 받는다. 단, 최초 배포에는 해당 없음(스토어 제출이 반드시 먼저 필요).
