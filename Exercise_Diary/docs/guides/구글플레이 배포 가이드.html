01

실질적으로 남은 것 — 자료 준비는 끝났다. 남은 진짜 작업은 (1) Play 계정 실제 가입 여부 확인, (2) 서비스 계정 JSON 발급, (3) 테스터 12명 모집, (4) eas build → eas submit으로 비공개 테스트 트랙에 첫 업로드하는 것, 이 네 가지뿐이다.

02

계정 만들기

먼저 Expo 계정이 필요하다 (무료, 빌드/제출에 공통으로 사용). 이미 로그인되어 있다면 건너뛴다.

터미널
npx eas login

계정이 없으면 expo.dev/signup에서 이메일로 무료 가입한다. Google Play 계정 가입 여부는 저장소 안에서 확인할 수 없으니, 아래가 실제로 준비되어 있는지 먼저 확인한다.

Android · Google Play

Google Play Console

최초 1회 $25 · play.google.com/console/signup 에서 Google 계정으로 가입 후 결제.

  • 본인 확인(신분증 등) 절차가 있을 수 있음.
  • 신규 개인 계정 제약 — 프로덕션 트랙으로 바로 못 가고, 비공개 테스트에 테스터 12명 이상을 등록해 14일 연속 테스트를 완료해야 함.
  • 조직/사업자 인증 계정은 이 요건이 면제되기도 함.
  • 가입이 끝나는 즉시 06(스토어 등록)·07(서비스 계정 JSON) 단계를 병행할 수 있다.
03

EAS 설정 — 현재 상태

eas.json은 이미 생성되어 있다. build:configure를 다시 돌릴 필요는 없다. 현재 내용은 다음과 같다 (iOS 프로필도 같은 파일에 있지만 이번 라운드에서는 손대지 않는다).

eas.json (현재)
{
  "cli": {
    "version": ">= 21.0.0",
    "appVersionSource": "remote"
  },
  "build": {
    "development": {
      "developmentClient": true,
      "distribution": "internal"
    },
    "preview": {
      "distribution": "internal"
    },
    "production": {
      "autoIncrement": true
    }
  },
  "submit": {
    "production": {}
  }
}

appVersionSource: "remote"와 production.autoIncrement: true가 이미 켜져 있어 Android versionCode는 EAS가 자동으로 올려준다. 다만 submit.production이 비어 있어 Android 자동 제출(eas submit)에 필요한 트랙·서비스 계정 정보가 아직 없다 — 07단계에서 채워 넣는다.

04

app.json — 현재 상태 (Android 관련부)

식별자, 아이콘, 권한 관련 설정은 이미 정리되어 있다. Android 배포와 관련된 핵심 값만 발췌하면 다음과 같다.

app.json (Android 발췌)
"name": "HiddenReps",
"version": "1.0.0",
"android": {
  "package": "com.hiddenlab.hiddenreps",
  "adaptiveIcon": {
    "backgroundColor": "#0B0B0E",
    "foregroundImage": "./assets/android-icon-foreground.png",
    "backgroundImage": "./assets/android-icon-background.png"
  }
},
"extra": {
  "eas": { "projectId": "26cd7654-0215-4e26-b32c-0f9aa0d89109" }
}

version(1.0.0)은 사용자에게 보이는 마케팅 버전 번호다 — 업데이트할 때마다 올린다. versionCode는 03단계의 autoIncrement 설정 덕분에 수동으로 관리할 필요가 없다. 카메라·사진·마이크 권한 문구(expo-image-picker, expo-media-library 플러그인 설정)와 android.permissions 목록도 이미 들어가 있다.

05

빌드하기 (EAS Build)

키스토어는 EAS가 자동으로 생성·관리한다. 첫 빌드 시 "Generate new keystore?" 같은 대화형 질문에는 그대로 Yes를 선택하면 된다.

터미널
npx eas build --platform android --profile production
  • 빌드는 Expo 클라우드 서버에서 진행되며, 완료되면 .aab 파일을 터미널과 expo.dev 대시보드에서 확인할 수 있다.
  • Free 플랜은 월 빌드 횟수 제한이 있지만, 첫 배포와 몇 번의 재제출에는 충분하다.
  • Google Play 계정이 아직 없어도 빌드 자체는 먼저 돌려볼 수 있다 — 계정 가입과 병행 가능.
06

스토어 등록 정보 작성

docs/guides/play-store-listing-copy.md에 이름·짧은 설명·긴 설명·데이터 안전 답변·콘텐츠 등급 답변이 전부 정리되어 있어 Play Console에 그대로 옮기면 된다.

Android · Play Console

앱 등록

Play Console → 앱 만들기. play-store-listing-copy.md의 이름·설명을 그대로 붙여넣고, 아이콘(icon-512.png)·피처 그래픽(feature-graphic-1024x500.png)·스크린샷을 업로드.

  • 개인정보처리방침 URL — https://hiddenliv.github.io/RNProject/
  • 데이터 보안(Data Safety) 양식 — 카피 문서 표대로 입력 (운동 기록은 수집 없음, 광고 ID만 AdMob을 통해 수집·Google과 공유로 신고)
  • 콘텐츠 등급(IARC) — 카피 문서 답변대로 진행 시 예상 등급 "전체 이용가"
  • 대상 연령층 특정 아동 대상 아님, 광고 포함(Google AdMob), 인앱 구매 없음 — 앱 콘텐츠 → 광고 메뉴에서 별도로 "예" 선언 필요
  • 휴대전화·태블릿(7인치/10인치) 스크린샷 모두 업로드 — store-assets/android/screenshots/와 하위 tablet-7in/, tablet-10in/에 준비됨. 태블릿 애셋을 빼먹으면 기본 스토어 등록정보 저장이 막힌다
  • 비공개 테스트 트랙을 먼저 설정 — 테스트 → 비공개 테스트 → 트랙 생성 → 테스터 이메일 12명 이상 추가 → 07단계의 .aab를 이 트랙에 먼저 업로드
07

마켓 제출하기 (EAS Submit)

Android

자동 제출을 위해 서비스 계정(Service Account) JSON 키가 필요하다. 현재 이 저장소에는 아직 발급되어 있지 않다 (.gitignore에 google-service-account*.json 패턴만 미리 등록된 상태).

Play Console 설정 → API 액세스 화면에서 바로 "새 서비스 계정 만들기" 버튼을 누르던 옛 방식은 Google이 없앴다. 지금은 서비스 계정 생성 자체를 Google Cloud Console에서 하고, Play Console에서는 그 계정을 "사용자 및 권한"에 초대해 권한만 부여하는 방식이다.

  1. Google Cloud Console에서 프로젝트 생성 (기존 프로젝트가 있으면 생략)
  2. Cloud Console → IAM 및 관리자 → 서비스 계정 → 서비스 계정 만들기 → 이름 지정 후 "만들고 계속하기"
  3. 생성된 서비스 계정의 이메일 주소를 복사해둔다 (다음 Play Console 단계에서 필요)
  4. 서비스 계정 상세 화면 → 키(Keys) → 키 추가 → 새 키 만들기 → JSON 선택 → 다운로드
  5. Cloud Console에서 Google Play Android Developer API를 검색해 사용 설정
  6. Play Console → 사용자 및 권한(Users and permissions) → 새 사용자 초대 → 3단계에서 복사한 서비스 계정 이메일 입력
  7. 앱 권한(App permissions)에서 이 앱을 선택하고 최소한 아래 권한을 부여 후 초대 전송
    • 앱 정보 보기(읽기 전용)
    • 초안 앱 수정 및 삭제
    • 프로덕션으로 출시, 기기 제외, Play 앱 서명 사용
    • 테스트 트랙에 앱 출시
    • 테스트 트랙 관리 및 테스터 목록 수정
  8. 다운로드한 JSON 키를 프로젝트 루트에 저장 (예: google-service-account.json) — 이미 .gitignore에 등록되어 있어 실수로 커밋될 위험은 없음
  9. eas.json의 submit.production을 아래처럼 채워 넣는다

권한 부여 후 Google API가 인식하기까지 최대 24시간 걸릴 수 있어, eas submit이 바로 안 되면 잠시 후 재시도한다.

eas.json — submit 설정 (채워 넣을 값)
"submit": {
  "production": {
    "android": {
      "serviceAccountKeyPath": "./google-service-account.json",
      "track": "internal"
    }
  }
}
터미널
npx eas submit --platform android --profile production

처음에는 track을 internal 또는 alpha(비공개 테스트)로 지정한다. 이 업로드가 완료된 순간부터 14일 카운트다운이 시작되므로, 06단계의 등록정보 입력과 테스터 이메일 확보를 이 업로드 전에 끝내두는 게 좋다. 08단계의 요건(테스터 12명, 14일 연속)을 충족한 뒤 Play Console에서 프로덕션으로 승격한다.

08

심사 및 배포

신규 계정 첫 앱은 폐쇄 테스트 14일(02단계 참고) + 심사 며칠이 걸린다. 이후 업데이트 심사는 보통 몇 시간~수일로 훨씬 빠르다.

09

이후 업데이트 배포 방법

네이티브 재빌드가 필요한 변경

새 네이티브 모듈 추가, 권한 추가, Expo SDK 업그레이드 등 — app.json에서 버전을 올리고 eas build → eas submit을 그대로 반복한다.

JS/TS 코드·에셋만 바뀐 경우

EAS Update로 스토어 재심사 없이 즉시 배포할 수 있다.

터미널
npx eas update --branch production --message "설명"

앱을 이미 설치한 사용자는 다음 실행 시 자동으로 최신 JS 번들을 받는다. 단, 최초 배포에는 해당하지 않는다 — 스토어 제출이 반드시 먼저 필요하다.

10

지금 실제로 남은 체크리스트

식별자·개인정보처리방침·아이콘·등록 카피 등 저장소 안에서 끝낼 수 있는 자료 준비는 이미 완료됐다(01단계 참고). 아래는 저장소 밖에서, 또는 실제 실행이 필요한 남은 작업만 추린 것이며, 14일 테스트를 최대한 빨리 시작하는 순서로 짰다.

0 / 5 완료
지금 바로 — 14일 타이머 조건 채우기
계정 생기는 대로 병행
계정·테스터·서비스 계정 준비되면

스토어 심사와는 별개로 확인할 것 — 현재 크래시 리포팅 도구가 없어 출시 후 오류가 나도 개발자가 알 방법이 없다. Sentry 같은 서드파티 SDK는 Data Safety의 "수집 없음" 답변과 상충할 수 있어 보류된 상태이므로, 최소한 도움말 화면에 문의 이메일을 넣는 절충안이라도 제출 전에 검토할 것을 권한다. 자세한 논의는 docs/roadmap.md의 P0 항목 참고.
