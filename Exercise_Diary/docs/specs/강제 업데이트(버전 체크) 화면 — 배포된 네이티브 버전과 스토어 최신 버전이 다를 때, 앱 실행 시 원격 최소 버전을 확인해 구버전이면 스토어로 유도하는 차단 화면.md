# 업데이트 안내 바텀시트(버전 체크)

> 2026-08-14 갱신: 최초 스펙은 "닫기 불가 전체 화면 차단"이었으나, 참고 레퍼런스(바텀시트 + "나중에" 스킵 버튼)를 반영해 **스킵 가능한 업데이트 안내**로 범위를 바꿨다. 매 콜드 스타트마다 다시 뜨는 지속적인 리마인드 방식이며, 더 이상 앱 사용을 물리적으로 막지는 않는다.

## 목적

네이티브 코드가 바뀐 업데이트를 배포하면 스토어 심사·롤아웃 지연 때문에 사용자마다 설치된 버전이 한동안 제각각이다. 오래된 네이티브 버전을 계속 쓰는 사용자는 새 기능이 깨지거나 예기치 않게 동작할 수 있으므로, 앱 시작 시 원격에 정의된 최소 필수 버전과 비교해 그보다 낮으면 업데이트를 권하는 바텀시트를 띄운다. 사용자는 그 자리에서 업데이트하거나 나중으로 미룰 수 있지만, 미뤄도 다음 실행 때 같은 안내를 다시 보게 되어 자연스럽게 업데이트를 유도한다.

## 사용자 시나리오

1. 사용자가 앱을 실행(콜드 스타트)하면, 화면이 뜨기 전(또는 뜬 직후) 원격의 최소 필수 버전 정보를 조회한다.
2. 현재 설치된 앱 버전이 해당 플랫폼(iOS/Android)의 최소 필수 버전 이상이면 평소처럼 앱을 사용한다 — 추가 UI 없음.
3. 현재 설치된 앱 버전이 최소 필수 버전보다 낮으면, 화면 하단에서 바텀시트가 올라온다. 뒷배경은 어두워지지만 기존 화면(홈 등)이 흐릿하게 비쳐 보인다.
4. 바텀시트에는 업데이트가 필요하다는 안내 문구와 "나중에"·"업데이트하기" 두 버튼이 나란히 있다.
5. "업데이트하기"를 누르면 해당 플랫폼 스토어의 앱 페이지(App Store/Google Play)로 이동한다.
6. "나중에"를 누르거나 기기 뒤로가기(Android 하드웨어 백 버튼 포함)를 누르면 바텀시트가 닫히고 평소처럼 앱을 계속 쓸 수 있다.
7. "나중에"로 닫아도 그 결정은 저장되지 않는다 — 다음에 앱을 다시 켜면(콜드 스타트) 여전히 구버전이면 같은 바텀시트가 다시 뜬다.
8. 원격 버전 정보 조회에 실패(네트워크 오류, 타임아웃, 형식 오류 등)하면 바텀시트를 띄우지 않고 평소처럼 앱을 사용하게 한다 — 오프라인 사용자가 불필요하게 방해받지 않게 한다.
9. 사용자가 스토어에서 업데이트를 완료하고 앱을 다시 실행하면(버전이 최소 필수 버전 이상이 되면) 바텀시트 없이 정상적으로 앱이 열린다.

## 요구사항

1. 최소 필수 버전 정보는 `docs/privacy-policy.html`과 같은 방식으로 gh-pages 브랜치에 올려둔 JSON 파일(`version.json`)에서 가져온다. 별도 백엔드나 유료 서비스는 쓰지 않는다.
2. `version.json`은 iOS와 Android의 최소 필수 버전을 각각 독립적으로 명시한다(한쪽 플랫폼만 최소 버전을 올려도 다른 플랫폼 사용자는 영향받지 않는다).
3. `version.json`에는 플랫폼별 스토어 페이지 URL(App Store/Google Play)도 포함되어, 바텀시트의 "업데이트하기" 버튼이 해당 URL로 이동할 수 있다.
4. 버전 체크는 앱 콜드 스타트 시 1회 수행한다. 이미 앱을 사용 중인 세션 도중(포그라운드 복귀 등)에는 다시 체크하지 않는다.
5. 현재 설치된 앱 버전은 실제 빌드에 반영된 버전 값을 기준으로 판단한다(`app.json`의 `expo.version` 등 실제 배포 버전과 일치하는 값).
6. 버전 비교는 `1.2.3`과 같은 점(.)으로 구분된 숫자 버전 형식을 major.minor.patch 순으로 비교한다(문자열 사전순 비교로 인한 오판 없이 `1.9.0` < `1.10.0`처럼 올바르게 비교되어야 한다).
7. 현재 버전이 최소 필수 버전보다 낮은 경우에만 바텀시트가 뜬다. 같거나 높으면 뜨지 않는다.
8. 바텀시트는 하단에서 올라오는 형태이며, 뒷배경(기존 화면)이 어둡게 비쳐 보인다. 아이콘은 우측 상단, 제목·본문은 좌측 정렬, "나중에"·"업데이트하기" 버튼이 하단에 나란히 배치된다.
9. "나중에" 버튼 또는 기기 뒤로가기를 누르면 바텀시트가 닫히고 기존 화면으로 정상 복귀한다 — 이후 앱 사용에 제약이 없다.
10. "업데이트하기" 버튼은 기기 플랫폼에 맞는 스토어 URL(iOS는 App Store, Android는 Google Play)을 연다. URL을 열지 못하는 경우에도 앱이 멈추거나 에러를 노출하지 않는다.
11. 원격 조회 실패(네트워크 오류, 타임아웃, JSON 파싱 실패, 필드 누락 등) 시에는 바텀시트를 띄우지 않고 앱을 정상 진행시킨다.
12. 원격 조회에 걸리는 시간 때문에 앱 시작이 과도하게 지연되지 않도록 조회에는 적절한 타임아웃을 둔다(타임아웃 시 11번 규칙에 따라 통과 처리).
13. 바텀시트는 라이트/다크 테마 양쪽에서 앱의 기존 테마와 자연스럽게 어울린다.
14. 바텀시트 문구는 한국어/영어/일본어/중국어 4개 언어를 모두 지원한다(`src/lib/i18n/locales/`).

## 제외 범위

- 사용자가 "나중에"를 선택한 이력을 저장해 일정 기간 다시 안 보여주는 기능(예: "하루 동안 보지 않기") — 이번 스펙은 매 콜드 스타트마다 다시 보여주는 단순한 방식만 다룬다.
- 심각도에 따라 스킵 가능/불가능을 나누는 2단계(소프트/하드) 정책 — 이번 스펙은 항상 스킵 가능한 단일 정책만 다룬다.
- EAS Update(OTA) 기반의 JS 번들 강제 갱신 — 이번 스펙은 스토어를 통한 네이티브 업데이트 유도만 다룬다.
- `version.json` 값을 자동으로 갱신하는 배포 파이프라인 자동화(예: EAS 빌드 완료 시 자동으로 minVersion 갱신) — 값 갱신은 당분간 수동으로 편집·배포한다.
- 원격 설정 서버 대시보드, A/B 테스트, 사용자 세그먼트별 업데이트 정책.
- 포그라운드 복귀 시 재검사, 주기적 폴링 등 콜드 스타트 이외의 체크 트리거.
